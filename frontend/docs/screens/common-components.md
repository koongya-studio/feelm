# 공통 컴포넌트 구조 및 사용 기준 (1차)

Epic [S15P21E106-266]의 공통 컴포넌트 정의입니다. 화면 요소는
[Screen Spec](./screen-spec.md), 폴더 구조와 배치 규칙은
[화면 구조 설계](./frontend-structure.md)를 따릅니다.

## 1. 목적과 범위

Screen Spec의 15개 화면에서 반복되는 요소를 컴포넌트로 정리하고, 무엇을 공통으로 두고
무엇을 화면 전용으로 둘지, 각 컴포넌트가 지켜야 할 상태와 접근성 기준을 정합니다.

이 문서는 **1차 정의**입니다. 컴포넌트의 최종 props 시그니처는 구현 업무에서 확정하고,
여기서는 역할 · 사용 화면 · 필요한 상태 · 지켜야 할 기준을 정합니다.

**하지 않는 것**: 와이어프레임의 배치 · 색상 · 폰트 · 간격 · 문구를 바꾸지 않습니다. 새
디자인 컨셉, 장식, 애니메이션, 화면, 기능을 추가하지 않습니다.

## 2. 적용한 참고 자료

프로젝트에 설치된 `impeccable` 디자인 스킬을 **스킬로 호출하지는 못했습니다.** 이 스킬은
로컬 `Feelm/` 작업 폴더에 묶인 디렉터리 범위 스킬이라 저장소 작업 컨텍스트에서 목록에
올라오지 않습니다.

대신 스킬의 지침 파일 3개를 직접 읽어 적용했습니다.

| 파일 | 적용한 부분 |
| --- | --- |
| `reference/craft-floor.md` | 컴포넌트 상태 목록(hover · disabled · loading · error · empty + 키보드 초점), 아이콘은 그려진 SVG로 통일, 브라우저 기본 표면 테마, 컨트롤 문구 규칙, 카드 남용 회피 |
| `reference/android.md` | 하단 내비 3~5개 목적지, 터치 타깃 48dp · 간격 8dp, 일시적 피드백은 스낵바 · 중단이 필요한 결정만 다이얼로그, 타입 역할 기반 스케일 |
| `reference/audit.md` | 품질 검증 5개 차원(접근성 · 성능 · 테마 · 반응형 · 구현 정합성)과 터치 타깃 44×44px 기준 |

`android.md`는 네이티브 Android 앱을 대상으로 한 지침이라 그대로 적용할 수 없습니다.
이번 산출물은 React 반응형 웹앱(ADR-0013)입니다. `design-concept.md`가
`Android 기반 · Material 3는 구조와 사용성 기준으로 활용`으로 정하고 있어, Material 3는
구조와 사용성 참고로만 쓰고 Material 컴포넌트 라이브러리를 도입하지 않습니다.

스킬의 지침과 와이어프레임이 충돌하면 **와이어프레임을 따릅니다.** `craft-floor.md`도
`the brief's own words can earn any of them`으로 브리프 우선을 정하고 있습니다. 예를
들어 카드 기반 구성은 스킬의 기본 회피 대상이지만, 와이어프레임 2.2의 추천 카드는
확정된 배치이므로 유지합니다.

## 3. 컴포넌트 승격 기준

### 3.1 어디에 두는가

| 기준 | 위치 |
| --- | --- |
| 한 화면에서만 쓰임 | 그 화면 폴더 안 |
| 두 개 이상 화면에서 쓰임 | `src/components/` |
| 레이아웃 구조 | `src/layouts/` |

**처음에는 화면 폴더 안에 만들고, 두 번째 화면이 필요해질 때 올립니다.** 미리 공통으로
만들지 않습니다. 사용처가 하나뿐인 컴포넌트를 공통에 두면 그 화면의 요구만 반영된 API가
공통 규격이 됩니다.

### 3.2 올릴 때 지킬 것

- 올린 뒤 기존 사용 화면에 의도하지 않은 변경이 생기지 않는지 확인합니다
- 공통 컴포넌트 수정은 그 업무에 필요한 범위에서만 합니다
- 두 화면의 요구가 다르면 하나의 컴포넌트에 분기를 늘리기보다 별개로 두는 것이 나은지
  먼저 판단합니다

### 3.3 계층

```text
layouts/      화면 껍데기와 내비게이션
components/
  ├─ 기본     도메인을 모르는 조작·입력·표시 단위
  ├─ 표시     값을 보여주는 단위
  └─ 도메인   Feelm의 개념(필름 · 팝콘 · OTT · 영화)을 아는 단위
```

도메인 계층은 기본 · 표시 계층을 사용할 수 있지만, 반대 방향으로 의존하지 않습니다.

구현하는지를 뜻합니다.

### 4.2 기본

| 컴포넌트 | 역할 | 사용 화면 | 만들 업무 |
| --- | --- | --- | --- |
| `Button` | 주 · 보조 · 텍스트 버튼 | 거의 모든 화면 | 08 |
| `IconButton` | 아이콘만 있는 버튼 | 2.1 알림, 2.2 카드 `⋯`, 1.1 카드 `⊖` | 08 |
| `Icon` | SVG 아이콘 렌더링 | 전역 | 07 |
| `VisuallyHidden` | 화면에 안 보이고 보조기술에만 읽히는 텍스트 | 전역 | 07 |
| `TextArea` | 한 줄 감상 입력 | 2.4 감상평, 2.5 한줄평 | 11 |
| `SelectableTile` | 선택 · 해제되는 타일 | 1.2 OTT 선택 | 10 |
| `Menu` | `⋯` 버튼에 붙는 팝오버 메뉴 | 2.3 | 09 |
| `Snackbar` | 일시적 피드백 | 2.3-A | 09 |

`Icon`과 `VisuallyHidden`은 공통 레이아웃 업무(S15P21E106-255)에서 필요해 먼저
만들었습니다.

`Menu`는 처음 `BottomSheet`로 적었으나 **와이어프레임 2.3은 바텀시트가 아닙니다.**
카드의 `⋯` 버튼에 붙는 작은 팝오버입니다.

```text
position:absolute; right:12px; top:150px; width:148px;
border-radius:14px; box-shadow:0 8px 24px rgba(0,0,0,0.1)
```

`TextArea`도 와이어프레임에서 여러 줄 입력이 아니라 높이 50px의 단행 입력 형태로
그려져 있습니다. 한줄평은 200자 이하이므로(API-036) 실제 입력 방식은 화면 구현에서
확인합니다.

`TextArea` · `SelectableTile` · `Menu` · `Snackbar`는 각각 화면 한 곳에서만 쓰이므로
3.1절 기준에 따라 **처음 쓰는 화면 업무에서 만들고 둘째 화면이 필요해질 때 공통으로
올립니다.** `만들 업무` 열은 그 시점입니다.

`Button` 변형은 와이어프레임에서 확인된 세 가지입니다.

| 변형 | 와이어프레임 예 |
| --- | --- |
| `primary` | 선택 완료 (2개) · 평가 완료 · 필름 늘리기 · 다시 시도 · 팝콘 섞기 보기 |
| `secondary` | 구독 중인 OTT가 없어요 · 영화 검색하기 · 아직 못 봤어요 |
| `text` | 차차 찾아갈래요 · 나중에 평가하기 · 취향 리포트 보기 |

`[?]` `펼쳐서 8가지 맛 개수 보기`(5.8)가 버튼인지 링크인지 와이어프레임에서 단정할 수 없습니다. 화면 구현 시 확인합니다.

### 4.3 표시

| 컴포넌트 | 역할 | 사용 화면 | 만들 업무 |
| --- | --- | --- | --- |
| `Poster` | 영화 포스터 이미지 + 대체 텍스트 + 자리표시자 | 1.1, 2.1, 2.2, 2.3, 2.4, 2.5, 3.1, 3.1-A | 08 |
| `Badge` | 상태 · 수치 표시 | 2.1 `아직 안 본 영화`, 2.2 `일치 92% · 안 봄`, `연결 72% · 새로운 맛` | 08 |
| `Chip` | 취향 키워드 · 태그 | 2.1 `계획형 안티히어로를 좋아해요`, 3.1 키워드 4개, 5.9 태그 | 08 |
| `RatingStars` | 별점 표시 (읽기 전용) | 2.4 평균 · 한줄평, 3.1, 3.1-A | 08 |
| `Section` | 라벨이 붙은 테두리 컨테이너 | 2.1 각 섹션, 3.1 | 08 |
| `RatingInput` | 별점 입력 | 2.5 | 11 |
| `StatusView` | 오류 · 빈 데이터 · 로딩 상태 화면 | 2.2-A + 업무 16 | 16 |

`Section`은 처음 `SectionHeader`로 적었으나 **와이어프레임의 반복 단위는 제목과 액션
링크로 이루어진 헤더가 아닙니다.** 2.1과 3.1이 같은 사양의 테두리 컨테이너를 쓰고,
그 안에 작은 라벨이 붙습니다.

```text
컨테이너: border 1px rgba(0,0,0,0.15) · radius 16px · padding 14px · gap 12px
라벨:     12.5px / 700 / rgba(60,58,54,0.5)
```

5장의 `Card`를 만들지 않는다는 방침과 충돌하지 않습니다. `Section`은 범용 카드가
아니라 와이어프레임이 이 사양으로 반복해서 쓰는 특정 섹션 컨테이너입니다. 카드 안에
카드를 넣지 않는 규칙은 그대로 유지합니다.

`RatingStars`는 0.5~5.0점과 반쪽 별을 표시합니다(FR-19, API-036, 2026-09-07 합의).
평균 별점 3.7처럼 0.5 배수가 아닌 값도 받으므로 별 렌더링만 0.5 간격으로 맞추고
숫자 표시·보조기술 읽기에는 입력 점수를 소수 첫째 자리까지 사용합니다.

`RatingInput`과 `StatusView`는 화면 한 곳에서만 쓰이거나 다른 업무와 겹치므로 미뤘습니다.
`StatusView`는 로딩 · 빈 데이터 · 오류 상태 업무(S15P21E106-264)에서 함께 정의합니다.

`Badge`와 `Chip`을 나누는 기준입니다.

| | `Badge` | `Chip` |
| --- | --- | --- |
| 내용 | 상태나 수치 | 취향 키워드나 태그 |
| 조작 | 없음 | 없음 (이번 범위) |
| 예 | `아직 안 본 영화`, `일치 92%` | `케이퍼`, `반전 선호` |

둘 다 이번 범위에서는 조작할 수 없습니다. 나중에 필터로 쓰이면 `Chip`에 선택 상태를
추가합니다.

`[?]` 두 컴포넌트를 하나로 합칠지는 실제 구현 시 스타일 차이를 보고 판단합니다. 지금
합치면 근거 없이 하나의 API에 두 용도를 넣는 것이 됩니다.

### 4.4 도메인

| 컴포넌트 | 역할 | 사용 화면 | 만들 업무 |
| --- | --- | --- | --- |
| `OttBadge` | OTT 식별 배지 (N · T · W · D · C · A) | 1.2, 2.1, 2.2, 2.3, 2.4, 3.1-A | 08 |
| `MovieCard` | 영화 한 편을 카드로 표시 | 2.1, 2.2, 2.3, 2.4 유사 영화, 3.1 | 09 |
| `FilmReel` | 프레임을 필름 릴 모양으로 표시(가로 · 세로) | 1.3, 2.2, 2.6, 2.7, 3.1, 3.1-A | 10 |
| `PopcornBucket` | 팝콘 알 분포 SVG | 3.2, 5.8, 5.9 | 13 |
| `FlavorLegend` | 팝콘 맛 8종 범례 | 3.2, 5.8 | 13 |

`MovieCard` · `FilmReel` · `PopcornBucket` · `FlavorLegend`는 **처음 쓰는 화면 폴더에서
만들고, 두 번째 화면이 필요해질 때 `src/components/`로 올립니다**(3.1절 기준). 표에
적은 `만들 업무`는 처음 만드는 시점입니다.

`MovieCard`는 와이어프레임에서 배치가 크게 다릅니다.

| 형태 | 구성 | 화면 |
| --- | --- | --- |
| 대표형 | 큰 포스터 + 제목 + 메타 + 배지 + 추천 이유 + OTT | 2.1 오늘의 추천 |
| 목록형 | 포스터 + 제목 + 배지 + 추천 이유 + `⋯` | 2.2, 2.3 |
| 가로형 | 작은 포스터 + 제목 | 2.1 내 OTT 목록, 2.4 유사 영화 |
| 기록형 | 포스터 + 제목 + 상대 시각 + 별점 | 3.1 최근 추가된 영화 |

**하나의 컴포넌트에 네 형태를 분기로 넣지 않습니다.** 포스터와 제목 조합만 공통으로
두고(`Poster` + 제목), 나머지는 각 화면의 하위 컴포넌트로 둡니다. 두 화면이 정말 같은
배치를 쓰게 되면 그때 올립니다.

`PopcornBucket`은 ADR-0013이 `팝콘 버킷은 React에서 SVG로 렌더링한다`로 정하고 있어
SVG로 만듭니다.

## 5. 만들지 않는 컴포넌트

| 컴포넌트 | 만들지 않는 이유 |
| --- | --- |
| `Tabs` | Screen Spec 8.1에서 3.2의 `테마 · 장르 · 별점` 탭과 2.4 유사 영화 탭을 계약 기준으로 제외했습니다. 이번 범위에 탭이 필요한 화면이 없습니다 |
| `Dialog` | 이번 범위에 중단이 필요한 결정 화면이 없습니다. 2.3은 시트, 2.3-A는 스낵바입니다 |
| `Card` | 범용 카드 컨테이너를 만들지 않습니다. 화면마다 카드 구성이 달라 공통 규격이 성립하지 않고, 범용 카드는 배치를 카드로 밀어 넣는 원인이 됩니다 |
| `Modal` | 위와 같습니다. 2.3은 바텀시트입니다 |
| `Toast` | `Snackbar` 하나로 둡니다. Material 3 기준으로 일시적 피드백은 스낵바이고, 2.3-A는 `실행 취소` 동작이 붙는 형태입니다 |
| `Stepper` | 온보딩 1.1~1.3에 단계 표시 요소가 와이어프레임에 없습니다 |
| `Avatar` | 5.8 멤버와 2.4 한줄평 작성자에 이미지 요소가 와이어프레임에 없습니다. 닉네임 텍스트로 충분합니다 |
| `Skeleton` | 로딩 표현 방식이 미확정입니다(`design-concept.md` 6장). 업무 16에서 `StatusView`와 함께 결정합니다 |

필요해지면 근거와 함께 추가를 제안하고, 승인 없이 만들지 않습니다.

## 6. 공통 규칙

### 6.1 아이콘

- **그려진 SVG만 사용합니다.** 이모지나 유니코드 문자를 아이콘 대신 쓰지 않습니다
- REF-01이 `아이콘은 단순한 아웃라인 스타일로 통일`로 정하고 있습니다. 선 두께와 굵기를
  하나로 맞춥니다
- `currentColor`로 색을 상속받아 부모의 상태(선택 · 비활성)를 따릅니다
- 의미를 전달하는 아이콘에는 접근 가능한 이름을 주고, 장식 아이콘은 보조기술에서
  숨깁니다

`[?]` 아이콘 세트를 직접 그릴지 라이브러리를 쓸지는 미확정입니다. 라이브러리는 새
의존성이므로 임의로 도입하지 않고 먼저 공유합니다. 와이어프레임의 아이콘은 하단 내비
5개, 알림, 뒤로 가기, `⋯`, `⊖`, 별 정도로 적습니다.

### 6.2 색상과 토큰

- **색상 값을 컴포넌트에 직접 쓰지 않습니다.** `src/styles/tokens.css`의 CSS 변수만
  사용합니다
- 팝콘 맛 색상은 API-044의 `color`를 런타임에 받아 씁니다. 토큰에 넣지 않습니다
  (Screen Spec 8.1 #2)
- 확정된 토큰은 흰 배경, 검정 계열 텍스트, 내비 선택 `#3C3A36` · 비선택 `#A5A29B`,
  내비 높이 66px입니다
- 나머지는 미확정입니다. 와이어프레임의 무채색 값을 토큰으로 옮기되, 확정 사양이 아니라
  와이어프레임 관찰값임을 토큰 파일에 적습니다

### 6.3 터치 타깃과 간격

| 항목 | 기준 |
| --- | --- |
| 최소 크기 | 44×44px. Material 3의 48dp 권장을 상한 목표로 둡니다 |
| 최소 간격 | 8px |

와이어프레임의 시각 크기가 이보다 작은 요소(2.2 카드의 `⋯`, 1.1 카드의 `⊖`)는 **보이는
크기를 바꾸지 않고 터치 영역만 넓힙니다.** 배치를 바꾸지 않는 범위에서 적용합니다.

### 6.4 컴포넌트 상태

조작 가능한 컴포넌트는 아래 상태를 모두 정의합니다. 하나라도 빠지면 구현이 끝난 것이
아닙니다.

| 상태 | 대상 |
| --- | --- |
| 기본 | 전체 |
| 초점 (키보드) | 조작 가능한 전체. 기본 초점 표시를 제거하지 않습니다 |
| 누름 | 버튼 · 타일 · 카드 |
| 선택 | `SelectableTile`, `BottomNav` 탭, `RatingInput` |
| 비활성 | 조건이 안 맞는 주 버튼 |
| 진행 중 | 저장 · 재시도 동작이 있는 버튼 |
| 오류 | 입력 컴포넌트 |
| 빈 상태 | 목록을 표시하는 컴포넌트 |

`[?]` 마우스 hover 표현은 이번 범위에서 정하지 않습니다. 와이어프레임이 모바일 기준이고
`design-concept.md`가 모션을 미확정으로 두고 있습니다. 초점 표시는 hover와 별개로
반드시 있어야 합니다.

### 6.5 접근성

| 항목 | 기준 |
| --- | --- |
| 의미 있는 요소 | `div`에 클릭을 붙이지 않고 `button` · `a` · `input`을 씁니다 |
| 하단 내비 | `nav` 요소. 현재 탭에 `aria-current="page"` |
| 제목 계층 | 화면마다 `h1` 하나. 건너뛰지 않고 내려갑니다 |
| 포스터 이미지 | 영화 제목을 대체 텍스트로. 장식 이미지는 `alt=""` |
| 별점 표시 | 숫자 값을 텍스트로도 읽히게 합니다 (`VisuallyHidden` 또는 `aria-label`) |
| 별점 입력 | 키보드로 조작 가능. 현재 값이 이름으로 읽힙니다 |
| 바텀시트 | 열릴 때 초점 이동, `Esc`로 닫기, 배경 요소로 초점이 새지 않게 함 |
| 스낵바 | `role="status"`. `실행 취소`는 초점 이동 없이 도달 가능해야 합니다 |
| 진행 상태 | `role="status"` (2.6 필름 추가 중) |
| 색상만으로 구분 금지 | 팝콘 맛 범례는 색과 함께 이름 · 수치를 표시합니다. 와이어프레임과 일치합니다 |
| 글자 크기 확대 | 고정 px 높이로 텍스트를 담는 컨테이너를 만들지 않습니다 |

`[?]` 색상 대비 검증은 Accent color와 팝콘 맛 색상이 확정된 뒤 수행합니다. 목표는
본문 4.5:1, 큰 텍스트 3:1입니다.

### 6.6 문구

- **와이어프레임 문구를 그대로 씁니다.** 임의로 다듬지 않습니다
- 문구를 새로 써야 하는 곳(`NotInScopePage`, `NotFoundPage`, 미확정 상태 표시)은 최소로
  씁니다. 컨트롤은 자기 동작을 이름으로 말하고, 오류는 문제와 회복 방법을 말합니다
- Screen Spec 8.1에서 계약 기준으로 확정한 문구는 계약을 따릅니다
  (`취향 발견 추천`, `차차 찾아갈래요`, `시놉시스`)

### 6.7 브라우저 기본 표면

직접 그리지 않은 부분도 화면의 일부입니다. `src/styles/global.css`에서 토큰으로
정합니다.

| 항목 | 처리 |
| --- | --- |
| 초점 표시 | 토큰 색상으로 정의. 제거하지 않습니다 |
| 텍스트 선택 색 | 토큰으로 정의 |
| 숫자 정렬 | 수치를 나열하는 곳(팝콘 범례, 카운트)에 표 형태 숫자 적용 |
| 스크롤 동작 | 가로 스크롤 영역(필름 스트립, 가로 목록)의 스냅 여부를 정합니다 |

`[?]` 위 항목의 색상 값은 토큰 확정 후 정합니다. 이번 단계는 자리만 만듭니다.

## 7. 하지 않을 것

`craft-floor.md`의 회피 목록 중 이번 작업에 해당하는 항목입니다. **와이어프레임이 이미
정한 배치에는 적용하지 않습니다.** 제가 새로 만드는 요소와 스타일에만 적용합니다.

- 이모지 · 유니코드 문자를 아이콘으로 쓰지 않습니다
- 범용 카드 컨테이너를 만들어 배치를 카드로 밀어 넣지 않습니다. 카드 안에 카드를 넣지
  않습니다
- 제목 위에 작은 라벨(kicker · eyebrow)을 얹지 않습니다
- 그라디언트 텍스트를 쓰지 않습니다. 강조는 굵기나 크기로 합니다
- 장식 목적의 유리 효과 · 블러를 쓰지 않습니다
- 1px을 넘는 색상 좌측 테두리로 강조하지 않습니다
- 콘텐츠 자리를 스파크라인 · 진행 링 같은 장식으로 채우지 않습니다
- 중단이 필요 없는 작업에 모달을 쓰지 않습니다
- 섹션 번호(01 / 02 / 03)를 순서 정보가 필요하지 않은 곳에 붙이지 않습니다

와이어프레임 5.9의 `① 참여자 취향 비교` `② 팝콘 믹서` `③ 공통 취향 결과`와 2.4의 번호
영역은 와이어프레임이 정한 순서 표기입니다. 그대로 유지합니다.
