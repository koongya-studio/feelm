# 화면 초안 전수 검토 체크리스트

업무 S15P21E106-396. -301에서 만든 화면 초안 55개를 하나씩 보고 유지·수정·삭제를 정한다.
API 연동(-391~-395)과 PC 웹 레이아웃(-390)은 이 검토가 끝난 뒤 한다.

기준 시점은 develop `108c451`(2026-09-13)이다.

## 쓰는 법

1. 화면을 열어 보고 **판정**에 `유지` · `수정` · `삭제` 중 하나를 적는다.
2. **메모**에 이유나 고칠 내용을 적는다. `320px:`로 시작하는 줄은 작은 화면 캡처에서 이미 찾은 문제다(-389).
3. **계약에 없는 값**이 있으면 **결정**에 `화면에서 제거` 또는 `API 요청`을 적는다. API 요청이면 Jira 키를 붙인다.
4. 삭제로 정한 화면은 라우트 · 들어오는 버튼 · 목업 · 테스트까지 지운다.

### 칸 설명

| 칸 | 뜻 |
|---|---|
| API | 화면이 부르는 API 번호(`docs/api`). `없음`은 서버를 부르지 않는 화면 |
| 지금 | `실제` 백엔드 호출 · `목업` · `일부` 실제(대부분 API-014 내 프로필만 실제) |
| 백엔드 | develop 백엔드에 해당 API가 있는가. `O` 전부 · `일부` · `X` 없음 |
| 계약에 없는 값 | 화면이 보여주지만 계약에 없는 값(`types/unspecified.ts`), 그리고 화면 사양의 미정(`[?]`) · 계약 충돌(`[!]`) |

## 검토하면서 같이 정리할 것

조사 중에 나온 코드 쪽 정리 거리다. 화면 판정과 별개로 처리 여부만 표시한다.

- [ ] `types/unspecified.ts`의 `TasteFlowView`(취향 흐름 문장 · 키워드 근거)를 어느 화면도 쓰지 않는다. 3.1이 `getTasteFlow`를 더 이상 부르지 않는다.
- [ ] `types/unspecified.ts` 주석이 옛 화면 번호를 쓴다(`weeklyFrameDelta`를 2.6 · 2.7로 적음. 지금 번호로는 2.5 · 2.6).
- [ ] 7.2-A · 7.2-B 라우트 파라미터가 `:userId`인데 계약은 `publicId`다. (7.2-C는 업무 -506에서 화면을 지웠다)
- [ ] 백엔드에 있는데 프론트에 호출 함수가 없는 API가 있다. 비밀번호 재설정 · 변경(API-012), 소셜 가입 · 로그인, 파티 초대(API-051). 연동 업무 -391 · -393에서 다룬다.
