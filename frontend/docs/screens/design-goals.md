## 1. 확정된 것

> **⚠️ 1.3~1.7은 작업 원칙과 플랫폼 전제이지 시각적 결정이 아닙니다.** 이것들로부터 색·모티프·질감을 유도하지 마세요. 시각적 결정은 1.1 · 1.2와 1.9~1.16에만 있습니다.

### 1.1 White background — **확정 (시각)**

기본 화면 배경은 흰색입니다.

- 현재 mockup에서도 약 30개 화면이 `#FFFFFF`를 쓰고 있어 실질적으로 이미 다수 방향입니다.
- 배경 8종 중 몇 단계를 남길지는 **1.15에서 2단계로 확정**되었습니다.

### 1.2 Black / near-black typography — **확정 (시각)**

본문 잉크는 검정 또는 준검정입니다.

- 기준값은 **`#2E2C29`(13.9:1)** 로 확정했습니다. `#1C1B18`은 쓰지 않습니다.
- `rgba(60,58,54,0.55)`(3.11:1) · `rgba(60,58,54,0.45)`(2.41:1)는 **제거**했습니다. 잉크는 4단계로 줄이고 전부 4.5:1 이상으로 올렸습니다 → 5장.
- `DESIGN.md`가 적어 둔 대비값(`#3C3A36` 10.1:1 · `#2E2C29` 12.3:1)은 WCAG 2.x 공식으로 다시 계산하면 각각 11.4:1 · 13.9:1입니다. **`src/styles/tokens.css`의 값이 맞습니다.**

### 1.3 Minimal — 작업 원칙 (시각적 결정 아님)

요소를 더하지 않고 덜어내는 쪽을 기본값으로 둡니다.

- 깊이를 1px hairline과 배경 톤으로 표현하는 방식은 **1.15에서 채택**되었습니다.

### 1.4 Clean — 작업 원칙 (시각적 결정 아님)

시각적 소음을 만들지 않습니다. 값이 갈라지지 않고 규칙이 예측 가능해야 합니다.

- 현재 font-size 26종 / radius 19종 / 배경 8종은 이 방향과 정면으로 충돌합니다. 정리 대상입니다. **배경 8종과 잉크 8종은 이번에 정리했고, font-size 26종과 radius 19종은 남아 있습니다** → 2.4.

### 1.5 Intuitive — 작업 원칙 (시각적 결정 아님)

사용자가 학습하지 않아도 다음 동작을 알 수 있어야 합니다.

- 현재 유일한 가속 동작인 롱프레스(⑥-1)가 13px 푸터 문구로만 안내되는 구조는 이 방향과 충돌합니다.
- 반면 현재 한국어 카피는 "버튼 이름"이 아니라 "동작 원리"를 설명하고 있어 이 방향에 크게 기여하고 있습니다. **카피 보이스는 보존 대상**입니다.

### 1.6 Mobile-first — 플랫폼 전제

412×892 compact width 세로 화면이 기준입니다. 한 손 · 한 엄지 사용을 전제로 합니다.

- 태블릿 / expanded width 대응 여부는 이 문서의 범위 밖이며 아직 논의된 바 없습니다.

### 1.7 Android 기반 · Material 3는 구조와 사용성 기준으로 활용 — 플랫폼 전제

**Material 3를 "시각적 정답"이 아니라 "구조와 사용성의 기준"으로 사용합니다.**

이 구분이 이 문서에서 가장 중요한 문장입니다. 구체적으로:

| M3에서 **가져올 것** (구조·사용성) | M3에 **종속되지 않을 것** (표현) |
|---|---|
| navigation 모델 (bar / rail / drawer, 목적지 개수) | 컴포넌트의 시각적 스타일 |
| 시스템 Back · predictive Back 대응 | Material 기본 색상 팔레트 |
| window insets (status / nav / cutout / IME) | Dynamic Color 적용 여부 |
| 48×48dp 터치 타겟, 8dp 간격 | 컴포넌트 실루엣과 질감 |
| `sp` 단위와 시스템 글자 크기 대응 | Material 아이콘 세트 사용 여부 |
| type scale / shape scale의 **존재 자체** | 그 scale의 구체적 수치 |
| color role의 **구조** (surface / on-surface / outline …) | 그 role에 들어갈 실제 색 |
| snackbar / dialog / bottom sheet의 **사용 규칙** | 그것들의 시각 표현 |
| dark theme을 1급 스킴으로 다루는 원칙 | dark theme의 구체적 색 |
| Material motion **패턴 분류** (container transform, shared-axis, fade-through) | 지속시간·이징의 구체값 |

즉 **"어디에 무엇이 있어야 하는가"와 "얼마나 크고 얼마나 접근 가능해야 하는가"는 M3를 따르고, "그것이 어떻게 보이는가"는 FEELM이 정합니다.**

- 모션 지속시간·이징은 이 원칙대로 **FEELM이 직접 정했습니다** → 1.16.

### 1.8 FEELM의 브랜드 표현 방식 — **확정 (2026-09-08)**

이전 판에서 이 항목은 "아직 탐색 중"이었습니다. **더 이상 아닙니다.**

FEELM의 세계는 **「암실」**입니다. 흰 종이에 잉크로 적고, 깊은 버건디 하나를 좁게 쓰고, 필름을 장식이 아니라 컨테이너로 씁니다. 포스터가 들어가는 자리는 무채색 빈칸이 아니라 **인화된 컷**입니다.

세부 결정은 아래에 있습니다.

| 항목 | 결정 | 구 번호 |
|---|---|---|
| 1.9 Accent color | 하나 도입. 화면의 5% 이하 | 2.1 |
| 1.10 Oxblood | `#4A0D0D`을 시스템 accent로 승격. 바탕색으로 쓰지 않음 | 2.2 |
| 1.11 Film motif | 유지하고 **구조**로 쓴다 (스트립 = 컨테이너) | 2.3 |
| 1.12 Ticket · typewriter | 제거. accent만 계승 | 2.4 |
| 1.13 Decorative motifs | dashed · 스프로킷 · 알 세 가지만 | 2.5 |
| 1.14 Special-screen | 임계 순간만 (1.3 · 2.6 · 2.7) | 2.6 |
| 1.15 표면 단계 | 2단계 — 흰색 + `#F1EFEA` | 2.7 |
| 1.16 Motion | 상태 전환 + 임계 순간 확장 | 2.8 |
| 1.17 은유 | 필름 · 컷 · 알이 하나. 팝콘은 맛 이름 | (신설) |

### 1.9 Accent color — **확정 (시각, 2026-09-08)** *(구 2.1)*

**accent를 하나 둡니다. 화면 면적의 5% 이하로 씁니다.**

**적용 지점은 네 곳으로 한정합니다.**

| 적용 지점 | 토큰 | 근거 |
|---|---|---|
| primary 버튼 배경 | `--color-accent` | 화면당 하나뿐이라 면적 예산 안에 들어옴 |
| 하단 내비 활성 탭 | `--color-accent-mark` | 다섯 중 하나 |
| 별점 채움 | `--color-accent-mark` | 사용자가 남긴 판단. 잉크와 구별돼야 함 |
| 선택 상태 (타일 · 체크) | `--color-accent-mark` + 8% tint | 내가 고른 것 |

**쓰지 않는 곳:** 배지, 카드 배경, 섹션 헤더, 안내 문구, 링크. 배지를 accent로 두면 목록 화면에서 면적이 5%를 넘습니다.

**근거:** 일상 화면 ~30개에 accent가 없고 primary 버튼조차 잉크색이던 상태는 "무채색을 선택한 것"이 아니라 "선택이 이루어지지 않은 것"이었습니다(3장 규칙 3). 목표가 "실제 동작하는 앱처럼 보이는 것"이므로, 무채색으로 두면 타이포와 포스터를 정리해도 와이어프레임 같은 인상이 남습니다.

### 1.10 Oxblood / burgundy — **확정 (시각, 2026-09-08)** *(구 2.2)*

**`#4A0D0D`를 시스템 accent로 승격합니다. 바탕색으로는 쓰지 않습니다.**

두 단계를 둡니다.

| 토큰 | 값 | 대비 | 역할 |
|---|---|---|---|
| `--color-accent` | `#4A0D0D` | 15.5:1 | primary 버튼 배경처럼 큰 면적 |
| `--color-accent-mark` | `#7A1E1E` | 10.3:1 | 표식 · 별점 · 활성 탭. 흰 배경 위에서 붉은 기가 보이는 밝기 |
| `--color-accent-tint` | `rgba(74,13,13,0.08)` | — | 선택 상태 배경 |

**`#4A0D0D`를 화면 바탕에 깔지 않습니다.** 그러면 1.1(흰 배경)과 충돌합니다. 회원가입 3개 화면의 oxblood 바탕은 폐기합니다.

**두 단계로 나눈 이유:** `#4A0D0D`는 흰 배경 위 작은 표식으로 쓰면 검정과 구별되지 않습니다. 별 하나, 탭 라벨 하나 크기에서 "붉다"고 읽히려면 밝아야 합니다. 큰 면적에는 어두운 쪽을 씁니다.

**근거:** 팀이 이미 만든 색이라 새 색을 발명하는 것보다 근거가 있고, 구 2.2의 "시스템 accent로 승격" 선택지에 그대로 들어갑니다. Kaushan Script 손글씨 워드마크와도 무채색 미니멀보다 잘 붙습니다.

**비활성 primary는 예외입니다.** accent에 `opacity`를 걸면 흰 배경과 섞여 흐린 분홍이 되어 "비활성"이 아니라 "다른 색"으로 보입니다. 비활성 primary는 무채색 면(`--color-track`)으로 둡니다.

### 1.11 Film motif · Film-strip visual treatment — **확정 (시각, 2026-09-08)** *(구 2.3)*

**필름 은유를 유지합니다. 다만 장식이 아니라 구조로 씁니다. 스트립은 컨테이너입니다.**

- 스프로킷 수치는 스트립 폭에서 파생시킵니다. 화면마다 다른 값(폭 12 / 13 / 6px)을 두지 않습니다.
- `필름 안 4px / 밖 14px` 반경 규칙은 **관찰이 아니라 규칙으로 승격**합니다. 스트립 안은 컷이고 밖은 카드라는 구분이 이 방향의 핵심입니다.
- 스트립을 배경 요소로 강등하거나 폐기하는 방향은 채택하지 않았습니다 → 4장 C안.

### 1.12 Ticket / typewriter / wax-seal aesthetic — **확정 (시각, 2026-09-08)** *(구 2.4)*

**제거합니다. accent 색만 계승합니다.**

- 39개 중 4개 화면에만 존재하고 나머지 35개와 연결되지 않는 세계였습니다.
- ③은 화면 전체가, ②-2는 편지 전체가 래스터 이미지였습니다. 코드가 아니라 그림으로만 존재하므로 확장 비용이 다른 화면과 다릅니다. 화면 수가 늘어날수록 유지되지 않습니다.
- 이 구간에서 남길 것은 `#4A0D0D` 하나이고, 그것은 1.10에서 시스템 accent가 되었습니다.

### 1.13 Decorative motifs — **확정 (시각, 2026-09-08)** *(구 2.5)*

**세 가지만 허용합니다.**

| 모티프 | 뜻 | 쓰는 곳 |
|---|---|---|
| dashed 사각형 | 아직 채워지지 않은 컷 | 빈 프레임, 애셋 미정 영역 |
| 스프로킷 | 필름 | 스트립 컨테이너 |
| 알 | 영화 한 편 | 팝콘 통, 범례 |

**폐기:** 포스터 placeholder의 X자 사선(165회), ⑦의 현상기·인화 오브젝트, ⑨의 사진 실사 팝콘 렌더, ⑥-5의 dashed 화살표 주석.

- 포스터 X자는 **인화된 컷**으로 대체했습니다. 화면의 절반이 무채색이면 실제 앱처럼 보이지 않습니다. 영화마다 다른 깊은 톤 8종을 `movieId`로 골라, 같은 영화는 어느 화면에서나 같은 색으로 나옵니다.
- 실사 렌더는 1.12와 같은 이유로 폐기합니다. 코드로 그릴 수 없는 것은 화면이 늘어날 때 따라오지 않습니다.
- 인덱스 라벨의 `GENRE · 장르` letter-spacing 문법은 장식이 아니라 타이포 규칙으로 봅니다. 판단을 보류합니다 → 2.4.

### 1.14 Special-screen visual language — **확정 (시각, 2026-09-08)** *(구 2.6)*

**특별 화면을 인정합니다. 단, 임계 순간에만 인정합니다.**

자격을 갖는 화면은 셋입니다.

| 화면 | 임계 순간 |
|---|---|
| 1.3 첫 취향 필름 | 필름이 처음 감기는 순간 |
| 2.6 → 2.7 평가 결과 | 컷이 필름에 감기는 순간 |

"특별 취급"의 내용은 **모션과 시선 유도**이고, 다른 시각 언어(다른 색 세계, 래스터 이미지)를 쓰는 것이 아닙니다. 색·타이포·표면은 일상 화면과 같습니다.

**폐기:** ⑤ 초기 결과 추천의 전체 래스터, ⑨ · ⑨-1의 별도 배경색(`#F7F3F2` · `#F6EFE3`).

### 1.15 표면(surface) 단계 수 — **확정 (시각, 2026-09-08)** *(구 2.7)*

**2단계입니다.** 흰색 `#FFFFFF` + 한 단계 낮은 캔버스 `#F1EFEA`.

- `#F1EFEA`는 **화면 배경**으로만 씁니다. 섹션 카드에는 쓰지 않습니다. 섹션은 흰 면 위 1px hairline으로 구분합니다.
- 폐기: `#FBFAF8` `#F3EFE6` `#4A0D0D` `#F7F3F2` `#F6EFE3`.
- `#E9E7E1`은 표면이 아니라 **필름 스트립의 색**으로 남깁니다(`--color-surface-strip`). `#EFEDE9`도 표면이 아니라 트랙·비활성 면입니다(`--color-track`).
- 깊이는 그림자가 아니라 hairline과 표면 단계로 표현합니다. 그림자는 임계 순간의 결과 카드에만 씁니다.

### 1.16 Motion 언어 — **확정 (시각, 2026-09-08)** *(구 2.8)*

**상태 전환을 도입하고, 임계 순간에는 확장합니다.**

M3의 패턴 분류만 가져오고 수치는 FEELM이 정합니다(1.7).

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--motion-press` | 90ms | 눌림 피드백 |
| `--motion-fast` | 140ms | 탭·선택 상태 전환 |
| `--motion-base` | 220ms | 스낵바 등장 |
| `--motion-emphasized` | 420ms | 임계 순간 (2.6 → 2.7) |
| `--ease-standard` | `cubic-bezier(0.2, 0, 0, 1)` | 상태 전환 |
| `--ease-out` | `cubic-bezier(0.05, 0.7, 0.1, 1)` | 등장 |

**상태 전환은 눌렀는지 알 수 있을 만큼만 짧게, 임계 순간은 지켜볼 수 있게 길게.** 이 문장이 수치를 고른 기준입니다.

`prefers-reduced-motion: reduce`에서 네 값을 모두 `0ms`로 내립니다. 모션은 장식이므로 끄면 그만이어야 하고, 켜져 있어야 동작하는 화면은 두지 않습니다.

### 1.17 은유 — **확정 (2026-09-08)** *(신설)*

**필름 · 컷 · 알은 하나의 은유입니다. 팝콘은 별도 은유가 아니라 "맛 이름"입니다.**

- 영화 한 편을 보고 평가하면 **컷**이 생기고, 컷이 모여 **필름**이 됩니다.
- 같은 한 편을 취향 분포에서 셀 때 그 단위를 **알**이라고 부릅니다. 알과 컷은 같은 것을 다른 축에서 센 것입니다.
- **팝콘**은 그 알들이 담긴 통의 이름이고, 8가지 유형의 이름(`케이퍼` `스릴` …)입니다. 극장 간식이라는 별도 세계를 열지 않습니다. 그래서 사진 실사 팝콘 렌더를 폐기했습니다(1.13).

구 2.6이 미해결로 남겨 둔 쟁점(⑨의 100알과 ⑧-5의 팝콘이 같은 애셋을 공유한다는 사실)은 **하나의 은유라는 쪽으로 답했습니다.**

### B안을 고른 이유

1. **목표가 "실제 동작하는 앱처럼"이었습니다.** accent 없이 무채색으로 두면 포스터 그래픽과 타이포를 정리해도 여전히 와이어프레임 같은 인상이 남습니다.

3. **`#4A0D0D`는 이미 팀이 만든 색입니다.** 새 색을 발명하는 것보다 근거가 있고, 구 2.2의 선택지 안에 있습니다.

### A안을 고르지 않은 이유

A안은 **더 안전한 안이었습니다.** 흰 종이에 잉크, 색은 포스터에서만. 앱이 차분해지고 사진이 주인공이 됩니다. 결정을 되돌린다면 여기로 돌아오는 것이 가장 비용이 적습니다(accent 토큰 4개의 값만 잉크로 바꾸면 됩니다).

고르지 않은 이유는 하나입니다. **무채색이라 "앱처럼"보다 "도구처럼" 보일 위험**이 있고, 이번 회차의 목표가 정확히 그 인상을 없애는 것이었습니다.

### C안을 고르지 않은 이유

두 가지입니다.

1. **"배치는 그대로, 표면만"이라는 이번 회차의 범위와 충돌합니다.** 스트립 폐기는 표면 변경이 아니라 배치 변경입니다.
2. **와이어프레임 대조 검증 812항목 중 실측값 대조가 대부분 무효가 됩니다.** 스트립이 사라지면 필름 안/밖 구분, 스프로킷, 프레임 크기 실측값이 전부 근거를 잃습니다.

C안은 "가장 요즘 앱 같은" 안이었습니다. 필름 은유 자체를 다시 검토하기로 한다면 그때 이 안을 꺼내야 합니다.
