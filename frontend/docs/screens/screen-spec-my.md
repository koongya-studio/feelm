## 1. 이 업무의 기준 — 레퍼런스 우선

302~304의 20화면은 화면별 시각 시안 없이 와이어프레임 구조와 확정 토큰만으로 그렸다.
305부터는 **레퍼런스를 받고 시작한다**(2026-09-11 팀 결정).

이번 레퍼런스는 4장이며 전부 다크 테마다.

| 파일 | 대상 | 등급 |
| --- | --- | --- |
| `Dormy App.jpg` | 7.1 모듈형 대시보드 | 확정 |

**와이어프레임은 기능 · 필수 정보 · 상태 · 이동 경로만 가져온다.** 박스 배치와 섹션
순서는 옮기지 않는다. 레이아웃과 시각 위계는 레퍼런스로 새로 설계한다.

### 확정 토큰과 부딪힐 때 — 모드는 라이트를 지킨다

## 4. 시각 규칙 — 기존 토큰만 쓴다

`tokens.css`를 고치지 않는다. 레퍼런스의 구성을 확정 토큰 안에서 만든다.

**무거운 것은 어둡게 건다.** 레퍼런스가 색 카드로 만든 시선 집중을 어두운 면
(`--color-surface-dark`)으로 만든다. 화면마다 어두운 블록은 **하나**다. 둘 이상이면
밝은 벽이라는 전제가 무너진다.

| 화면 | 어두운 블록 |
| --- | --- |
| 7.1 | 취향 필름 카드 |
| 7.2 | 없음 (입력 화면이다) |
| 7.2-A · 7.2-B | 상단 대표 비주얼 |

**사진 위 오버레이는 예외다.** 대표 비주얼 위의 검정 그라데이션은 테마가 아니라
글자 대비를 만드는 장치이므로 어두운 블록 수에 포함하지 않는다.

**색은 팝콘 8색에서만 가져온다.** `mocks/popcornFlavors.ts`가 유일한 출처이고
화면은 색을 하드코딩하지 않는다. 팝콘 색은 밝은 면에서 4종이 1.01~1.39:1로 사라지므로
(토큰 주석) **색 면은 어두운 블록 안에서만 쓰고**, 밝은 면에서는 테두리를 두르거나
이름을 함께 쓴다.

**검정 알약은 화면당 하나.** 7.2 저장이 그 화면의 유일한 알약이다. **7.2-B에는 알약이

- **이미 차단한 사람(409 `ALREADY_BLOCKED`)은 실패로 다루지 않는다.** 바라던 상태이므로
  성공과 같이 7.8-D로 보낸다. 그 밖의 4xx는 계약이 준 문구를 그대로 보여준다

### 8.6 회원 탈퇴 연동 (업무 -480, 2026-09-17)

7.8-A-1을 API-013 실제 호출로 바꿨다. 8.5가 남긴 결정 — 비밀번호를 화면에서 받을지
계약에서 뺄지 — 을 **화면에서 받는 쪽으로 정했다**(사용자 결정 2026-09-17).

- **근거는 되돌릴 수 없다는 것이다.** Access Token만으로 계정을 지울 수 있게 두면 자리를
  비운 기기 하나로 복구할 수 없는 일이 벌어진다. 계약을 바꾸는 쪽은 백엔드 변경과
  담당자 합의가 따라오는데, 얻는 것이 입력 한 칸을 아끼는 것뿐이었다. 비밀번호
  변경(API-012)도 같은 이유로 현재 비밀번호를 받는다. 와이어프레임 수정 요청은
  **CR-24**로 남겼다
- **`탈퇴하기`는 체크와 비밀번호가 모두 채워져야 열린다.** 확인 창은 그 뒤에 한 번 더 뜬다
- **계약이 가르는 실패를 화면도 가른다.** `401 INVALID_CREDENTIALS`는 `비밀번호가
  올바르지 않아요`, `409 PASSWORD_NOT_SET`은 소셜 계정 안내, 나머지는 서버 문구다.
  실패하면 확인 창만 닫고 화면에 남아 다시 적을 수 있다
- **소셜 전용 계정은 입력 대신 안내를 보고 `탈퇴하기`가 열리지 않는다.** 본인 확인 수단이
  아직 없어 백엔드가 409로 거절한다(업무 -435). **7.8-A의 `회원 탈퇴` 줄은 감추지
  않는다** — 7.8-A-2 비밀번호 변경과 다른 판단이다. 비밀번호 변경은 없어도 되는 기능이지만
  탈퇴는 요구사항이 보장하는 경로(FR-37)라, 줄을 지우면 사용자가 방법도 이유도 알 수 없다
- **`hasPassword`를 못 읽으면 비밀번호를 받는 쪽으로 둔다.** API-014가 실패했을 때
  입력을 감추면 이메일 계정이 탈퇴할 방법을 잃는다. 반대로 두면 소셜 계정은 서버가
  409로 가려 준다 — 화면이 틀렸을 때 더 싼 쪽을 고른 것이다
- **성공하면 `signOut` 뒤 0.1로 보낸다.** 서버가 `refresh_token` 쿠키를 지우지만 메모리의
  Access Token은 화면이 버려야 한다(8.2 이동 경로 5)

`[?]` 계약의 `400 VALIDATION_FAILED`(값 없음)에는 화면이 닿지 않는다. `탈퇴하기`가
비밀번호 없이는 열리지 않기 때문이다. 서버 판정이 화면 판정보다 뒤에 있는 정상 상태다.

## 10. 7.1 재구성 — 사용자 시안 (2026-09-16, 업무 -459)

9장에서 계약에 없는 값을 걷어낸 뒤, **사용자 시안(인스타그램형 프로필 · 피드)으로 7.1의
구조를 다시 짰다.** 시안은 세 번에 걸쳐 왔고 이 장은 마지막 것을 적는다.

| 자리 | 무엇 | 출처 |
| --- | --- | --- |
| 헤더 오른쪽 | `설정` 아이콘 | 이동만 |
| 상단 | 3:4 프로필 사진 + 닉네임 | `[C]` API-014 `nickname` |
| 버튼 둘 | `프로필 편집`(→ 7.2) · `프로필 공유` | 공유는 기기 공유 메뉴 |
| 바로가기 | `4컷 리포트`(→ 7.3) · `취향 팝콘`(이동 없음) | 정적 그림 |
| 탭 | `평가한 영화` · `추천 기록` | 화면 안 전환 |
| 본문 | 고른 탭의 포스터 3열 피드 | `[C]` API-039 · API-048 |

### 10.1 피드는 각 탭의 실제 기록이다

- **평가한 영화** — API-039(`getMyRatings`, 업무 -611). 포스터 위에 별점을 얹는다(응답의
  `score`). 누르면 7.6과 같은 곳, **2.5 평가 수정**으로 간다. 프레임 없는 과거 평가
  (`frameId: null`)도 칸으로 나오므로 이 탭의 수는 3.1 필름의 프레임 수보다 많을 수 있다
- **추천 기록** — API-048(`getRecommendationHistory`). **실제 호출이다**(업무 -478).
  포스터 아래에 출처(`type`)와 날짜(세트의 `generatedAt`)만 적는다. 누르면
  **2.4 영화 상세**로 간다. 12장을 함께 본다
- **취향 필름(API-042)은 부르지 않는다.** 프레임을 평가 · 추천 기록인 것처럼 쓸 수 없다.
  필름은 하단 내비 `필름` 탭(3.1)이 보여준다. 7.1에서 `내 취향 필름` 제목과 프레임 격자를
  뺐다
- **상태 셋을 구분한다** — 읽는 중 · 조회 실패(다시 시도 버튼) · 빈 목록. 빈 목록을 가짜
  포스터로 채우지 않고, 실패를 빈 목록으로 뭉개지 않는다
- 두 목록을 처음에 함께 읽는다. 탭은 이동이 아니라 화면 안 전환이라 눌렀을 때 다시
  기다리면 안 된다(7.6이 두 탭에 쓰는 방식과 같다)

**세 탭 모두 `더 보기`로 다음 장을 받는다**(업무 -478 · -611 · -503, 2026-09-18). 한 장은
20건이고 다음 장은 첫 장과 **같은 조건**에 `nextCursor`만 실어 받는다 — 조건이 바뀐 커서는
세 API 모두 `400`이다. 실패해도 보던 격자는 남기고 버튼만 `다시 시도`로 바꾼다. 버튼은 탭마다
따로 선다 — 추천 기록에 다음 장이 있어도 다른 탭에 따라 나오지 않는다.

무한 스크롤로 하지 않았다. 피드가 끝나는 자리가 보여야 하는데, 탭이 셋이고 탭마다 끝이
달라서 스크롤만으로 이어 받으면 지금 탭이 끝났는지 알 수 없다. 4.2 검색은 탭이 없는 한
목록이라 무한 스크롤이다(업무 -612).

### 10.2 격자

포스터 비율 2:3, 칸 사이 3px, 화면 폭을 꽉 채운다(`page`의 좌우 여백을 음수 여백으로
상쇄한다). 카드로 감싸지 않는다. 격자 칸 폭이 화면에 따라 달라 실측 px을 쓸 수 없어
`Poster`에 `fluid`를 더했다 — **폭은 자리를 채우고 비율만 고정**한다.

### 10.3 프로필 이미지는 자리만 있다

닉네임 위에 **3:4 세로 자리**를 둔다(84 × 112px, 포스터와 같은 모서리). `Avatar`에
`shape`를 더해 7.1만 직사각형이고 7.8-D는 그대로 동그라미다. **API-014 · API-015에 `avatarUrl`이 없고 올리는 API도
없어 늘 기본 아이콘이다**(`Avatar`의 자리표시자). 누를 수 없게 두어 되는 기능처럼 보이지
않게 했다. 9.1에서 프로필 이미지를 지운 결정은 그대로다 — **자리만 두고 값은 여전히 없다.**
실제 사진을 쓰려면 API-015에 `avatarUrl`과 업로드 API가 필요하다.

### 10.4 통계 수치는 없다

`frameCount` · `popcornCount` · `ratingCount`를 API-014가 주지만 이 화면에 두지 않는다
(사용자 결정). 다른 자리에도 다시 넣지 않는다.

### 10.5 어두운 블록과 벽

**어두운 블록은 없다.** 4장 규칙의 원문은 `화면마다 어두운 블록은 하나다`이고 같은 장의
표는 7.2에 `없음`을 적는다 — 최대 하나이지 반드시 하나가 아니다. 화면에 남는 어두운 것은
포스터와 `4컷 리포트` 필름 조각뿐이고, 둘 다 면이 아니라 벽에 걸린 사물이다.

**벽은 앱 공통 벽 그대로다**(`--gradient-page`, 업무 -358에서 정한 값). 7.1만 흰 벽을
쓰게 만들었다가 되돌렸고, 공통 벽 자체를 팝콘 통 색으로 바꿨다가도 되돌렸다(2026-09-16).
`아이스 화이트`는 **이미 쓰던 공통 배경을 가리킨 말**이었는데 팝콘 통에서 색을 새로 뽑아
칠한 것이 잘못이었다. 벽을 바꾸는 화면은 3.3 리포트 발급(버건디) 하나뿐이다.
**화면은 배경을 따로 칠하지 않는다** — 프로필 · 그림 · 탭 · 포스터 사이 여백이 모두 같은
벽이어야 하므로 어떤 영역에도 면을 깔지 않는다. 필름 조각의 구멍도 색으로 칠하지 않고
마스크로 뚫어 벽이 그대로 비치게 했다.

### 10.6 프로필 공유

**계약이 아니라 브라우저가 한다**(사용자 지시 2026-09-16). 공유 API가 없으므로 서버를
부르지 않고, 7.2-B 공개 프로필 주소(`/users/{userId}`)를 기기의 공유 메뉴(Web Share API)에
넘긴다. 공유 메뉴가 없는 브라우저에서는 주소를 복사하고, 그것도 막히면 알린다.
3.5 리포트 공유가 쓰는 방법과 같다.

`[!]` 계약의 공개 프로필 키는 `publicId`인데 라우트는 `userId`다(9.4). 주소 규칙이
정해지면 공유하는 주소도 같이 바꾼다.

### 10.7 시안에 있지만 넣지 않은 것

한 줄 소개 · 해시태그다. 계약에 값이 없다(9.1).

### 10.8 설정은 아이콘이다

헤더 오른쪽 `설정` 글자를 아이콘으로 바꿨다(사용자 지시 2026-09-16). **와이어프레임에 없는
아이콘이라 `components/Icon`에 새로 그렸다**(`SettingsIcon`) — 다른 아이콘과 같은 선 두께 ·
둥근 끝이고, 20px에서 뭉개지지 않도록 톱니를 굵고 짧게 뒀다. 글자는 남기고 보이지만 않게
해(`VisuallyHidden`) 스크린 리더가 읽을 이름을 지킨다. 화면 제목 `MY`도 같은 방식이다.

## 11. 7.5 · 7.6 · 7.7을 지우고 MY 탭으로 옮겼다 (업무 -495, 2026-09-16)

10장에서 추천 기록과 평가를 7.1 안의 탭으로 들이면서 `7.1 → 7.5` · `7.1 → 7.6` 화살표가
없어졌다. 7.1이 그 둘의 유일한 입구였으므로 **화면 셋을 지우고 하던 일을 피드로 옮겼다**
(사용자 결정 2026-09-16).

| 지운 화면 | 하던 일 | 지금 자리 |
| --- | --- | --- |
| 7.5 추천 기록 | 추천받은 영화 목록 · 출처 · 날짜 | MY `추천 기록` 탭 |
| 7.6 평가한 영화 | 평가 목록 · 별점 | MY `평가한 영화` 탭 |
| 7.7 평가하지 않은 영화 | 본 기록은 있는데 평가가 없는 영화 | MY `안 남긴 영화` 탭 |

라우트(`/my/recommendations` · `/my/ratings` · `/my/ratings/unrated`)와 화면 파일 · 목업 ·
테스트를 함께 지웠다. 검토 체크리스트의 삭제 규칙대로다.

### 11.1 탭이 셋이 됐다

`평가한 영화` · `안 남긴 영화` · `추천 기록`이다. 안 남긴 영화는 API-034
(`WATCHED_UNRATED`)와 OTT 기준정보(API-025)를 함께 읽어 포스터 아래에 OTT와 날짜를 적는다 —
7.7이 쓰던 값 그대로다. 누르면 2.5 평가하기로 간다.

**고른 탭은 주소의 `?tab=`에 남는다.** 탭은 라우트가 아니지만 화면 밖에서 특정 탭으로

## 12. 추천 기록을 실제 API에 연동했다 (업무 -478, 2026-09-16)

11장에서 7.5가 사라진 자리, MY `추천 기록` 탭이 **API-048 추천 이력 조회**를 실제로
호출한다. 목업 이력 네 세트(`mocks/recommendationHistory.ts`)는 함께 지웠다.

- **`dismissed` · `watchStatus`는 서버가 지금 상태로 채운다**(API-048 처리 규칙). 목업
  시절에는 `api/recommendations`가 세션 저장소의 관심없음 · 평가를 덧칠했는데, 둘 다 실제
  DB에 없는 목업 영화(2.2 추천 카드)의 것이라 서버 이력과 맞춰 볼 곳이 없다. 두 값 모두
  화면에 그리지는 않는다
- **`더 보기`를 붙였다**(사용자 결정 2026-09-16). 한 장은 20세트이고 그보다 오래된 이력은
  `nextCursor`로 온다 — 버튼이 없으면 첫 장 뒤의 이력에 닿을 길이 없다. 4.2 검색이 쓰는
  처리와 같다: 다음 장이 실패해도 보던 격자는 두고 버튼만 `다시 시도`로 바꾼다
- `[!]` **이 탭은 당분간 비어 있다.** 이력은 API-045가 추천 세트를 만들 때 쌓이는데
  백엔드에 세트 생성이 없고(업무 -164 · -194 대기), 2.2 오늘의 추천은 목업이라 이력을
  남기지 않는다. 화면 확인은 `recommendation_sets`에 직접 넣어서 했다
  (`frontend/verification/S15P21E106-478.md`)
- `[!]` **`파티 추천` 출처는 실제로 오지 않는다.** 계약은 세트의 `user_id` · `party_id`로
  개인 · 파티를 나눈다고 적지만 API-048 구현은 개인 세트만 조회한다. 문구는 계약의 `type`을
  따라 남겨 두었고, 어느 쪽을 고칠지는 업무 -501에서 정한다
- 같은 파일의 **기본 추천(API-045)과 관심없음(API-047)은 목업으로 남는다.** 추천 목록은
  백엔드가 없고(업무 -164 · -194), 관심없음은 목업 추천 카드에서 열려 `movieId`가 실제 DB에
  없다

## 15. 목업 화면이 실제 변경 API를 부르지 않는다 (업무 -610, 2026-09-18)

### 15.1 7.2-B 차단은 잠겼다

공개 프로필(API-062)이 백엔드에 없어 7.2-B는 목업이다. 그 화면이 실제 차단(API-020)을 부르면
목업 번호라 서버에 없는 사람이어서 늘 `404`였다. ⋯ 메뉴의 `사용자 차단`은 **준비 중으로 잠갔고**
확인 창과 7.8-D 이동은 뺐다. API-062가 열려 실제 사람이 흐르면 되살린다(이동표 `7.2-B ⇢ 7.8-D`).
7.8-D의 목록과 해제(API-021 · 022)는 실제 API 그대로다. 목업 프로필이 실제 차단 목록을 섞어 보던
판정도 지웠다 — 그건 API-062의 `isBlockedByMe`가 할 일이다.

### 15.2 7.8-B 공개 범위 — 프로필 줄만 저장된다

계약이 정한 값은 프로필 `visibility`(API-015, `PUBLIC` · `PRIVATE`) 하나다. 그 줄만 서버에
저장하고 `파티원만`은 계약에 없는 단계라 고를 수 없다. 취향 필름 · 팝콘 버킷 · 한줄평의 공개
범위는 API가 없어 **준비 중으로 잠갔다.** 한때 세션 저장소에 두어 저장된 것처럼 보였는데
(2026-09-13) 새로고침하면 사라지는 값이라 설정처럼 보이면 안 된다.

### 15.3 7.8-C 알림 설정 — 두 토글은 준비 중이다

계약(API-017 · 018)은 `RATING` · `RECOMMENDATION` · `MARKETING` 셋이다. `파티 초대 알림` ·
`리포트 발급 알림`은 보낼 곳이 없어 잠그고 준비 중이라고 적는다. 자리는 와이어프레임대로 두어
계약이 열리면 값만 잇는다. 저장 중에는 같은 토글을 다시 눌러도 요청이 겹치지 않는다.

### 15.4 7.1 평가한 영화는 프레임(API-042)으로 그린다

> **API-039로 옮겼다**(업무 -611, 2026-09-18). 10.1을 본다. 아래는 그전의 결정이다.

내 평가 목록 API-039는 백엔드에 없다(S15P21E106-214 진행 중). 그전의 고정 목업은 방금 저장한
평가를 보여 주지 못했다. 프레임은 평가와 1:1이라(API-042 처리 규칙) 실제 저장 결과가 곧바로
보인다. 10장의 "프레임을 평가인 것처럼 쓰지 않는다"는 표현에 대한 결정이었고, 데이터 원천으로
프레임을 쓰는 것은 그 결정과 충돌하지 않는다. API-039가 열리면 그 함수로 옮긴다.
