# 와이어프레임 수정 지시서

`Feelm UI Wireframe Final.html`을 API 계약과 요구사항 정의서에 맞추기 위한 수정 요청
목록입니다. [Screen Spec](./screen-spec.md) 8장의 확정 결과에서 나왔습니다.

## 1. 배경과 원칙

Screen Spec 1차 작성 중 와이어프레임과 계약이 다른 항목 12건, 계약에 데이터 출처가 없는
화면 요소 9건을 발견했습니다.

**계약이 기준입니다.** 와이어프레임과 API 계약·요구사항 정의서가 다르면 계약을 따르고,
와이어프레임을 계약에 맞게 수정합니다. 문서 우선순위는 루트
[`AGENTS.md`](../../../AGENTS.md) 1장을 따릅니다.

## 2. 이 문서의 위치와 처리 방법

### 수정 대상 파일

| 항목 | 값 |
| --- | --- |
| 파일 | `Feelm UI Wireframe Final.html` |
| 위치 | 저장소 밖. 로컬 `Feelm/` 작업 폴더 |

### 수정 방법

**Claude Design 캔버스 편집기에서 수정합니다.** 이 파일은 캔버스 편집기가 생성한
산출물이며, 에셋과 디자인 DOM이 번들 페이로드로 들어 있습니다. 파일을 직접 편집하면
캔버스에서 다시 열었을 때 구조가 깨지거나 다음 저장 때 수정이 되돌아갈 수 있습니다.

Git으로 추적되지 않으므로 **수정 전 백업**을 권장합니다.

### 담당 업무

와이어프레임 수정은 UI/UX 업무이며 Epic `S15P21E106-266`(FE 초기 개발) 범위가 아닙니다.
`S15P21E106-75` 또는 `S15P21E106-107` [UI/UX] 와이어프레임 및 화면 흐름 설계 아래
별도 업무로 처리해 주세요.

## 3. 확정된 수정 요청 (CR-01 ~ CR-12, CR-19 ~ CR-25, CR-27, CR-29)

### CR-01 (취소) 평가 별점 단위

| 항목 | 값 |
| --- | --- |
| 대상 화면 | 2.5 영화 평가 |
| 유지 | `4.5 / 5.0 · 0.5점 단위` |
| 상태 | **취소.** 0.5~5.0점, 0.5점 단위로 표시합니다 |
| 근거 | MovieLens 32M 기준 2026-09-07 합의. FR-19, API-036 `score` (`number`, 0.5 배수) |

반쪽 별을 유지합니다. 정수만 표시하도록 변경하라는 이전 지시는 취소합니다.

**연쇄 확인 대상** — 개인 평가도 0.5점 단위 소수를 유지합니다.

| 화면 | 현재 표기 |
| --- | --- |
| 2.4 영화 상세 | `평균 ★ 3.7` — 평균값이므로 소수 유지가 맞습니다. 변경 불필요 |
| 3.1 취향 필름 메인 | `★ 4.5`, `★ 4.0`, `★ 5.0` — 개인 평가 원값 유지 |
| 3.1-A 프레임 상세 | `내 별점 4.0` — 개인 평가 원값 유지 |
| 4.1 검색 홈 (범위 밖) | `★ 4.3`, `★ 4.1`, `★ 4.4` — 평균값. 변경 불필요 |
| 2.4 다른 사용자 한줄평 | `★ 4.5`, `★ 4.0`, `★ 3.5` — 개인 평가 원값 유지 |

개인 평가는 0.5 배수이며 평균 별점에는 그 단위 제약을 적용하지 않습니다.

### CR-05 평가 화면에 한줄평 공개 범위 선택 추가

| 항목 | 값 |
| --- | --- |
| 대상 화면 | 2.5 영화 평가 |
| 현재 | 공개 범위 선택 수단이 **없음** |
| 변경 | 한줄평 입력 영역에 `PUBLIC`/`PRIVATE` 선택 컨트롤 추가 |
| 근거 | FR-19 인수 조건 `한줄평이 있으면 공개 범위 PUBLIC/PRIVATE를 선택한다`, API-036 (`comment` 있는데 `visibility` 없으면 `400 VALIDATION_FAILED`) |

**이 항목만 요소 추가입니다.** 나머지는 변경 또는 삭제입니다.

디자인 결정이 필요한 사항입니다.

- 컨트롤 형태 — 토글 · 체크박스 · 세그먼트 중 무엇을 쓸지
- 기본값 — 공통 규약의 Visibility 기본값은 `PRIVATE`입니다
- 문구 — `공개` / `비공개` 또는 다른 표현
- 노출 조건 — 한줄평을 입력했을 때만 나타낼지, 항상 보일지

관련 화면과 맞춰야 할 표현이 있습니다. 3.1-A 프레임 상세는 `내 한줄평 · 공개`로 공개
상태를 표시하고, 2.4 영화 상세는 다른 사용자의 공개 한줄평을 보여줍니다.

이 항목이 반영되기 전에는 프론트엔드에서 공개 범위 컨트롤을 구현하지 않습니다.

### CR-06 팝콘 맛 이름을 기준정보 기반으로

| 항목 | 값 |
| --- | --- |
| 대상 화면 | 2.7 필름 추가 완료 · 3.2 100알의 취향 · 5.8 파티원 팝콘 |
| 현재 | 장르명 8개 — 액션·모험 · 범죄·스릴러 · 드라마 · 로맨스 · 코미디 · SF·판타지 · 공포·미스터리 · 애니메이션·가족 |
| 변경 | 기준정보의 맛 표시명으로 대체 |
| 근거 | FR-06, ADR-0020, API-044 |

팝콘 맛은 **S15P21E106-439의 장르 기반 고정 상위 `taste_id` 8종**입니다
(ADR-0020). API-044 설명은 `클라이언트는 색상·표시명을 하드코딩하지 않고 이 API를
사용한다`고 정하고 있습니다.

**S15P21E106-466에서 해소됐습니다.** API-044에 `FLAVOR_A`~`FLAVOR_H`의 표시명·색상과
sprite 대응이 확정됐습니다. 화면은 불변 코드로 매칭하고 API의 표현 값을 사용합니다.

그 전에 할 수 있는 일: 와이어프레임의 8개 라벨을 잠정 값으로 명시하거나, 라벨 자리를
`맛 1`~`맛 8` 같은 자리표시자로 바꿔 장르명이 확정 사양으로 읽히지 않게 하는 것입니다.
어느 쪽이든 팀 결정이 필요합니다.

관련 문구도 함께 확인이 필요합니다. 3.2의 `8가지 팝콘 맛 · 한 알 = 영화 한 편 · 총
100알 = 평가한 영화 100편 · 데이터에 따라 색과 비율이 달라져요`는 계약과 맞습니다.

### CR-19 (취소) 이메일 인증을 메일 링크 방식으로

| 항목 | 값 |
| --- | --- |
| 대상 화면 | 0.4 이메일 회원가입 정보 입력 · 0.5 회원가입 완료 |
| 유지 | 이메일 옆 `인증요청` 버튼과 `인증번호 6자리` + `확인` 입력 — **와이어프레임 그대로 둡니다** |
| 상태 | **취소.** 가입 화면이 인증번호로 인증을 마칩니다. 0.8 이메일 인증과 0.8-A는 만들지 않습니다 |
| 근거 | 계약이 인증번호 방식으로 개정됐습니다(S15P21E106-601). API-078 이메일 인증번호 발송 · API-079 이메일 인증번호 확인이 생기고 API-002 · 003은 삭제됐습니다 |

2026-09-11 합의는 "인증번호를 확인하는 API가 계약에 없다"는 사실에 근거했고, 그 사실이
바뀌었습니다. 새 계약에서는 **가입 전에** 인증번호로 이메일 소유를 확인하고 받은
`emailVerificationToken`으로 가입하므로, 계정이 곧바로 `ACTIVE`가 되고 가입 응답이 세션을 함께
내립니다. 0.5의 인증 메일 안내와 재발송도 함께 사라집니다.

화면 반영은 업무 S15P21E106-637입니다(0.4 인증 단계 복원, 0.5 단일 경로, 0.8 · 0.8-A 삭제,
0.6의 미인증 계정 재발송 분기 삭제). **와이어프레임은 이 요청 전 상태가 맞으므로 0.4를 되돌릴
필요가 없고, 0.8을 새로 그릴 필요도 없습니다.**

### CR-28 OTT 추천 화면의 일치도 % · 추천 이유 · 분석 요약

계약이 침묵하는 값이 아니라 **계약이 주지 않기로 정한 값**이라 1장의 계약 우선 원칙을 그대로
적용합니다.

| 화면 | 빼는 것 | 대신 쓰는 것 |
| --- | --- | --- |
| EXT-01 | 본 영화 · 선호 장르 · 자주 본 배우 | `평가 N개`(API-014 `stats.ratingCount`)와 분석 대상 OTT 배지(API-025) |

| EXT-05 | `현재 진행도 N/10` 막대와 기준 평가 수 | 안내 문구와 버튼 둘만 남깁니다 |

EXT-05를 **언제** 보여줄지도 함께 정했습니다. EXT-01에서 평가 수로 미리 가르지 않고,
**API-068이 `insufficientData: true`를 주거나 `items`가 비어 있을 때** 보여줍니다. 기준 평가
수가 계약에 없고, 계약은 `현재 Candidate가 있으면 취향 입력이 0건이어도 insufficientData는
false`라고 정하고 있어 화면이 평가 수로 미리 판단할 근거가 없기 때문입니다.

계약은 바꾸지 않으므로 이 결정에서 파생되는 후속 계약 업무는 없습니다. 화면 반영은 업무
`S15P21E106-564`입니다.
