# 와이어프레임 수정 지시서

`Feelm UI Wireframe Final.html`을 API 계약과 요구사항 정의서에 맞추기 위한 수정 요청
목록입니다. [Screen Spec](./screen-spec.md) 8장의 확정 결과에서 나왔습니다.

## 1. 배경과 원칙

Screen Spec 1차 작성 중 와이어프레임과 계약이 다른 항목 12건, 계약에 데이터 출처가 없는
화면 요소 9건을 발견했습니다.

**계약이 기준입니다.** 와이어프레임과 API 계약·요구사항 정의서가 다르면 계약을 따르고,
와이어프레임을 계약에 맞게 수정합니다. 문서 우선순위는 루트
[`AGENTS.md`](../../../AGENTS.md) 1장을 따릅니다.

## 2. 이 문서의 위치와 처리 방법

### 수정 대상 파일

| 항목 | 값 |
| --- | --- |
| 파일 | `Feelm UI Wireframe Final.html` |
| 위치 | 저장소 밖. 로컬 `Feelm/` 작업 폴더 |
| 형식 | Claude Design 캔버스 번들 (단일 HTML, 약 20MB) |
| Git 추적 | 되지 않음 |

### 수정 방법

**Claude Design 캔버스 편집기에서 수정합니다.** 이 파일은 캔버스 편집기가 생성한
산출물이며, 에셋과 디자인 DOM이 번들 페이로드로 들어 있습니다. 파일을 직접 편집하면
캔버스에서 다시 열었을 때 구조가 깨지거나 다음 저장 때 수정이 되돌아갈 수 있습니다.

Git으로 추적되지 않으므로 **수정 전 백업**을 권장합니다.

### 담당 업무

와이어프레임 수정은 UI/UX 업무이며 Epic `S15P21E106-266`(FE 초기 개발) 범위가 아닙니다.
`S15P21E106-75` 또는 `S15P21E106-107` [UI/UX] 와이어프레임 및 화면 흐름 설계 아래
별도 업무로 처리해 주세요.

### 이 문서를 쓰는 방법

- **CR-01 ~ CR-12**: 계약 기준이 확정된 항목입니다. 그대로 수정하면 됩니다. 단 CR-06은 대체할 값이 아직 없어 값 확정 후 수정합니다
- **CR-13 ~ CR-18**: 결정이 먼저 필요한 항목입니다. 결정 후 수정합니다
- **5장 보류**: 계약 자체가 미정이라 지금 수정할 수 없는 항목입니다
- **6장 부가 확인**: 계약과 충돌하지는 않지만 와이어프레임에서 확인이 필요한 항목입니다

## 3. 확정된 수정 요청 (CR-01 ~ CR-12)

### CR-01 평가 별점을 1점 단위 정수로

| 항목 | 값 |
| --- | --- |
| 대상 화면 | 2.5 영화 평가 |
| 현재 | `4.5 / 5.0 · 0.5점 단위` |
| 변경 | `4 / 5` — 별 5개, 1점 단위 |
| 근거 | FR-19 인수 조건 `점수(1~5점)는 필수`, API-036 `score` (`integer`, 1~5) |

별 아이콘도 반쪽 별 표현을 쓰지 않도록 조정이 필요합니다.

**연쇄 확인 대상** — 아래 화면의 별점 표기가 정수로 표현 가능한지 확인해 주세요.

| 화면 | 현재 표기 |
| --- | --- |
| 2.4 영화 상세 | `평균 ★ 3.7` — 평균값이므로 소수 유지가 맞습니다. 변경 불필요 |
| 3.1 취향 필름 메인 | `★ 4.5`, `★ 4.0`, `★ 5.0` — 내 평가값이므로 **정수로 변경** |
| 3.1-A 프레임 상세 | `내 별점 4.0` — 내 평가값이므로 **정수로 변경** |
| 4.1 검색 홈 (범위 밖) | `★ 4.3`, `★ 4.1`, `★ 4.4` — 평균값. 변경 불필요 |
| 2.4 다른 사용자 한줄평 | `★ 4.5`, `★ 4.0`, `★ 3.5` — 개인 평가값이므로 **정수로 변경** |

평균 별점은 소수, 개인 평가 별점은 정수입니다.

### CR-02 추천 카드 개수를 3장으로

| 항목 | 값 |
| --- | --- |
| 대상 화면 | 2.2 오늘의 추천 |
| 현재 | 취향 맞춤 3장 + 새로운 맛 발견 2장 = 5장 |
| 변경 | 취향 맞춤 **2장** + 취향 발견 **1장** = 3장 |
| 근거 | API-045 처리 규칙 `기본 구성은 TASTE 2편 + DISCOVERY 1편` |

`DISCOVERY` 후보가 없으면 `TASTE` 3편이 되는 경우도 계약에 있습니다(API-045). 이 상태를
와이어프레임에 표현할지는 선택입니다.

### CR-03 추천 섹션 이름을 `취향 발견 추천`으로

| 항목 | 값 |
| --- | --- |
| 대상 화면 | 2.2 오늘의 추천 |
| 현재 | `새로운 맛 발견 추천` |
| 변경 | `취향 발견 추천` |
| 근거 | FR-12 비고 `정식 명칭 취향 발견 추천 (팀 결정 2026-08-28)` |

섹션 설명 문구 `기존 취향과 연결되는 새로운 팝콘 맛이에요`는 계약과 충돌하지 않으므로
유지합니다.

### CR-04 감상 확인 선택지를 2개로

| 항목 | 값 |
| --- | --- |
| 대상 화면 | 2.4-A 감상 확인 |
| 현재 | `봤어요` / `아직 못 봤어요` / `보지 않을래요` |
| 변경 | `봤어요` / `보지 않을래요` — `아직 못 봤어요` 삭제 |
| 근거 | API-035 요청 본문이 `watched: boolean` 2개 값 |

`아직 못 봤어요`의 의도는 기본 동작이 대신합니다. 응답하지 않으면 상태가
`LINK_CLICKED`로 유지되고, 7일 미응답 시 서버가 `EXPIRED`로 처리합니다.

이동표에서 `2.4-A ⇢ 8.1 아직 못 봤어요 → 나중에 다시 알림` 항목도 함께 삭제해 주세요.

### CR-05 평가 화면에 한줄평 공개 범위 선택 추가

| 항목 | 값 |
| --- | --- |
| 대상 화면 | 2.5 영화 평가 |
| 현재 | 공개 범위 선택 수단이 **없음** |
| 변경 | 한줄평 입력 영역에 `PUBLIC`/`PRIVATE` 선택 컨트롤 추가 |
| 근거 | FR-19 인수 조건 `한줄평이 있으면 공개 범위 PUBLIC/PRIVATE를 선택한다`, API-036 (`comment` 있는데 `visibility` 없으면 `400 VALIDATION_FAILED`) |

**이 항목만 요소 추가입니다.** 나머지는 변경 또는 삭제입니다.

디자인 결정이 필요한 사항입니다.

- 컨트롤 형태 — 토글 · 체크박스 · 세그먼트 중 무엇을 쓸지
- 기본값 — 공통 규약의 Visibility 기본값은 `PRIVATE`입니다
- 문구 — `공개` / `비공개` 또는 다른 표현
- 노출 조건 — 한줄평을 입력했을 때만 나타낼지, 항상 보일지

관련 화면과 맞춰야 할 표현이 있습니다. 3.1-A 프레임 상세는 `내 한줄평 · 공개`로 공개
상태를 표시하고, 2.4 영화 상세는 다른 사용자의 공개 한줄평을 보여줍니다.

이 항목이 반영되기 전에는 프론트엔드에서 공개 범위 컨트롤을 구현하지 않습니다.

### CR-06 팝콘 맛 이름을 기준정보 기반으로

| 항목 | 값 |
| --- | --- |
| 대상 화면 | 2.7 필름 추가 완료 · 3.2 100알의 취향 · 5.8 파티원 팝콘 |
| 현재 | 장르명 8개 — 액션·모험 · 범죄·스릴러 · 드라마 · 로맨스 · 코미디 · SF·판타지 · 공포·미스터리 · 애니메이션·가족 |
| 변경 | 기준정보의 맛 표시명으로 대체 |
| 근거 | FR-06, ADR-0015, API-044 |

팝콘 맛은 장르가 아니라 **E5 영화 임베딩을 K-Means로 분류한 8개 취향 군집**입니다
(ADR-0015). API-044 설명은 `클라이언트는 색상·표시명을 하드코딩하지 않고 이 API를
사용한다`고 정하고 있습니다.

**지금은 수정할 수 없습니다.** API-044의 미정 사항에
`8종 표시명·색상과 군집 코드 매핑 검수`가 열려 있어 대체할 표시명이 아직 없습니다.
표시명이 확정된 뒤 수정해 주세요.

그 전에 할 수 있는 일: 와이어프레임의 8개 라벨을 잠정 값으로 명시하거나, 라벨 자리를
`맛 1`~`맛 8` 같은 자리표시자로 바꿔 장르명이 확정 사양으로 읽히지 않게 하는 것입니다.
어느 쪽이든 팀 결정이 필요합니다.

관련 문구도 함께 확인이 필요합니다. 3.2의 `8가지 팝콘 맛 · 한 알 = 영화 한 편 · 총
100알 = 평가한 영화 100편 · 데이터에 따라 색과 비율이 달라져요`는 계약과 맞습니다.

## 4. 결정이 필요한 항목 (CR-13 ~ CR-18)

계약에 데이터 출처가 없는 화면 요소입니다. **계약에 필드를 추가**하거나 **와이어프레임에서
요소를 제거**해야 합니다. 결정 전까지 프론트엔드는 구현을 보류합니다.

계약 추가를 선택하면 API 계약 변경이므로 팀 합의가 필요합니다
([`ai-collaboration.md`](../../../docs/ai-collaboration.md) 6장 높은 위험).

| 문제 | `요즘 취향 흐름` 문장과 키워드 4개의 근거 문장(`계획형 캐릭터 영화 12편에 ★4 이상` 등)에 대응 필드가 없습니다. API-040 `keywords`는 `code`와 `label`만 있습니다 |
| 선택지 A | API-040 `keywords`에 근거 문장 필드를 추가 |
| 선택지 B | 근거 문장을 제거하고 키워드 라벨만 표시 |

API-040 미정 사항에 `키워드 사전 목록과 산출 규칙`이 열려 있어 이 결정과 함께 다루면
좋습니다.

### CR-17 파티 팝콘 파생 수치

| 항목 | 값 |
| --- | --- |
| 대상 화면 | 5.8 (`대표 맛`, `겹치는 맛`) · 5.9 (`공통 취향 일치 72%`, 참여자별 `46%`·`38%`) |
| 문제 | API-057 응답은 멤버별 맛 집계만 내려주며 파생 수치 산출 규칙이 없습니다. 처리 규칙은 `팝콘 공유·추가 비교 분석은 범위 밖(FR-21)`이라고 정하고 있습니다 |
| 선택지 A | 산출 규칙을 정의하고 클라이언트에서 계산 |
| 선택지 B | API-057에 파생 수치를 추가 |
| 선택지 C | 화면에서 파생 수치를 제거하고 맛 집계만 표시 |

5.9의 `② 팝콘 믹서`는 와이어프레임 자체가 `이미지 · SVG · 애니메이션 에셋 영역`으로만
표기돼 있어 시각 표현도 미확정입니다.

### CR-18 `나에게 맞는 OTT 찾기` 배너

| 항목 | 값 |
| --- | --- |
| 대상 화면 | 2.1 홈 |
| 문제 | API-068은 확장 단계이고, 와이어프레임의 EXT 화면 5개도 `MVP 이후 (Phase 2)`로 표기돼 있습니다. 1차 화면인 홈에 진입 배너가 있습니다 |

API-068 미정 사항에 `화면 배치(어느 화면에 노출할지)`가 열려 있습니다.
