업무 `S15P21E106-303` 산출물 · 에픽 `S15P21E106-301`

기준 자료는 `Feelm UI Wireframe Final.html` 67프레임 중 4.x 네 장과 6.1입니다. 표기 규칙
(`[W]` `[C]` `[?]` `[!]`)과 공통 사항은 [`screen-spec.md`](./screen-spec.md) 2·3장을,

아니라 연동 API와 계약 불일치까지 적었습니다.

## 2. 화면별 요소

### 4.1 검색 홈

**목적** 검색어를 받고, 아직 아무것도 찾지 않은 사람에게 볼 거리를 줍니다.

**요소** `[W]`

| 요소 | 내용 |
| --- | --- |
| 검색 입력 | 영화 제목, 감독, 배우 검색 |
| 최근 검색어 | 목록 · 전체 삭제 |
| 급상승 영화 | 후속 연동 시 6위까지. 순위 · 제목 · 순위 변동 · 평가 수 · 별점. 라벨은 `최근 60분 조회 증가` |
| 안내 | 검색어를 입력하면 결과가 나와요 |

**데스크톱 탐색 화면(업무 -911)**에서는 좌측 메뉴와 본문 제목을 `영화 탐색`으로 표시합니다.
상단 공통 검색창이 유일한 검색 입력이며, 본문에는 필터 버튼과 최근 검색어·급상승·평점 높은
영화를 둡니다. 검색어를 입력하면 같은 화면의 본문이 결과와 정렬·필터로 바뀝니다. 검색어
수정·지우기는 상단에서 하고, 모바일의 본문 검색 입력은 유지합니다.

**연동 API** `[C]` API-064 급상승 영화(후속 FE 업무에서 `size=6` 요청)

업무 -612에서 급상승 목업을 제거해 현재 검색 홈에는 급상승 영역이 없습니다. API-064가
구현되면 후속 FE 업무에서 실제 API를 연결해 이 영역을 다시 넣습니다. 같은 화면의
검색(API-028)과 필터 옵션(API-029)은 현재 실제 API를 호출합니다.
대체 스냅샷(`stale=true`)이면 마지막 갱신 시각(`updatedAt`)과 집계 지연 안내를 표시합니다.

**최근 검색어에는 계약이 없습니다.** 서버가 보관하는 값이 아니라 이 기기에서 무엇을
찾았는지이므로 API가 없는 것이 자연스럽습니다. 실제 앱이라면 `localStorage`가 맞지만
목업은 매번 같은 상태에서 시작해야 해서 세션 저장소에 두었습니다.

### 4.2 영화 검색 결과

**요소** `[W]`

| 요소 | 내용 |
| --- | --- |
| 검색 입력 | 입력값 + 취소 |
| 최근 검색어 | 4.1과 같은 목록 |
| 결과 수 | 검색 결과 N건 |
| 결과 행 | 포스터 · 제목 · `연도 · 장르 · ★ 평점` · OTT 배지 |
| OTT 없음 | 시청 가능한 OTT 없음 |
| 더 보기 | 다음 장이 있을 때만 |
| 안내 | 포스터를 누르면 상세페이지로 이동해요 |

**연동 API** `[C]` API-028 영화 검색

**실제 호출입니다**(업무 -476). 화면이 정하는 것은 조건을 모으는 방식뿐이고, 필터 결합
(서로 다른 필터는 AND · 같은 필터의 복수 값은 OR)과 정렬은 서버가 합니다.

- **결과 수는 `totalCount`입니다.** 받아 온 `items`의 길이가 아니라 cursor · size를
  적용하기 전 전체 건수라, 다음 장이 남아 있어도 숫자가 맞습니다
- **한 장은 20편이고 나머지는 `더 보기`로 잇습니다.** 커서는 발급 시점의 검색조건에
  묶여 있어(API-028 처리 규칙) 조건이 바뀌면 버리고 첫 장부터 받습니다. 무한 스크롤은
  넣지 않았습니다 — 사용자가 다음 장을 부르는 시점이 분명해야 조건이 바뀐 커서를 실어
  보내지 않습니다
- **`더 보기`가 실패해도 이미 그린 목록은 남습니다.** 버튼만 `다시 시도`로 바뀝니다
- **검색은 회원 전용입니다.** 로그인하지 않고 `/search`로 들어오면 제출이 `401`로
  실패하고 4.2 자리에 오류 상태가 섭니다. 이 화면만의 문제가 아니라 로그인 없이 직접
  열 수 있는 탭 전체의 문제이므로 여기서 따로 다루지 않았습니다
- **개봉연도와 장르가 없는 영화가 있습니다.** 원천 값이 없으면 `releaseYear`가 `null`,
  연결이 없으면 `genres`가 빈 배열입니다. 메타 줄은 있는 값만 잇습니다

### 4.3 검색 필터

**요소** `[W]` 장르 6 · 국가 6 · OTT 6 · 개봉연도 4 · 정렬 3 · 초기화 · `결과 보기 · N편`

**연동 API** `[C]` API-029 검색 필터 옵션 조회 · API-028(개수 세기)

`결과 보기 · N편`의 개수는 **고른 조건으로 미리 세어 본 값**입니다. 시트가 열려 있는
동안 조건을 바꿀 때마다 다시 셉니다.

**선택지는 API-029 응답으로 채웁니다**(업무 -476). 실제 영화와 연결된 기준정보만
오므로 **데이터가 적으면 선택지도 적습니다** — 와이어프레임이 그린 장르 6 · 국가 6은
고정된 수가 아닙니다. 개수 세기에는 개수 전용 계약이 없어 검색을 그대로 부르되
`size=1`로 한 장을 가장 작게 받습니다(`totalCount`는 cursor · size 이전 값입니다).

### 4.4 검색 결과 없음

**요소** `[W]` `검색 결과가 없어요` · `다른 영화 제목이나 감독, 배우 이름으로 검색해 보세요` ·
`검색어 초기화`

계약은 결과가 없어도 빈 `items`와 200을 줍니다(API-028 처리 규칙). 오류가 아니므로
`StatusView`의 `empty`로 그렸습니다.

## 4. 계약과 다른 점

### `[!]` 정렬 `취향 일치순`에 해당하는 계약 값이 없다

와이어프레임 4.3은 `취향 일치순` · `최신순` · `평점순`인데 API-028 `sort`는
`RELEVANCE` · `RATING` · `RELEASE_DATE`입니다. `RELEVANCE`는 **검색어 적합도**이지
취향 일치도가 아닙니다. 계약을 기준으로 하고(2장 계약 우선 원칙) 화면 문구를 계약이
실제로 하는 일에 맞춰 **`관련도순`**으로 바꿨습니다. 취향 일치 정렬이 필요하면 계약에
값을 추가해야 합니다.

### `[!]` 별점 만점이 다르다

와이어프레임 4.2는 `★ 7.3`처럼 10점 만점으로 적었지만 계약의 `averageRating`은
0.5~5.0입니다(FR-19 · API-036). 계약대로 5점 만점으로 두었습니다. 실제 API로 바꾼
뒤(업무 -476)에는 5점을 넘는 값이 오지 않으며, 평가가 없는 영화는 집계값이 `0`으로
옵니다.

### `[C]` 급상승의 집계 기준

와이어프레임 4.1의 라벨은 `· 최근 사용자 평가 기준`인데 API-064는 **영화 상세 조회
추이**를 집계합니다(ADR-0017). 후속 FE 연동에서는 `최근 60분 조회 증가`로 표시합니다.

### `[C]` 급상승 응답에 OTT가 없다

API-064 응답에는 OTT 정보가 없습니다. 후속 FE 연동에서 급상승 행의 OTT 배지는 표시하지
않습니다.

업무 -612에서 기존 급상승 목업과 `mocks/search.ts`는 제거되었습니다.

### `[?]` OTT 요금제와 월 요금

와이어프레임 6.1은 `프리미엄 · 매월 17,000원`을 적었지만 API-025에도 API-026에도 대응
필드가 없습니다. 사용자가 직접 입력하는 값인지 서비스가 아는 값인지부터 정해야 해서
넣지 않았습니다.

## 5. 이번 업무에서 구현하지 않은 것

- **입력 중 자동 검색.** 4.2가 입력값과 결과를 함께 보여줘 타이핑 중에도 결과가 보이는
  것처럼 읽히지만, 글자마다 조회하면 실제 연동에서 요청이 폭증합니다. 계약에 디바운스
  규칙이 없어 제출 방식으로 뒀습니다
- **무한 스크롤.** 커서 페이지는 `더 보기`로 구현했습니다(업무 -476). 와이어프레임에
  없는 요소이고, 커서가 검색조건에 묶여 있어 사용자가 다음 장을 부르는 시점이 분명한
  쪽이 안전합니다
- **EXT-01 나에게 맞는 OTT 찾기.** 확장 기능이라 6.1에 진입점을 두지 않았습니다
