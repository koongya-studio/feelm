# Feelm 프론트엔드 화면 문서

Epic [S15P21E106-266] `[FE] Feelm 와이어프레임 기반 프론트엔드 초기 개발`의 화면 설계
산출물을 관리합니다.

이 문서는 규칙을 새로 정의하지 않습니다. 화면 작업에 필요한 기준 자료가 어디에 있고
무엇의 기준인지만 정리하고, 규칙은 기존 문서로 연결합니다. 문서 종류별 역할과 문서가
충돌할 때의 우선순위는 [`docs/README.md`](../../../docs/README.md)와 루트
[`AGENTS.md`](../../../AGENTS.md) 1장을 따릅니다.

## 1. 폴더 구성

| 경로 | 내용 |
| --- | --- |
| `frontend/docs/screens/` | 이번 에픽의 화면 설계 산출물 (Screen Spec, 화면 구조, 공통 컴포넌트 기준) |
| [`screen-spec-auth.md`](./screen-spec-auth.md) | 에픽 `S15P21E106-301`의 가입·로그인 화면(0.1 ~ 0.7-A) |
| `frontend/docs/FEELM-UI-Mockup.html` | 이전 UI 목업. 기준 자료가 아닙니다 |

| `frontend/landing/` | 독립 배포하는 정적 랜딩 페이지. 이번 에픽 범위가 아닙니다 |

`frontend/` 전체 구성과 랜딩 페이지 운영은 [`frontend/README.md`](../../README.md)를
참고합니다.

## 2. UI 기준 자료

**기준은 `Feelm UI Wireframe Final.html` 하나입니다.** 화면 구성, 요소, 배치, 화면 간
이동은 이 파일을 따릅니다.

| 자료 | 화면 수 | 위치 | 상태 |
| --- | --- | --- | --- |
| `Feelm UI Wireframe Final.html` | 67프레임 | 저장소 밖 (아래 3장) | **기준** |
| `FEELM-UI-Mockup.html` | 29 | `frontend/docs/` | 참고. 필요할 때만 사용 |
| `FEELM UI Mockups Final FOR REAL.html` | 39 | **파일 없음** | 참고. 아래 7장 참조 |

기준 자료와 참고 자료가 다르게 표현하는 화면은 기준 자료를 따릅니다. 참고 자료는 기준
자료에 정보가 없을 때만 보조로 사용하고, 사용한 경우 어느 자료를 근거로 삼았는지
Screen Spec에 남깁니다.

기준 자료는 Claude Design 캔버스 번들 형식의 단일 HTML이라 브라우저로 열어 확인합니다.
원본은 수정하지 않고 읽기 전용으로 참고합니다.

아래 자료는 저장소에 포함되지 않아 상대 경로로 연결할 수 없습니다. 위치만 기록합니다.

계약을 따르고 차이를 기록합니다.

이번 단계는 목업 데이터로 화면을 구현하지만, 목업 데이터의 형태는 API 명세의 응답
구조를 따릅니다. 실제 연동 시 화면 수정 범위를 줄이기 위한 것이며, 명세에 없는 필드를
임의로 만들지 않습니다.

ADR-0013이 확정한 사항 중 이번 에픽에 직접 적용되는 것은 다음과 같습니다.

- 웹 클라이언트는 React와 Vite 기반 반응형 웹앱으로 구현합니다.
- 팝콘 버킷은 React에서 SVG로 렌더링합니다.
- ADR-0013의 후속 작업으로 남은 React 프로젝트 구조·상태 관리·Vite 환경변수·테스트
  전략 확정은 이 에픽의 화면 구조 설계와 프로젝트 초기 세팅 업무에서 다룹니다.

## 5. 와이어프레임 화면 인벤토리

기준 자료는 그룹 11개, 전체 67프레임입니다. 화면별 요소·동작·이동 경로·상태는 Screen
Spec에서 다루고, 이 문서는 그룹 단위까지만 기록합니다.

| 그룹 | 화면 수 | 비고 |
| --- | --- | --- |
| 0. 계정 진입 및 회원가입 | 8 | |
| 1. 초기 취향 설정 | 3 | |
| 2. 홈 및 영화 추천 | 10 | |
| 3. 취향 필름 및 취향 리포트 | 6 | |
| 4. 검색 | 4 | 이전 목업에서만 미정 표기 |
| 5. 파티 | 9 | |
| 6. OTT 관리 | 1 | |
| 7. MY 및 프로필 | 17 | |
| 8. 알림 | 2 | |
| 확장 기능 · 나에게 맞는 OTT 찾기 | 5 | MVP 이후 (Phase 2) |
| 참고 화면 REF-01 · REF-02 | 2 | 사용자 화면이 아닌 가이드 |

사용자 화면 65개 + 참고 2개 = 67프레임입니다.

`REF-01 하단 내비게이션 가이드`는 로그인 이후 공통 하단 바의 탭 구성, 색상, 높이,
적용·미적용 화면을 정의합니다.

> **REF-01의 5탭 구성은 `S15P21E106-329`에서 대체되었습니다(2026-09-09).** 현재
> 하단 내비는 홈 · 필름 · 파티 · MY 4탭이고, 검색은 상단 헤더로 옮겼습니다. 형태도
> 화면 폭을 채우는 바가 아니라 떠 있는 알약입니다. 기준은
> [`design-concept.md`](./design-concept.md)이며, REF-01은 적용·미적용 화면 목록에

## 7. 미확정 사항

아래 항목은 확정되지 않았습니다. 화면 구현 시 임의로 결정하지 않고, 결정이 필요한
시점에 확인합니다.

### 디자인 방향

`DESIGN_GOALS.md`가 미확정으로 표시한 항목입니다.

| 항목 | 상태 |
| --- | --- |
| Accent color | 미확정 |
| Oxblood / burgundy 사용 여부 | 미확정 |
| Film motif · 필름 스트립 시각 처리 | 미확정 |
| Ticket / typewriter / wax-seal 계열 표현 | 미확정 |
| 장식 모티프 | 미확정 |
| 특수 화면의 시각 언어 | 미확정 |
| Surface 단계 수 | 미확정 |
| Motion 언어 | 미확정 |

확정된 것은 흰 배경, 검정 계열 타이포그래피, 모바일 우선, Android 기반이며 Material 3를
구조와 사용성 기준으로 활용한다는 점입니다. 브랜드 표현 방식은 탐색 중입니다.

이번 단계는 최종 디자인을 완성하는 단계가 아니므로, 와이어프레임의 무채색 구성을
그대로 구현하고 위 항목이 확정된 뒤 별도 업무로 반영합니다.

### 검색 화면

검색 화면(와이어프레임 4.1 ~ 4.4)은 **기준 와이어프레임에는 미정 표기가 없고**, 이전
목업의 [`manifest.json`](../images/manifest.json)에서만 `⑩ 검색 홈 (입력 전) (미정)`,
`⑩-1 영화 검색 결과 (미정)`으로 표기돼 있습니다. 기준 와이어프레임에서 확정된 것인지,
표기가 빠진 것인지 확인이 필요합니다.

이번 에픽 구현 범위가 아니므로 이번 단계에서는 판단하지 않습니다.

### 자료 간 불일치

로컬 `Feelm/` 작업 폴더의 `PRODUCT.md`는 39화면 목업 `FEELM UI Mockups Final FOR
REAL.html`을 기준으로 화면 인벤토리를 기록하고 있으나, 해당 파일은 로컬 `Feelm/` 작업
폴더와 이 저장소 어디에도 없습니다. `PRODUCT.md`의 화면 인벤토리는 현재 기준 자료
67프레임과 일치하지 않습니다.

이번 에픽은 `Feelm UI Wireframe Final.html`을 기준으로 진행합니다. `PRODUCT.md`의
제품 목적·사용자·용어·브랜드 약속·데모 데이터 취급 원칙은 유효하게 참고하되, 화면
인벤토리는 참고하지 않습니다. `PRODUCT.md` 정리는 이 에픽 범위가 아니므로 별도 업무로
분리하는 것을 제안합니다.

### 데모 데이터 취급

`PRODUCT.md`가 정한 원칙에 따라, 화면에 표시되는 사용자 이름·통계·영화 메타데이터·추천
점수는 모두 데모 데이터입니다. 구현된 시스템이 생성한 값이 아니므로 측정된 결과로
표현하지 않습니다. OTT 서비스명·로고·요금은 예시이며 제휴나 API 연동이 확정된 사항이
아닙니다.
