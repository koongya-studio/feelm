# Screen Spec — 가입·로그인 (0.1 ~ 0.7-A)

업무 `S15P21E106-302` 산출물 · 에픽 `S15P21E106-301`

기준 자료는 `Feelm UI Wireframe Final.html` 67프레임 중 0.x 여덟 장입니다. 표기 규칙
(`[W]` `[C]` `[?]` `[!]`)과 공통 사항은 [`screen-spec.md`](./screen-spec.md) 2·3장을
따릅니다.

**[`screen-spec.md`](./screen-spec.md)와 나누어 두는 이유.** 그 문서는 에픽
`S15P21E106-266`의 15개 화면으로 범위를 못 박고 있습니다(1장). 범위를 넓히면 그 에픽의
완료 기준이 흐려지므로, 에픽 301의 화면은 여기에 쌓습니다.

**깊이가 얕은 이유.** 이 여덟 화면에는 대응하는 API 계약이 아직 없습니다. 인증 방식은
ADR-0009가 토큰 전달만 정했고 가입·로그인 요청·응답은 확정되지 않았습니다. 그래서
`screen-spec.md`가 화면마다 갖는 **연동 API**·**상태** 절을 두지 않고, 와이어프레임에서
읽히는 요소와 이동만 적었습니다. 계약이 나오면 그때 채웁니다.

## 4. 이번 업무에서 구현하지 않은 것

- **`비로그인 ⇢ 0.6` 라우트 보호.** 인증 상태 계층이 있어야 하고 화면 초안 범위를
  넘습니다. 넣으면 목업 미리보기에서 모든 화면이 로그인으로 튕깁니다. 후속 업무로
  분리합니다
- **실제 OAuth 이동.** 제공자를 눌러도 목업이라 곧바로 다음 화면으로 갑니다
- **서버 검증.** 인증번호·중복 확인·로그인 실패 처리는 계약이 없어 넣지 않았습니다

## 5. 미확정

- `[?]` **로그인 후 분기 기준.** `0.6 ⇢ 1.1`과 `0.6 → 2.1`을 무엇으로 가르는지가
  와이어프레임에 없습니다. 목업 프로필의 `onboardingCompleted`(API-014)로 정했습니다
- `[?]` **인증번호 제한 시간.** 와이어프레임 표시값이 `02:47`이라 3분으로 잡았습니다
- `[?]` **아이디 찾기 성공 표시.** 찾은 아이디를 어디에 어떻게 보여주는지 화면이
  없습니다. 임의로 만들지 않고 0.6으로 돌려보냅니다
- `[?]` **인증번호 자리수.** 0.4는 `인증번호 6자리`, 0.7은 `4 2 8 _ _ _`로 여섯 칸을
  그렸습니다. 둘 다 6으로 두었습니다
- `[?]` **소셜 제공자 로고.** 각 사의 브랜드 가이드가 로고와 색을 강제하는 경우가
  있습니다. 와이어프레임대로 무채색 한 글자 표식을 씁니다
- `[?]` **비밀번호 규칙의 나머지.** 특수문자 요구·최대 길이·금지 문자는 계약에 없습니다
- `[?]` **성별·나이의 저장 여부와 형식.** 입력만 두었고 계약이 없습니다
