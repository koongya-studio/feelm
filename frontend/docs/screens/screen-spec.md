# Screen Spec (1차)

Epic [S15P21E106-266] `[FE] Feelm 와이어프레임 기반 프론트엔드 초기 개발`의 구현 대상
화면 명세입니다. 기준 자료와 우선순위는
[화면 문서 지도](./README.md)를 따릅니다.

## 1. 목적과 범위

와이어프레임에서 **확인된** 화면 요소, 화면 내부 동작, 화면 간 이동 경로, 상태를
정리하고 **미확정 사항을 구분해 기록**합니다. 이 문서는 화면 구현과 목업 데이터 구성의
입력으로 사용합니다.

### 대상 화면 (15개 + 참고 1개)

| 구분 | 화면 |
| --- | --- |
| 초기 취향 설정 | 1.1 영화 취향 초기 설정 · 1.2 구독 OTT 초기 설정 · 1.3 첫 취향 필름 생성 완료 |
| 홈 및 추천 | 2.1 로그인 후 홈 · 2.2 오늘의 추천 · 2.2-A 추천 실패 · 2.3 추천 카드 ⋯ 메뉴 · 2.3-A 관심없음 처리 |
| 영화 상세·평가 | 2.4 영화 상세 · 2.4-A 감상 확인 · 2.5 영화 평가 · 2.6 필름 추가 중 · 2.7 필름 추가 완료 |
| 취향 필름 | 3.1 취향 필름 메인 · 3.1-A 프레임 상세 |
| 팝콘 | 3.2 100알의 취향 · 5.8 파티원 팝콘 한눈에 보기 · 5.9 파티 팝콘 섞기 |
| 참고 | REF-01 하단 내비게이션 가이드 |

### 범위 밖

대상 외 52개 화면은 명세하지 않습니다. 이동 경로가 범위 밖 화면으로 나가는 경우 **목적지
번호만** 기록하고, 해당 화면은 이번 단계에서 구현하지 않습니다.

실제 API 연동, 백엔드 구현, 최종 브랜딩도 범위 밖입니다. 이번 단계는 목업 데이터로
동작합니다.

### 계약 우선 원칙 (확정)

와이어프레임과 API 계약·요구사항이 다른 경우 **계약이 기준입니다.** 구현은 계약을 따르고,
와이어프레임은 계약에 맞게 수정합니다.

팀이 명시적으로 와이어프레임 쪽을 택한 경우에는 계약을 고칩니다.
2026-09-07 별점 단위 합의는 FR-19·API-036·ERD에 반영됐으며 8.1절 1번을 따릅니다.

와이어프레임 원본 수정은 UI/UX 업무이며 이 에픽 범위가 아닙니다. 무엇을 어떻게 고쳐야
하는지는 [와이어프레임 수정 지시서](./wireframe-change-requests.md)에 정리했습니다.

`[!]` 항목과 확정 결과는 8장에 모아 두었습니다.
