# PC 검색 화면 데스크톱 시안 확인 기록

2026-09-22, 4.1 · 4.2 검색에 2026-09-21 PC 시안을 적용한 뒤 폭 네 단계에서 배치가 깨지지
않는지, 412px이 그대로인지를 실제 브라우저에서 확인한 기록입니다. 확인은 로컬 개발 서버에
로그인 없이 붙는 임시 고정 응답을 두고, 폭을 412 · 1024 · 1280 · 1440px으로 바꿔 가며 화면을
캡처해서 했습니다(업무 -783 · -785와 같은 방법이며 임시 파일은 커밋 전에 지웠습니다).

**결론부터**: 네 폭 모두 가로 넘침과 콘텐츠 겹침이 없고, 412px은 기존 화면과 같습니다.
확인 과정에서 배치 결함 둘을 찾아 고쳤습니다.

## 1. 무엇을 어디에 두었나

| 자리 | 내용 |
| --- | --- |
| 제목 | `검색` 큰 제목(좁은 화면의 `ScreenHeader` 대신) |
| 검색줄 | 큰 입력창과 `필터 N` 단추. 단추가 정사각형 아이콘에서 글자와 개수 배지로 바뀐다 |
| 그 아래 | `제목 · 감독 · 배우 통합 검색` · 최근 검색어 칩 · **걸려 있는 필터 칩 + `필터 초기화`** |
| 결과 머리줄 | `검색 결과 N`과 정렬 컨트롤 (좁은 화면과 같다) |
| 결과 | 카드 격자. 포스터 아래에 제목 · 개봉연도 · 장르 · 평점 · OTT 배지 |
| 우측 단 | 고른 영화(포스터 · 연도 · 장르 · 평점 · OTT · `영화 상세 보기` · 줄거리 · 감독 · 주요 출연진 · 장르 · 제작 국가)와 `유사한 작품` |

보조 패널 껍데기는 업무 -783이 만든 `components/AsidePanel`, 포스터는 `components/Poster`,
OTT 배지는 `components/OttBadge`를 그대로 씁니다. **새로 만든 디자인 자산은 없습니다**(업무 지시).

**최근 검색어는 넓은 화면에서 결과가 있어도 남습니다**(시안). 412px에서는 지금까지처럼
검색 전에만 보입니다 — 그 폭은 세로가 짧아 결과가 밀립니다.

## 2. 카드를 누르면 무엇이 되는가

**1280px 이상에서는 고르기, 그보다 좁으면 이동입니다**(사용자 결정 2026-09-22).

시안은 고른 카드에 빨간 테두리를 두고 상세로 가는 것은 우측 패널의 `영화 상세 보기`입니다.
그런데 우측 패널 자리는 1280px 이상에서만 열리므로(업무 -782), 1024~1279px에서 카드를
고르기로 만들면 눌러도 아무 일이 없습니다. 그 폭과 412px 이하에서는 칸이 지금까지처럼 곧
상세 링크입니다(`SearchResultGrid`의 `onPick` 유무).

**고르는 일은 상태가 아니라 결과에서 끌어냅니다.** 새 검색 결과가 오면 고른 번호가 그 안에
없으므로 저절로 첫 영화로 돌아갑니다(시안 — 첫 칸에 테두리가 있다). 맞추는 효과를 따로 두면
결과가 바뀔 때마다 한 박자 늦게 따라옵니다.

## 3. 폭 단계별로 확인한 것

| 폭 | 확인 결과 |
| --- | --- |
| 412px | **기존과 같음**. 3열 포스터 + 제목, 정사각형 필터 아이콘, 필터 칩 줄 없음, 하단 3탭 |
| 1024px | 좌측 내비 · 상단 바. 우측 단 없음, 중앙 764px. 카드 4열이며 **고르기가 아니라 링크** |
| 1280px | 우측 단(328px)이 열리고 중앙 676px. 카드 4열 |
| 1440px | 중앙 836px · 우측 328px. 카드 **5열**(한 칸 151 × 327px) — 시안의 배치 |

네 폭 모두에서 **가로 스크롤바가 생기지 않고**(`scrollWidth === clientWidth`) 글자가 겹치는
자리도 없습니다.

## 4. 시안과 다르게 둔 것

| 시안 | 이 구현 | 이유 |
| --- | --- | --- |
| 아래의 쪽 번호 `1 2 3 4 5` | 지금의 **스크롤로 이어 받기 · `더 보기`** | 계약(API-028)의 페이지는 **불투명 커서**다. `nextCursor`를 따라가는 방식이라 `3쪽으로` 같은 건너뛰기를 만들 수 없고, 전체 쪽 수도 계산할 값이 없다. 쪽 번호는 계약 변경이 먼저다 |
| 우측 `연관 키워드`(사회 계층 · 블랙 코미디 · 칸 영화제 ⋯) | `장르 · 제작 국가` 칩 | 키워드는 어느 응답에도 없다. 같은 자리에 API-030이 주는 값을 둔다(사용자 결정 2026-09-22) |
| 활성 필터 칩의 `한국`(국가) | 장르 · OTT · 개봉연도 칩만 | **이 화면은 국가를 고르게 하지 않기로 이미 정했다**(업무 -612 — 계약이 주는 국가가 백을 넘어 시트가 국가 목록으로 뒤덮였다). 그 결정을 이 업무가 되돌리지 않는다(사용자 결정 2026-09-22) |
| 평점 `8.6` | `4.3` | 이 앱의 평가는 0.5~5.0이다(FR-19). 영화 상세와 같은 수를 적는다(업무 -783과 같은 결정) |
| 감독 · 출연진의 얼굴과 `›` | 이름만 | 인물 화면이 이 앱에 없고 계약의 `profileUrl`도 사람에 따라 비어 있다. 누를 수 없는 `›`를 두면 눌리는 것처럼 보인다 |
| 분홍 · 파스텔 칩 | 무채색 | UI 요소에 유채색을 쓰지 않는다(`design-concept.md` 2.3). 걸려 있다는 것은 테두리와 `✕`가 말한다 |
| `정확도순` | `관련도순` | 계약의 `RELEVANCE`가 하는 일에 맞춘 기존 문구다(`searchFilter.ts`) |

## 5. 유지한 동작

- **주소의 검색 조건이 그대로다**(업무 -634). 칩으로 필터 하나를 풀어도 검색어와 나머지
  조건은 주소에 남는다
- 상세 이동과 **뒤로 가기 결과 · 스크롤 복원**(`searchSnapshot`)이 그대로다. 우측 패널의
  `영화 상세 보기`와 `유사한 작품`도 떠나기 전에 같은 자리에 적어 둔다
- 타이핑 검색 · 디바운스 · 두 글자 임계 · 오래된 응답 버리기 · 필터 시트 · 정렬 · 다음 장
  이어 받기는 손대지 않았다

**고른 영화마다 API-030과 API-031을 한 번씩 더 부릅니다.** 검색 응답(API-028)에는 줄거리 ·
감독 · 출연진이 없어 패널을 채울 수 없기 때문입니다. 받는 동안에도 패널은 검색 결과가 준
것(제목 · 포스터 · 연도 · 장르 · 평점 · OTT)으로 이미 서 있어 빈 화면이 보이지 않고, 좁은
폭에서는 고르지 않으므로 부르지 않습니다.

## 6. 공용 컴포넌트 변경

`components/AsidePanel`에 **선택값 `onClose`를 더했습니다**(업무 -783이 만든 카드 껍데기).
4.2의 우측 패널은 고른 영화를 말하므로 고르기를 물릴 수 있어야 하고, 시안이 제목 줄
오른쪽에 `✕`를 두었습니다. 주지 않으면 그리지 않으므로 이 값을 쓰지 않는 3.1 · 2.2 · 5.1의
카드는 **한 픽셀도 바뀌지 않습니다.**

## 7. 확인하면서 고친 것

| 증상 | 원인 | 고친 방법 |
| --- | --- | --- |
| 카드마다 폭이 달라 격자가 들쭉날쭉 | 격자 항목의 자동 최소 크기가 내용의 min-content이라, `2021 · 다큐멘터리`처럼 줄바꿈하지 않는 줄과 OTT 배지 석 장이 `1fr`을 넘겼다 | 칸(`li`)의 `min-width`를 0으로 두어 모든 열을 같은 폭으로 |
| 같은 열 안에서도 카드 폭이 제각각 | 고르는 칸은 `button`이고 단추는 칸을 채우지 않고 자기 내용만큼만 넓어진다(링크는 지금까지도 채웠다) | 데스크톱 칸의 폭을 100%로 못 박음 |

| 검사 | 결과 |

| `npm run lint` | 통과 |

| `npm run build` | 통과 |

새 테스트는 `SearchDesktop.test.tsx` 아홉입니다. 고정하는 것은 **무엇이 어느 자리에
그려지고**(카드의 연도 · 장르 · 평점 · OTT, 우측 패널, 필터 칩), **동작이 그대로인지**
(고르기 · 상세 이동 · 주소의 검색 조건), 그리고 **좁은 폭에서 데스크톱 전용 요소가 새지
않는지**입니다.

자동 테스트는 jsdom에서 돌아 **레이아웃이 없습니다.** 폭이 모두 0이라 7장의 둘은 하나도
잡히지 않습니다.

## 9. 확인하지 못한 것

- **실제 데이터로 확인하지 않았습니다.** 로그인 없이 보기 위해 고정 응답을 두었고 포스터
  이미지 대신 자리표시자가 그려진 상태입니다. 제목이 아주 긴 영화, 출연진이 없는 영화,
  줄거리가 없는 영화, OTT가 다섯인 영화는 보지 못했습니다.
- **다음 장 이어 받기를 넓은 화면에서 눈으로 보지 못했습니다.** 고정 응답이 한 장짜리라
  `hasNext`가 늘 `false`였습니다. 목록을 잇는 코드는 손대지 않았습니다.
- **키보드와 화면 읽기 도구로 확인하지 않았습니다.** 카드 선택(`aria-pressed`)과 패널의
  초점 순서는 눈으로만 봤습니다.
- **배포 환경에서는 확인하지 않았습니다.** 로컬 개발 서버로만 봤습니다.
- **768px은 따로 보지 않았습니다.** 1024px 미만은 모바일 셸이 그대로이며 그 경계는
  업무 -782에서 확인했습니다.
