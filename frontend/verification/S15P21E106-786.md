# PC MY 화면 데스크톱 시안 확인 기록

2026-09-22, 7.1 MY에 2026-09-21 PC 시안을 적용한 뒤 폭 네 단계에서 배치가 깨지지 않는지,
412px이 그대로인지를 실제 브라우저에서 확인한 기록입니다. 확인은 로컬 개발 서버에 로그인
없이 붙는 임시 고정 응답을 두고, 폭을 412 · 1024 · 1280 · 1440px으로 바꿔 가며 화면을
캡처해서 했습니다(업무 -783 ~ -785와 같은 방법이며 임시 파일은 커밋 전에 지웠습니다).

**결론부터**: 네 폭 모두 가로 넘침과 콘텐츠 겹침이 없고, 412px은 기존 화면과 같습니다.
확인 과정에서 배치 결함 셋을 찾아 고쳤습니다.

## 1. 무엇을 어디에 두었나

| 자리 | 내용 |
| --- | --- |
| 제목 줄 | `프로필` · 오른쪽에 설정 톱니 |
| 프로필 카드 | 사진 · 닉네임 · 소개 · `프로필 편집` · `프로필 공유` · 수치 셋 (`ProfileLayout`, 밝은 면) |
| 바로가기 | `4컷 리포트` · `취향 팝콘` 검은 카드 둘. 넓은 화면에서는 이름 아래 설명 한 줄이 붙는다 |
| 내 기록 | 구역 이름 · 탭 셋 · 포스터 격자(칸마다 별점 · 날짜 · 제목) · `더 보기` |
| 우측 단 | `나의 취향 키워드` · `팝콘 분포도` · `최근 활동` |

**사진 배경 틀이 없다.** 412px은 프로필 사진이 화면 전체 배경이지만(업무 -697), 시안의
데스크톱 프로필은 밝은 벽 위의 흰 카드입니다. 상단의 검색 · 알림 · 프로필은 데스크톱 셸의
상단 바가 이미 맡습니다(업무 -782).

**본문은 두 벌이 아닙니다.** 프로필 · 바로가기 · 탭 · 피드를 한 덩어리로 만들어 좁은
화면은 사진 배경 틀 안에, 넓은 화면은 셸의 중앙 단에 그대로 놓습니다. 갈리는 것은 껍데기와
면의 밝기뿐입니다.

## 2. 폭 단계별로 확인한 것

| 폭 | 확인 결과 |
| --- | --- |
| 412px | **기존과 같음**. 어두운 사진 배경 · 3열 포스터 · 별점만 · 하단 3탭 |
| 1024px | 좌측 내비 · 상단 바. 우측 단 없고 중앙 764px. 포스터 6열 |
| 1280px | 우측 단(328px)이 열리고 중앙 676px. 포스터 5열 |
| 1440px | 중앙 836px · 우측 328px. 포스터 **7열**(한 칸 105px) |

네 폭 모두에서 **가로 스크롤바가 생기지 않고**(`scrollWidth === clientWidth`) 글자가 겹치는
자리도 없습니다.

## 3. 시안과 다르게 둔 것

| 시안 | 이 구현 | 이유 |
| --- | --- | --- |
| 수치 `본 영화 / 평가 / 취향 리포트` | `프레임 / 팝콘 / 공개 한줄평` | **지금 세 수치를 유지한다**(사용자 결정 2026-09-22). 수치는 7.2 · 7.2-A · 7.2-B와 공용인 `ProfileLayout`이 그리므로, 바꾸면 네 화면의 프로필이 함께 바뀐다 |
| 우측 `좋아하는 장르 TOP 5` 막대 | 두지 않음 | **아래 `팝콘 분포도`와 같은 값이다**(사용자 결정 2026-09-22). 이 앱에서 `액션 · 모험`은 장르가 아니라 팝콘 맛이고(API-041 · API-044) 백분율도 같은 알 수의 비율이다. 같은 수치를 두 번 그리지 않고 표 하나로 합쳤다 |
| `최근 활동` 활동 로그 | 평가(API-039) · 리포트(API-059)를 시각순으로 섞어 넉 줄 | **활동 로그 계약이 없다.** 이미 받아 둔 두 목록으로 조립한다(사용자 결정 2026-09-22) — 새로 부르는 API는 없다. 시안의 `취향 팝콘이 업데이트되었어요`는 그 시각을 주는 값이 없어(API-041에 갱신 시각이 없다) 넣지 않았다 |
| 선호도 `22%` | `★ 4.4` | 계약이 주는 값은 맛별 평균 별점이다(API-041). 3.1 · 3.2와 같은 표기여야 같은 값이 화면마다 다른 수로 보이지 않는다(업무 -783과 같은 결정) |
| 프로필 사진이 왼쪽, 이름 · 버튼이 오른쪽 | 사진 · 이름 · 버튼이 세로로 | 프로필 머리는 네 화면이 함께 쓰는 `ProfileLayout`이다. 이 업무에서 그 배치를 바꾸면 7.2 · 7.2-A · 7.2-B가 함께 바뀐다 |
| `내 기록` 오른쪽의 `더 보기 ›` | 격자 아래 `더 보기` 하나 | 다음 장을 받는 버튼은 이미 격자 아래에 있다(업무 -503). 같은 일을 하는 버튼을 두 자리에 두지 않는다 |
| 우측 `최근 활동`의 `전체 보기 ›` | 두지 않음 | 같은 화면의 `내 기록` 피드가 그 일을 한다. 위를 가리키는 링크가 된다 |

**넓은 화면의 날짜는 해까지 적습니다.** 피드는 여러 해에 걸쳐 있어 `1. 10`만으로는 언제인지
알 수 없습니다. 412px 3열에는 그 글자가 들어갈 자리가 없어 지금까지의 짧은 형식 그대로입니다.

## 4. 공용 컴포넌트 변경

**팝콘 맛 분포 표를 `components/PopcornFlavorPanel`로 옮겼습니다.** 업무 -783이 3.1 취향
필름의 우측 패널에 만든 표인데, 이번 시안의 `팝콘 분포도`가 **같은 표**입니다(검은 카드 ·
팝콘 알 그림 · 감상량 · 선호도). 두 화면이 각자 그리면 간격과 수치 표기가 어긋나므로 한
번만 만들고 카드 제목과 화살표가 가는 곳만 받습니다(Jira 지시 — 이미 개발해 쓰는 것은 새로
만들지 않고 재사용한다).

**3.1이 그리는 모양과 가는 곳은 그대로입니다.** 옮긴 것은 표와 그 CSS뿐이고 제목
(`나의 취향 팝콘`) · 링크 · 어두운 면은 3.1이 계속 정합니다. 3.1 테스트 27개가 그대로
통과합니다.

## 5. 확인하면서 고친 것

| 증상 | 원인 | 고친 방법 |
| --- | --- | --- |
| 포스터 아래 날짜 · 제목 위로 **별점 알약이 내려앉음** | 별점이 칸 전체를 기준으로 절대 배치되어 있었는데, 넓은 화면에서 칸에 글이 붙으면서 칸이 길어짐 | 별점을 **포스터 칸 안**(`PosterCue`)으로 옮김. 그 칸이 곧 포스터라 412px의 자리는 그대로다 |
| 프로필 카드의 `프로필 편집` · `프로필 공유`가 **보이지 않음** | 두 버튼이 사진 배경 위의 유리 판이라 글자가 흰색이었다 | 넓은 화면에서 시안대로 `편집`은 흰 면, `공유`는 빨간 테두리로 |
| 링크에 읽히는 이름이 `4.5 인 셉 션` 순서로 뒤바뀜 | 별점을 포스터 안으로 옮기면서 읽기 순서가 제목보다 앞이 됐다 | 읽기 도구용 제목을 포스터보다 앞에 둠 |

## 6. 자동 검사

| 검사 | 결과 |
| --- | --- |
| `npm run test:run` | 901개 모두 통과 |
| `npm run lint` | 통과 |
| `npm run format:check` | 통과 |
| `npm run build` | 통과 |

새 테스트는 `MyDesktop.test.tsx` 여섯입니다. 고정하는 것은 **무엇이 어느 자리에 그려지고**
(제목 · 우측 패널 셋 · 피드 칸의 날짜와 제목), **동작이 그대로인지**(탭과 `더 보기`가 같은
API를 같은 조건으로 부른다), 그리고 **412px에서 데스크톱 전용 요소가 새지 않는지**입니다.

전체 실행을 두 번 돌렸고 한 번은 901개가 모두 통과, 한 번은 한 건이 깨졌습니다. 단독으로
돌리면 통과하며 업무 -782 · -783의 확인 기록에 이미 적힌 **전체 실행 부하에서만 드러나는
간헐 실패**입니다.

자동 테스트는 jsdom에서 돌아 **레이아웃이 없습니다.** 폭이 모두 0이라 5장의 셋은 하나도
잡히지 않습니다.

## 7. 확인하지 못한 것

- **실제 서버 데이터로 보지 못했습니다.** 프로필 사진 · 소개 · 취향 키워드는 계약에 없어
  목업 저장소 값이고(업무 -616), 4컷 리포트 그림은 고정 응답을 만들지 않아 빈 인화지로
  확인했습니다. 리포트가 실제로 들어찬 모습은 보지 못했습니다.
- **`안 남긴 영화` · `추천 기록` 탭의 넓은 화면 모습을 눈으로 보지 못했습니다.** 고정
  응답이 빈 목록이었습니다. 칸의 구성은 평가 탭과 같습니다.
- 키보드와 화면 읽기 도구, 배포 환경은 확인하지 않았습니다.
- **768px은 따로 보지 않았습니다.** 1024px 미만은 모바일 셸이 그대로이며 그 경계는
  업무 -782에서 확인했습니다.
