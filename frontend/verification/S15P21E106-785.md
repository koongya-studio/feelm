# PC 파티팝콘 화면 데스크톱 시안 확인 기록

2026-09-22, 5.1 파티팝콘에 2026-09-21 PC 시안을 적용한 뒤 폭 다섯 단계에서 배치가 깨지지
않는지, 412px이 그대로인지를 실제 브라우저에서 확인한 기록입니다. 확인은 로컬 개발 서버에
로그인 없이 붙는 임시 고정 응답을 두고, 폭을 412 · 768 · 1024 · 1280 · 1440px으로 바꿔 가며
화면을 캡처해서 했습니다(업무 -783과 같은 방법이며 임시 파일은 커밋 전에 지웠습니다).

> 2026-09-25 업무 `S15P21E106-853`에서 계약에 없는 `초대 코드로 참여하기` 버튼과 준비 중
> 안내를 모바일·데스크톱 모두에서 제거했습니다. 아래 배치 설명은 현재 UI에 맞게
> 갱신했으며, 나머지 내용은 당시 시안 검증 기록입니다.

**결론부터**: 다섯 폭 모두 가로 넘침과 콘텐츠 겹침이 없고, 412px은 기존 화면과 같습니다.
확인 과정에서 배치 결함 셋을 찾아 고쳤습니다.

## 1. 무엇을 어디에 두었나

| 자리 | 내용 |
| --- | --- |
| 제목 줄 | `PARTY POPCORN` · `파티팝콘` · `같이 볼 영화, 함께 골라요`, 오른쪽에 `＋ 파티 만들기` |
| 받은 초대 N | 카드 두 열. 장식 타일 · 방장 얼굴 · 때 · 인원 · 파티 이름 · `수락하기` · `자세히 보기` |
| 참여 중인 파티 N | 카드 격자. 고른 카드는 검정 면에 빨간 테두리 + 파티 팝콘 통, 나머지는 흰 면에 공통 취향 칩. 카드마다 아래에 `파티로 이동` |
| 우측 단 | 고른 파티(멤버 · 공통 취향 · 인원 참여 현황 · `파티 추천 보기`)와 `새로운 파티를 만들어보세요` |

보조 패널 껍데기는 업무 -783이 만든 `components/AsidePanel`을 그대로 씁니다. 통은
`components/PopcornBucket`, 사람 아이콘은 `components/Icon`의 `PartyGroupIcon`이며 **새로
만든 디자인 자산은 없습니다**(업무 지시).

**고른 파티와 파티로 가는 것을 나눴습니다.** 카드를 누르면 우측 패널이 그 파티를 말하고,
파티 화면(5.8)으로 가는 것은 카드 아래의 `파티로 이동`입니다. 시안이 그 둘을 나눠 두었고,
카드를 누를 때마다 화면이 떠나면 오른쪽 패널을 볼 수가 없습니다.

## 2. 폭 단계별로 확인한 것

| 폭 | 확인 결과 |
| --- | --- |
| 412px | 워드마크 헤더 · 강조 카드 · 가로 카드 줄 · 아래 `파티 만들기` · 하단 내비 |
| 768px | 412px 셸이 가운데에 그대로 섬(업무 -782의 규칙) |
| 1024px | 좌측 내비 · 상단 바. 우측 단 없음, 중앙 764px. 초대 2열(360px) · 파티 카드 2열(360px) |
| 1280px | 우측 단(328px)이 열리고 중앙 676px. **초대가 1열(644px)로 내려감**, 파티 카드 2열(316px) |
| 1440px | 중앙 836px · 우측 328px. 초대 2열(396px), 파티 카드 3열(260px) — 시안의 배치 |

다섯 폭 모두에서 **가로 스크롤바가 생기지 않고**(`scrollWidth === clientWidth`) 글자가 겹치는
자리도 없습니다.

## 3. 시안과 다르게 둔 것

시안에는 있으나 파티 계약(API-050 · API-052 · API-057)에 값이 없는 것들입니다. 없는 값을
지어내지 않는다는 이 화면의 기존 규칙(`PartyListPage/index.tsx` 머리말)을 그대로 따랐고,
아래 셋은 **사용자 결정 2026-09-22**입니다.

| 시안 | 이 구현 | 이유 |
| --- | --- | --- |
| 초대 카드의 영화 포스터 | 팝콘 장식 타일(2:3, 빈 통) | 초대(API-052)에 영화가 없다. 파티는 취향을 섞어 추천을 받는 것이라 초대 시점에 고른 영화라는 것 자체가 없다 |
| 우측 `영화 선택 현황 3 / 4명 선택 완료` | `인원 참여 현황 N / M명 참여` | 파티원이 영화를 하나씩 고르는 절차가 이 앱에 없다(API-057 · API-058) |
| 멤버 배지 `선택 완료` · `선택 중` | `방장` · `멤버` | 같은 이유. 계약이 주는 것은 역할(`role`)뿐이다 |
| 카드 배지 `토론 중` · `영화 선택 중` | `모집 중`(정원 미달) · `진행 중`(정원 참) | 계약의 파티 상태는 `ACTIVE` · `CLOSED`뿐이고 목록에 오는 것은 활성 파티뿐이다(API-050 기본값) |
| 초대 카드의 한마디(`이번 주에 같이 볼 영화 골라봐요!`) | 파티 이름 | 초대에 메시지 필드가 없다 |
| 초대 카드의 참여자 얼굴 | 그리지 않음 | API-052가 주는 것은 `memberCount` 하나다. 인원은 오른쪽 위에 이미 있다 |
| 얼굴 사진 | 닉네임 첫 글자 | 프로필 사진이 파티 계약에 없다(`userId` · 닉네임뿐). 412px과 같은 처리다 |
| 고르지 않은 카드의 팝콘 알 | 공통 취향 칩 | 알은 통 안에 담겨야 읽히는 그림이다(3.2 · 5.9). 같은 값(API-057)을 글로 적는다 |
| 파스텔 칩 · 노랑 · 파랑 점 | 무채색 | UI에 유채색을 쓰지 않는다(`design-concept.md` 2.3). 412px 강조 카드와 같은 결정이다 |
| 패널 제목 옆 톱니(파티 설정) | 두지 않음 | 파티 관리(나가기 · 종료 · 내보내기)의 진입점은 5.8의 `⋯` 메뉴 하나라는 결정(업무 -462)을 이 업무가 바꾸지 않는다 |

`우리의 공통 취향` 칩은 **412px 강조 카드와 같은 값**입니다 — 파티 팝콘(API-057)을 맛별로
합쳐 알이 많은 셋이고, 이름표(API-044)를 못 받은 맛은 뺍니다. 두 폭에서 같은 파티가 서로
다른 취향을 말하지 않게 한 함수 하나를 씁니다.

**시안에 없는 상태를 하나 더했습니다.** 파티도 초대도 없을 때의 가운데 안내입니다. 우측
패널의 `새로운 파티를 만들어보세요`가 그 말을 하지만 그 패널은 1280px 이상에서만 있어
(업무 -782) 1024~1279px에서는 제목 줄만 남았습니다.

## 4. 유지한 동작

- `수락하기`는 **5.6과 같은 호출**(API-053)이고, 성공하면 파티 목록과 받은 초대를 다시 읽습니다
- `자세히 보기`는 지금까지와 같이 5.6으로, `파티로 이동`은 5.8로 갑니다
- `파티 추천 보기`는 5.8의 `함께 볼 영화 추천받기`와 같은 곳(5.9 팝콘 섞기)으로 갑니다
- 초대 코드 참여는 계약에 없어 현재 화면에 버튼이나 준비 중 안내를 노출하지 않습니다
  (업무 `S15P21E106-853`, CR-26)
- 파티 목록을 못 받으면 같은 안내와 `다시 시도`가, 초대만 못 받으면 같은 줄이 그대로 뜹니다

**파티 팝콘(API-057)을 부르는 횟수가 데스크톱에서 늘었습니다.** 412px은 강조 카드 하나뿐이라
첫 파티만 부르고, 데스크톱은 카드마다 통이 설 수 있어 목록 전체를 나란히 부릅니다. 활성
파티는 사용자당 최대 10개입니다(API-049 처리 규칙).

## 5. 확인하면서 고친 것

| 증상 | 원인 | 고친 방법 |
| --- | --- | --- |
| `＋파티 만들기` · `자세히 보기›`의 아이콘이 글자에 붙음 | `components/Button`은 자식 사이에 간격을 두지 않는다 | 이 화면의 버튼에만 `gap`을 더함 |
| 고른 카드의 통이 카드 아래로 넘쳐 잘림 | 통 폭을 시안 값(168px)으로 두어 카드 높이보다 커짐 | 124px로 줄이고 통 자리를 `flex: 1 · min-height: 0`으로 묶음 |
| 1280px에서 초대 카드가 두 열로 남아 방장 이름이 `서연…`으로 잘리고 버튼 둘이 서로 밀림 | 한 장의 최소 폭을 300px로 두었는데, 타일(104px) 옆에 남는 글 칸이 220px 아래로 줄었다 | 최소 폭을 360px로 올림. 1280px은 한 열이 됨 |

## 7. 확인하지 못한 것

- **실제 데이터로 확인하지 않았습니다.** 로그인 없이 보기 위해 고정 응답을 돌려주는 임시
  진입점을 두고 확인했습니다. 파티 이름이 20자인 경우, 닉네임이 아주 긴 파티원, 활성 파티가
  열 개인 계정은 보지 못했습니다.
- **키보드와 화면 읽기 도구로 확인하지 않았습니다.** 카드 선택(`aria-pressed`)과 보조 패널의
  초점 순서는 눈으로만 봤습니다.
- **배포 환경에서는 확인하지 않았습니다.** 로컬 개발 서버로만 봤습니다.
- **5.8 이후 화면은 이 업무의 범위가 아닙니다.** 데스크톱 셸 위에서 5.8 · 5.9 · 5.5는 아직
  모바일 구성 그대로입니다.
