# PC 전체화면 화면 데스크톱 레이아웃 확인 기록

2026-09-22, 전체화면 화면(영화 상세 · 파티 만들기 · 설정 하위 등)을 넓은 화면에서 탭 화면과
같은 껍데기 안에 넣고, 폭 단계별로 배치가 깨지지 않는지 실제 브라우저에서 확인한 기록입니다.

**결론부터**: 1024px 이상에서 전체화면 화면도 좌측 내비 · 상단 바를 그대로 두게 되어, 탭
화면에서 들어가고 나올 때 폭과 메뉴가 바뀌지 않습니다. 1024px 미만은 손대지 않았습니다.
확인 과정에서 배경 사진이 상단 바를 덮는 결함 하나를 발견해 고쳤습니다.

## 1. 어떤 방식을 골랐나

Jira 본문이 요구한 세 갈래 중 **(나) 전부 셸 안에 넣는다**를 골랐습니다(사용자 결정
2026-09-22). 나머지 둘은 이렇습니다.

| 갈래 | 내용 | 고르지 않은 이유 |
| --- | --- | --- |
| (가) | 본문만 넓히고 좌측 내비 없이 둔다 | 탭 화면에서 넘어올 때마다 메뉴가 사라졌다 나타난다 |
| (나) | **셸 안에 넣어 좌측 내비를 유지한다** | **고름** |
| (다) | 탐색형과 집중형을 나눈다 | 한 화면씩 성격을 판정해야 하고, 그 기준을 지금 확정할 근거가 없다 |

(나)를 고르면 파티 만들기처럼 끝까지 가야 하는 흐름 중에도 좌측 메뉴로 빠져나갈 수 있습니다.
**막지 않았습니다.** 흐름을 중간에 붙잡는 것은 이 앱에 아직 없는 동작이고(7.2 프로필 편집의
`useBlocker`가 유일한 예외입니다), 시안이나 완료 조건이 요구하지도 않았습니다. 필요하다고
판단되면 별도 업무로 다룹니다.

## 2. 무엇을 바꿨나

데스크톱 뼈대를 `AppLayout` 안에서 꺼내 공용 컴포넌트로 만들고, 두 레이아웃이 그것을
씁니다. 복사하면 둘이 따로 자랍니다.

| 파일 | 바꾼 것 |
| --- | --- |
| `layouts/DesktopShell/` | -782가 `AppLayout`에 직접 세웠던 뼈대를 그대로 옮긴 새 컴포넌트 |
| `layouts/AppLayout/` | 데스크톱 가지가 `DesktopShell`을 쓴다. 모바일 가지는 그대로 |
| `layouts/FullScreenLayout/` | 1024px 이상이고 로그인했으면 `DesktopShell`을 세운다 |
| `pages/movies/MovieDetailPage/` · `components/ProfileBackdrop/` | 화면에 고정하는 배경층이 상단 바 자리를 비운다 |
| `hooks/useScrollFade.ts` | 스크롤 영역을 찾는 `scrollParent`를 내보낸다 |

**로그인한 사람에게만 셸을 세웁니다.** 이 레이아웃에는 로그인 없이 닿는 화면이 하나
있습니다 — 없는 주소(404)이고 `RequireAuth` 바깥에 있습니다. 좌측 내비는 로그인해야 갈 수
있는 곳만 가리키므로, 세우면 누를 때마다 로그인 화면으로 튕기는 메뉴를 보여주게 됩니다.

**스크롤 위치 되돌리기를 셸에 걸었습니다.** 모바일에서는 문서가 스크롤해 브라우저가 뒤로
가기의 자리를 스스로 되돌립니다. 셸 안에서는 문서가 잠기고 중앙 본문이 스크롤하므로
(`global.css`의 `data-layout="app"`) 되돌릴 주체가 없어집니다. 탭 화면이 -520에서 같은
이유로 쓰던 `useScrollRestoration`을 그대로 씁니다.

## 3. 배경 사진이 상단 바를 덮었다 — 고침

2.4 영화 상세와 7.1 · 7.2 프로필은 포스터 · 사진을 `position: fixed; inset: 0`으로 깔고 본문만
그 위로 흘려보냅니다. 창 전체가 곧 화면이던 모바일에서는 맞았지만, 셸 안에 들어오니
`inset: 0`이 상단 바 자리까지 덮어 **검색 입력이 포스터에 묻혔습니다**(2026-09-22 브라우저
확인). 좌측 내비는 자기 배경이 있어 가려지지 않았습니다.

셸이 `--shell-backdrop-inset`으로 비켜야 할 자리를 알려 주고, 두 배경층이
`inset: var(--shell-backdrop-inset, 0)`으로 읽습니다. 모바일에는 이 변수가 없어 `0`으로
떨어지므로 지금까지와 같습니다.

**덮개는 이 값을 쓰지 않습니다.** 바텀시트와 확인 창은 데스크톱에서 화면 전체를 어둡게 덮는
것이 맞습니다(-782). 좁힌 것은 화면 한 장의 배경일 뿐입니다.

## 4. 폭 단계별로 확인한 것

로컬 개발 서버에 개발용 목업 계정(`api/mockAccount`)으로 붙어 폭을 바꿔 가며 캡처했습니다.

| 폭 | 확인 결과 |
| --- | --- |
| 526px · 768px · 900px · 1000px | **기존과 같음**. 412px 단이 가운데 놓이고 좌측 내비 · 상단 바가 없음 |
| 1060px | 좌측 내비 · 상단 바가 서고 중앙 한 단. 파티 만들기 · 영화 상세 모두 가로 넘침 없음 |
| 1100px | 같음 |
| 1280px | 우측 보조 패널 자리가 열리지만 전체화면 화면은 보내는 내용이 없어 `:empty`로 접힘. 빈 단이 남지 않음 |
| 1440px | 중앙 단이 960px 상한에서 가운데 정렬. 알림 · 계정 관리 · 차단 사용자 · 공개 프로필 · 영화 상세 모두 넘침 없음 |

확인한 화면은 알림 목록 · 영화 상세 · 파티 만들기 · 계정 관리 · 차단 사용자 · 공개 프로필과,
대조용 탭 화면인 취향 필름 · 추천 영화입니다.

**탭 화면에서 전체화면 화면으로 들어갔다 돌아오는 것은 사용자가 직접 눌러 확인했습니다**
(2026-09-22). 넓은 창에서 3.1 취향 필름 → 2.4 영화 상세 → 뒤로 가기를 거치며 폭 · 스크롤 ·
뒤로 가기가 끊기지 않았습니다. 캡처 도구가 클릭을 넣을 수 없어 남겨 두었던 완료 조건입니다.

서는지, 로그인하지 않았으면 셸을 세우지 않는지를 고정합니다.

## 6. 확인하지 못한 것과 남은 위험

- **폭이 정확히 1024px인 화면은 캡처로 깨끗하게 확인하지 못했습니다.** 쓰고 있는 캡처 도구가
  창 크기를 잡는 동안 폭이 1024px 경계를 지나가고, 그 순간 셸이 갈리면서 화면이 다시 그려져
  데이터를 받는 중인 상태로 찍힙니다. 1060px 이상에서는 나타나지 않습니다.

  같은 증상이 이 업무에서 건드리지 않은 3.1 취향 필름 · 2.2 추천 영화에서도 나옵니다. 두
  화면은 -782의 `AppLayout`을 그대로 쓰므로 이 변경이 만든 것이 아닙니다.

  **갈림 자체가 데이터를 잃게 하는지는 시험으로 확인했고, 잃지 않습니다.** 폭을 바꾸면 듣고
  있던 쪽에 알리도록 `test/viewport`를 고쳐 그 순간을 만들고, 받는 중에 갈려도 다시 받아
  내용이 나오는지와 다 받은 뒤에 갈려도 내용이 남는지를 `FullScreenLayout.test.tsx`에
  고정했습니다. 따라서 남은 것은 캡처 도구 쪽 사정으로 보이며, **실제 브라우저에서 창을
  1024px 경계 너머로 끌어 2.4 영화 상세가 비지 않는지 한 번 눈으로 보는 것**만 남았습니다.
- **전체 실행의 간헐 실패가 저장소에 남아 있습니다.** 확인하는 동안 전체 실행이 드물게
  깨졌고, 깨진 것은 이 업무가 더한 시험이 아니라 7.2 프로필 편집과 3.1 필름의 기존 시험
  둘이었습니다. 같은 조건을 만들어 `origin/develop`을 별도 worktree에서 돌려 보니 **손대지
  않은 `develop`도 CPU를 점유한 상태에서 같은 시험 둘이 깨집니다**(3회 중 2회). 이 변경이
  만든 것이 아니라, -789가 남긴 위험이 그대로 있는 것입니다.

  | 대상 | 결과 |
  | --- | --- |
  | `develop`, 부하 없음 × 6 | 모두 통과 |
  | `develop`, CPU 12개 점유 × 3 | 2회 실패 (프로필 편집 미리보기 · 필름 자동 이어 받기) |
  | 이 브랜치, 부하 없음 × 6 | 모두 통과 |

  `RouterProvider`에 `useTransitions={false}`를 걸어 보았으나 같은 시험이 그대로 깨져
  되돌렸습니다. 원인이 -789의 두 유형과 다르다는 뜻이므로, 후속 업무
  [S15P21E106-797](https://ssafy.atlassian.net/browse/S15P21E106-797)에서 다시 봅니다.
- **키보드로 셸을 지나는 것은 확인하지 못했습니다.** 캡처 도구가 주소로 화면을 열 수만 있고
  `Tab` 이동을 넣을 수 없습니다. 좌측 내비가 생기면서 본문까지의 거리가 늘어난 것은 -782가
  건너뛰기 단추로 다뤘고 그 단추가 서는 것은 시험으로 고정했지만, 실제로 눌러 본 것은
  아닙니다.
- **실제 데이터가 얇습니다.** 목업 계정이라 알림 목록은 오류 상태로, 취향 필름은 빈 상태로
  그려졌습니다. 배치는 확인했지만 목록이 길 때의 스크롤은 보지 못했습니다.
