# S15P21E106-952 프로필 공개 필름 관리 검증

- 검증일: 2026-09-27
- 범위: 프로필 편집의 최근 공개 필름 3편 미리보기와 관리 창. API·공개 선택 저장 방식은 변경하지 않음.

## 자동 검증

`npm run test:run -- src/pages/my/ProfileEditPage/ProfileEditPage.test.tsx src/pages/my/PublicProfilePage/PublicProfilePage.test.tsx`

46개 테스트 통과. 대량 목록에서 최근 3편 표시, 12편 단위 페이지 이동, 페이지·검색·필터 간 선택 유지, 저장 및 미리보기 반영, 취소, 빈 목록·빈 검색 결과, 공개 중 마지막 페이지의 전체 해제, 저장 실패 후 초안 유지 및 재시도, 미저장 변경 상태에서 뒤로 가기와 계속 편집을 확인했다.

`npm run lint`, `npm run format:check`, `npm run build` 통과. 빌드의 기존 PostCSS `from` 및 500kB 초과 청크 경고는 남아 있다.

## 실제 브라우저 검증

로컬 Vite와 Chrome headless에서 실제 ProfileEditPage를 렌더링하고 API 응답만 100편의 검증 데이터로 대체했다. React StrictMode를 사용했다. 테스트용 진입 파일은 확인 후 삭제했다.

390×844, 1280×900, 844×390에서 다음을 확인했다.

1. 관리 창이 열리면 제목 검색에 초점이 놓인다.
2. 저장·취소와 페이지 이동은 목록 스크롤 밖에 있고 화면 안에 유지된다.
3. 두 번째 페이지에서 제목 검색 후 공개를 해제하고 공개 중 필터를 적용하면 빈 결과가 표시된다.
4. 검색 입력에서 Enter를 눌러도 저장되지 않는다.
5. Tab 이동은 네이티브 모달 안에 머물며 Escape로 닫으면 관리 버튼에 초점이 돌아온다.
6. 스크린샷을 검토해 배경 비침을 수정했고, 가로 화면에서는 포스터 6열 배치를 확인했다.

## 한계와 공통 변경

- 배포 서버와 실제 계정·iOS Safari에서는 검증하지 않았다.
- 기존 공개 필름 선택 저장은 세션 메모리 방식이다. 새로고침 후 유지나 서버 공개 프로필과의 개별 선택 동기화는 이번 작업에 포함하지 않았다.
- 공용 ProfileLayout에서는 편집 모드만 최대 3편으로 제한하고 관리 진입 버튼을 변경했다. 공개·미리보기 모드의 표시 계약은 유지한다.
- 최신 origin/develop(f8b61f96)을 확인했으며 변경 대상 파일의 새 원격 변경은 없었다. GitLab의 열린 MR은 직접 확인하지 못했다.
- Jira S15P21E106-953의 공개 한줄평 작업은 같은 ProfileLayout을 수정할 수 있으므로 병합 시 해당 구역과의 중복을 확인해야 한다.
