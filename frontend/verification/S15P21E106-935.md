# S15P21E106-935: 리포트 PNG 캡처의 TMDB CORS 실패 수정

## 범위와 원인

서비스 개발자 도구 로그에서 `image.tmdb.org/t/p/w1280/...jpg` 및
`/t/p/original/...jpg`의 CORS 실패를 확인했다. 화면의 img 표시와 달리 캡처용 fetch는
사진 데이터를 읽어야 하므로 실패했고, API-061 PNG 업로드 전에 처리가 중단됐다.

캡처 시 TMDB 사진만 같은 출처 `/tmdb-images/{size}/{file}`로 읽는다.
Nginx는 HTTPS TMDB 호스트를 고정하고 이미지 파일 경로와 GET/HEAD만 허용한다.
요청 헤더·본문을 외부로 전달하지 않고 Host만 설정하며, Set-Cookie 응답도 제거한다.
외부 TLS 인증서를 검증하고 기존 Docker DNS resolver를 사용한다.
Vite에도 같은 캡처 경로와 인증정보 제거를 적용한다.

## 로컬 검증

- 캡처 유틸·리포트 흐름 테스트: 2개 파일, 54개 테스트 통과.
- TypeScript 검사 및 Vite 배포 빌드 통과.
- 변경 TypeScript 파일의 ESLint·Prettier 검사 통과.
- 빌드에서 PostCSS from 옵션 및 기존 번들 크기 경고가 있었지만 실패하지 않았다.
- 전체 Nginx 설정은 로컬 nginx:alpine에서 테스트 인증서와 backend/frontend 주소를
  대체하여 `nginx -t` 성공. 서비스 인증서·서버 DNS 검증을 대신하지 않는다.

- 로컬 Docker 사용자 네트워크에서 실제 TMDB 사진 4개 모두 200 image/jpeg 확인.
- 유효하지 않은 경로 3개는 404, 사진 POST는 403 확인.
- 최초 기본 bridge 네트워크 시험은 Docker 내부 DNS 조건이 달라 실패했으며,
  Compose와 같은 사용자 네트워크로 수정 후 위 통합 검증이 통과했다.
- 로컬 테스트 인증서에서만 curl -k를 사용했다. 실제 TMDB upstream TLS 검증은 활성화했다.

## 서비스 적용 순서

승인된 변경을 서버 checkout에 반영한 뒤 기존 infra/.env를 사용한다.
Nginx 설정은 bind mount이므로 아래 기존 배포 절차로 재생성한 뒤 프론트를 배포한다.

```bash
export BACKEND_IMAGE="$(docker inspect feelm-backend --format '{{.Config.Image}}')"
docker compose --env-file infra/.env -f infra/compose/service.yml config --quiet
docker compose --env-file infra/.env -f infra/compose/service.yml run --rm --no-deps nginx nginx -t
docker compose --env-file infra/.env -f infra/compose/service.yml up -d --no-deps --force-recreate nginx
curl -I https://j15e106.p.ssafy.io/tmdb-images/w1280/tiN6K0LnkK6jG20M39H3AfnXIgQ.jpg
```

정상 응답은 200 및 Content-Type image/jpeg다. 502면 서버의 TMDB DNS·외부 HTTPS 연결과
CA 인증서, 404면 설정 적용과 이미지 경로를 확인한다. 프록시 정상 확인 후 프론트
이미지를 기존 배포 절차로 반영한다.

## 배포 후 수동 확인 (미수행)

1. 문제를 보인 모바일 네이버 앱 브라우저에서 새 프론트가 로드됐는지 확인한다.
2. 리포트 저장을 눌러 같은 출처 /tmdb-images/ 사진 GET의 200과 CORS 오류 부재를 확인한다.
3. API-061 POST와 서명 URL 다운로드 GET이 성공하는지 확인한다. 서명은 로그 공유 시 가린다.
4. 내려받은 PNG가 1080×3268이며 감독·배우·캐릭터 사진이 모두 포함되는지 확인한다.
5. 공유하기의 앞면·뒷면 이미지도 확인한다. 다운로드·공유 지원은 기기 브라우저에 따라 확인한다.

코드 수정과 로컬 검증 완료는 서비스 배포 및 실제 모바일 확인 완료를 뜻하지 않는다.
