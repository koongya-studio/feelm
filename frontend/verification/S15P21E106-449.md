# 1.1 취향 초기 설정 카드 노출 확인 기록

2026-09-15, 1.1 화면에 영화 카드가 하나도 나오지 않는 증상(S15P21E106-449)을 요청 ·
응답 · 배치 순서로 확인한 결과입니다.

**결론부터 — 화면의 결함이 아닙니다.** 요청은 서버에 닿고 응답도 `200`이지만 `items`가
빈 배열입니다. 배포 DB의 어떤 영화에도 대표 맛이 배정돼 있지 않아 카드가 만들어지지
않습니다(API-023 처리 규칙 · [ADR-0015](../../docs/adr/0015-kmeans-ctfidf-taste-clusters.md)).

온보딩·OTT 연동 자체의 계약 확인은
[S15P21E106-379.md](./S15P21E106-379.md)에 있습니다. 그때는 로컬 DB에 영화가 0행이라
`items`가 빈 것을 결함이 아니라고 적고 넘어갔는데, **적재된 배포 환경에서도 같은 결과**인
것이 이번에 확인된 부분입니다.

## 1. 확인한 순서

Jira가 요구한 세 단계 그대로입니다.

| 단계 | 결과 |
| --- | --- |
| 요청이 서버에 닿는가 | 닿습니다. `GET /api/v1/onboarding/cards?size=10` → `200` |
| 응답에 카드가 담기는가 | 담기지 않습니다. `items` 길이 **0** |
| 화면이 받은 카드를 배치하는가 | 배치합니다. 10장을 주면 10장이 원 주변에 겹치지 않고 섭니다 |

## 2. 배포 환경 응답

대상은 `https://j15e106.p.ssafy.io`입니다. 이 확인 시점의 배포본은 `main`이고, `develop`과의
차이 10커밋 중 온보딩 카드 경로(`frontend/src/pages/onboarding` ·
`frontend/src/api/onboarding.ts` · `backend/.../domain/onboarding`)는 **변경이 없습니다.**
배포본이 낡아서 생긴 차이가 아닙니다.

실제 계정으로 로그인(API-004 `200`)한 뒤 받은 Access Token으로 호출했습니다.

| 요청 | 응답 |
| --- | --- |
| `GET /onboarding/cards?size=10` | `200` `{"items":[]}` — **items 0개** |
| `GET /onboarding/cards` (기본 20) | `200` `{"items":[]}` — **items 0개** |
| `GET /onboarding/cards?size=40` | `200` `{"items":[]}` — **items 0개** |
| `GET /onboarding/cards?size=41` | `400 VALIDATION_FAILED` (`size`는 40 이하) |
| `GET /users/me` | `200` `onboardingCompleted: false` |

`size=41`이 계약대로 거절되는 것으로 보아 엔드포인트는 정상 동작합니다. 고를 영화가
없을 뿐입니다.

브라우저에서도 같았습니다. 배포 앱에 로그인하면 `/app/onboarding/taste`로 가고,
개발자도구 네트워크에 `GET /api/v1/onboarding/cards?size=10` `200`이 한 건 남으며 화면에는
점선 원과 가운데 표식만 남습니다. 증상과 응답이 일치합니다.

## 3. 카드가 0장인 이유

`OnboardingCardRepository`의 후보 질의는 `movies.representative_flavor_id = f.id`로
`popcorn_flavors`와 조인합니다. 대표 맛이 비어 있는 영화는 조인에서 빠지므로 카드가
되지 않습니다. 응답의 `flavorCode`를 비워 둘 수 없기 때문입니다.

공개 API로 확인한 배포 DB 상태입니다.

| 확인 | 결과 |
| --- | --- |
| `GET /movies/{id}` 15건 표본 (1 · 5 · 10 · 50 · 100 · 250 · 500 · 1000 · 2000 · 5000 · 10000 · 20000 · 50000) | **모두 `flavorCode: null`** |
| `GET /otts` | `200`, 5종 정상 |

영화 자체는 적재돼 있고 OTT도 정상입니다. **대표 맛만 비어 있습니다.**

저장소에서 `movies.representative_flavor_id`에 값을 넣는 곳은 없습니다. `V202609021030`이
열과 인덱스를 만들 뿐이고, 값은 ADR-0015의 파이프라인이 씁니다.
`pipeline/spark/batch/prepare/movie_metadata.py`도 대표 맛을 입력으로 받아 넘기기만 하며,
입력이 없으면 `representative_flavor_code`를 `null`로 채웁니다. 즉 **`develop`을 배포해도
이 값은 채워지지 않습니다.** 코드가 아니라 데이터의 문제이며, 별도 업무로 분리했습니다.

## 4. 화면이 카드를 배치하는지

배포 백엔드는 `localhost` 출처를 CORS로 막습니다(`403 Invalid CORS request`). 배포와 같은
출처로만 부르도록 되어 있어 정상 동작이며, 그래서 개발 서버로 배포 백엔드를 붙여 볼 수는
없습니다. 계약과 같은 모양의 응답을 돌려주는 임시 스텁을 `VITE_API_PROXY_TARGET`으로 붙여
화면만 확인했습니다. 스텁은 확인용이라 저장소에 남기지 않았습니다.

| 응답 | 화면 |
| --- | --- |
| `items` 10장 | 카드 10장이 원 안팎에 겹치지 않고 배치됨 |
| `items` 0장 | `지금은 보여드릴 영화가 없어요` + `다시 시도` + `차차 찾아갈래요 (건너뛰기)` |
| 응답 전(지연 1.5초) | `영화 카드를 준비하고 있어요` |
| 빈 목록에서 건너뛰기 | API-024 `skipped: true` 제출 후 1.2로 이동 |

포스터는 `posterUrl: null`로 두고 확인해 자리표시자가 섰습니다. 실제 포스터가 붙은 모습은
보지 못했습니다.

## 5. 화면이 갖게 된 상태

카드를 받기 전과 빈 목록을 가릅니다. 둘 다 예전에는 `cards`가 빈 배열이라 같은 화면이었고,
그 화면이 **점선 원만 남은 배치 영역**이었습니다. 사용자에게는 `아직 안 왔다`가 아니라
`고장났다`로 읽힙니다.

- 받기 전 — `영화 카드를 준비하고 있어요`
- 빈 목록 — `지금은 보여드릴 영화가 없어요` · `다시 시도` · `차차 찾아갈래요 (건너뛰기)`
- 실패 — `영화 카드를 불러오지 못했어요` · `다시 시도` (이전과 같음)

빈 목록에 건너뛰기를 함께 둔 이유는 **고를 카드가 없어도 온보딩을 끝낼 수 있어야 하기**
때문입니다. 지금 배포 환경이 정확히 그 상태입니다.

`StatusView`는 `로딩 상태는 만들지 않는다`(팀 결정 2026-09-08)를 따르고 있고 다른 화면은
데이터를 받기 전에 아무것도 그리지 않아도 됩니다. 이 화면만 예외인 이유는 빈 화면이
아니라 **빈 공간**이 남기 때문입니다.

`⊖`로 사용자가 카드를 전부 지운 경우는 빈 목록으로 보지 않습니다. 직접 한 일이고 하단에
건너뛰기가 그대로 있습니다.

## 6. 확인하지 못한 것

| 항목 | 이유 |
| --- | --- |
| 실제 영화 카드가 배포 화면에 뜨는 모습 | 대표 맛이 배정된 영화가 없습니다. 배정 후 다시 봐야 합니다 |
| 실제 포스터가 붙은 카드의 배치 | 스텁이 `posterUrl: null`이라 자리표시자만 봤습니다 |
| 좁은 화면(모바일 폭)에서의 카드 겹침 | 데스크톱 브라우저 폭에서만 확인했습니다 |

자동으로 고정한 것은 `src/pages/onboarding/OnboardingFlow.test.tsx`에 있습니다. 카드가
실제로 그려지는지, 받기 전과 빈 목록이 각각 무엇을 세우는지, 빈 목록에서 건너뛰기가
제출까지 가는지를 봅니다.
