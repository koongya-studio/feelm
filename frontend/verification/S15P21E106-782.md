# PC 공통 데스크톱 셸 · 반응형 확인 기록

2026-09-21, 데스크톱 셸을 붙인 뒤 폭 네 단계에서 화면이 깨지지 않는지, 1024px 미만이
그대로인지, 키보드로 셸을 지날 수 있는지를 실제 브라우저에서 확인한 기록입니다. 확인은
로컬 개발 서버(5173)에서 사용자가 직접 창 폭을 바꿔 가며 했습니다.

**결론부터**: 네 폭 모두 가로 넘침과 콘텐츠 겹침이 없고, 1024px 미만은 기존 모바일 화면과
같습니다. 확인 과정에서 셸이 만든 결함 셋을 발견해 고쳤습니다 — 상단 바 검색이 검색 화면
안에서는 동작하지 않던 것, 아직 내용이 없는 우측 보조 패널이 빈 단으로 남던 것, 보낸
검색어가 상단 바에 그대로 남아 같은 글자가 두 번 보이던 것입니다.

## 1. 폭 단계별로 확인한 것

| 폭 | 셸 | 확인 결과 |
| --- | --- | --- |
| 412px | 하단 3탭 · 412px 콘텐츠 | 하단 내비 · 워드마크 헤더 · 스크롤이 **기존과 같음** |
| 768px | 하단 3탭 · 412px 콘텐츠 가운데 정렬 | 같음. 전환 기준이 1024px이라 아직 모바일 셸 |
| 1280px | 좌측 내비 · 상단 바 · 중앙 + 우측 자리 | 좌측 내비 5항목 표시, 우측 빈 단 없음 |
| 1440px | 위와 같음 | 같음 |

네 폭 모두에서 **가로 스크롤바가 생기지 않고 글자가 겹치는 자리도 없습니다.**

좌측 내비의 선택 표시도 함께 봤습니다. `취향 필름` · `추천 영화` · `파티팝콘` · `검색` ·
`MY` 다섯 중 지금 있는 화면 하나만 표시되고, `/film/popcorn` 같은 하위 경로에서는 상위
항목(`취향 필름`)이 표시된 채로 남습니다. **`검색`과 `추천 영화`가 `취향 필름`에 묻히지
않는 것**이 하단 3탭과 다른 점이며, 그대로 동작합니다.

좌측 띠와 상단 바는 본문을 스크롤해도 따라 움직이지 않습니다.

## 2. 바텀시트 · 확인 창

1280px에서 4.3 검색 필터 시트를 열어 확인했습니다. **화면 전체가 어두워지고 시트가
가운데에 뜹니다.** 고치기 전에는 화면 한가운데 412px 폭의 띠만 어두워지고 그 바깥은 밝은
채로 남았습니다.

전환은 시트마다 걸지 않고 `styles/tokens.css`의 덮개 토큰 넷(`--overlay-max-width` ·
`--overlay-place` · `--overlay-sheet-max-width` · `--overlay-sheet-radius`)을 1024px에서
한 번에 바꾸는 방식입니다. 지금 이 토큰을 읽는 것은 확인 창(`ConfirmDialog`)과 시트 셋
(`CommentManageSheet` · `SearchFilterSheet` · `ReportShareSheet`)입니다.

## 3. 키보드 포커스

좌측 내비가 생기면서 **본문에 닿기까지 `Tab`이 열한 번**이 됐습니다. 로고 · 내비 다섯 ·
설정 · 계정 행 · 상단 검색창 · 알림 · 프로필 순이고, 화면을 옮길 때마다 처음부터 다시
지나야 합니다. 모바일에서는 헤더 아이콘 둘만 지나면 본문이었습니다.

그래서 셸 맨 앞에 `본문으로 건너뛰기` 단추를 두었습니다. 평소에는 화면 위쪽 바깥에 숨어
있고 초점이 오면 왼쪽 위로 내려옵니다.

**확인한 것과 확인하지 못한 것이 갈립니다.**

- 단추가 화면 왼쪽 위에 제 모양으로 나타나는 것은 확인했습니다. 다만 초점이 아니라
  개발자 도구에서 `transform`을 직접 되돌려 띄운 상태로 봤습니다
- 단추가 DOM 순서에서 어떤 링크보다 앞이라는 것과, 눌렀을 때 본문에 초점이 가는 것은
  자동 테스트가 고정합니다(`AppLayout.test.tsx`)
- **실제로 `Tab`을 눌러 단추가 내려오는 것은 확인하지 못했습니다.** 개발자 도구가 초점을
  가져가는 환경이라 재현이 되지 않았습니다

처음에는 `:focus-visible`로 띄웠는데 브라우저가 키보드 조작이라고 판단해야 켜지고 그
판단이 상황마다 달라 나타나지 않는 일이 있었습니다. 이 단추는 화면 밖에 있어 마우스로
누를 수 없으므로 초점이 왔다는 것 자체가 키보드로 왔다는 뜻이고, 그래서 `:focus`로
바꿨습니다.

## 4. 확인하면서 고친 것

| 증상 | 원인 | 고친 방법 |
| --- | --- | --- |
| 검색 화면에 **이미 있을 때** 상단 바로 검색어를 보내면 주소만 바뀌고 결과는 그대로 | 4.1은 시작 조건을 처음 한 번만 읽는데, 같은 화면이라 다시 그려지지 않음 | 바깥에서 온 이동(`push`)이면 그 조건으로 다시 검색. 4.1이 스스로 적는 주소는 늘 `replace`라 섞이지 않음 |
| 1280px 이상에서 화면마다 **오른쪽에 빈 단**이 남음 | 페이지가 아직 보조 패널을 채우지 않는데 자리는 폭을 지킴 | `.aside:empty`로 접음. 페이지가 내용을 보내면 저절로 펴짐 |
| 검색어를 보낸 뒤 **상단 바와 화면 입력에 같은 글자가 두 번** 보임 | 상단 바는 셸에 있어 화면이 바뀌어도 입력이 살아 있음 | 보내고 나면 상단 바 입력을 비움. 시안의 상단 바도 비어 있음 |

첫 줄을 고치면서 한 번 잘못 짚었습니다. "내가 마지막으로 적은 주소"를 기억해 두고
견주는 방식이었는데, 검색어를 연달아 고칠 때(두 글자 → 한 글자) 기억은 마지막 것만 남고
비교는 그 사이 주소를 보게 되어 **지운 검색어로 다시 검색**됐습니다. 기존 테스트 둘이
그것을 잡았고, 주소 문자열 대신 이동 종류로 가르도록 바꿨습니다.

두 번과 단독 실행 세 번에서 다시 나오지 않았습니다. 같은 성격으로 보이지만 변경을 걷어낸
상태에서 따로 확인하지는 않았습니다.

## 6. 확인하지 못한 것

- **배포 환경에서는 확인하지 않았습니다.** 로컬 개발 서버로만 봤습니다.
- **화면 읽기 도구로 확인하지 않았습니다.** 좌측 내비의 `주요 화면` 이름과 보조 패널의
  `보조 정보` 이름이 실제로 어떻게 읽히는지는 확인 대상 밖이었습니다.
- **1024px 미만의 태블릿 실기기로 확인하지 않았습니다.** 768px은 데스크톱 브라우저의 창
  폭을 줄여 확인한 것입니다.
- **5개 화면의 내용은 이 업무의 대상이 아닙니다.** 1024px 이상에서 중앙 본문은 아직
  모바일 구성이 넓은 단에 그대로 놓인 모양이고, 우측 보조 패널은 비어 있어 접혀 있습니다.
  화면별 시안 적용은 S15P21E106-783 취향 필름 · 추천 영화, -784 검색, -785 파티팝콘,
  -786 MY가 맡습니다.
- **전체화면 레이아웃은 그대로 두었습니다.** 알림 목록 · 영화 상세 · 파티 흐름처럼
  `FullScreenLayout`을 쓰는 화면은 1024px 이상에서도 412px 폭으로 화면 가운데 놓입니다.
  시안 5종이 모두 탭 화면이라 이번 범위에 넣지 않았습니다. 데스크톱에서 이 화면들을
  어떻게 둘지는 후속 업무가 필요합니다.
