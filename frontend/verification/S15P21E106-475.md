# 영화 상세 연동 검증 기록

2026-09-16, 로컬 백엔드를 띄우고 실제 응답으로 화면을 확인한 결과입니다. 대상은
2.4 영화 상세(S15P21E106-475, API-030)입니다.

**이 기록은 로컬 확인 결과이며 배포 환경 검증 완료를 뜻하지 않습니다.** 확인하지 못한
것은 5장에 있습니다.

취향 필름·팝콘은 [S15P21E106-392.md](./S15P21E106-392.md), 파티는
[S15P21E106-393.md](./S15P21E106-393.md)에 있습니다.

## 1. 왜 남기는가

이 화면이 실제로 만나는 응답은 계약 예시와 모양이 다릅니다. 수집한 영화에는 **줄거리 ·
개봉일 · 상영 시간 · 대표 맛이 비어 있는 것**이 있고, 추천 이유는 추천을 만든 시점의
JSON 스냅샷이라 `summary`가 없을 수도 있습니다. 목업에는 이 값들이 항상 있었습니다.

또 하나는 **화면 사이의 이음매**입니다. 2.4만 실제 API로 바뀌고 들어오는 쪽(2.2 추천 ·
7.5 추천 기록 · 4.x 검색)과 나가는 쪽(2.4-A · 2.5)은 목업이라, 목업 `movieId`로 들어오면
상세가 `404`가 됩니다. 자동 테스트는 스텁을 세워 이 자리를 지나가므로 여기 적습니다.

## 2. 환경

| 항목 | 값 |
| --- | --- |
| 백엔드 | `local` 프로파일, `AUTH_MOCK_ENABLED=true`(고정 사용자 1), 포트 8081 |
| DB · Redis | `infra/compose`의 로컬 PostgreSQL · Redis |
| 프론트 | Vite dev 서버 5175 (`/api` → `localhost:8081`) |
| 데이터 | 비어 있는 DB에 확인용 행을 직접 넣고 확인한 뒤 모두 지웠습니다 |

넣은 것은 영화 2편(값이 모두 있는 영화 · 선택 필드가 모두 빈 영화), 장르 2 · 국가 2 ·
인물 3 · OTT 연결 2(넷플릭스 · 티빙), 사용자 1의 티빙 구독과 평가 1건, 추천 항목 2건
(이유에 `summary`가 있는 것과 없는 것)입니다. 영화 수집 파이프라인과 평가 API가 아직
없어 화면으로는 만들 수 없는 데이터입니다.

## 3. 확인한 것

### 3.1 값이 모두 있는 영화

| 영역 | 확인한 것 |
| --- | --- |
| 헤더 | `확인용 영화 하나`, `2013 · 케이퍼 · 드라마 · 115분`, `★ 4.3` · `1280명` |
| 볼 수 있는 곳 | `티빙`(구독 중) → `넷플릭스` 순. **서버가 정렬해 준 순서 그대로**입니다 |
| 주 동작 | `티빙에서 바로 보기` — 구독 중인 OTT가 맨 앞이라 알약도 그 OTT를 가리킵니다 |
| 시놉시스 | 응답의 줄거리 |
| 내 감상평 | 서버의 `myRating.comment`와 `한 줄 감상 고치기` |
| 출연 · 제작 | 감독 1 · 배우 2, 배역명이 없는 배우는 이름만 |

- `recommendationItemId`를 붙여 들어가면 `추천 이유`가 그 문구로 나옵니다
- 다른 영화의 추천 항목을 붙이면 계약대로 `recommendation: null`과 `200`이라 추천 이유
  영역만 빠지고 나머지는 그대로 나옵니다

### 3.2 선택 필드가 모두 비어 있는 영화

| 응답 | 화면 |
| --- | --- |
| `releaseDate`·`runtimeMinutes` `null`, `genres: []` | 제목 아래 메타 줄을 그리지 않습니다 |
| `synopsis: null` | `줄거리가 아직 등록되지 않았어요` |
| `ottProviders: []` | `볼 수 있는 곳`을 그리지 않고 알약이 `내 별점 남기기`로 바뀝니다 |
| `directors`·`cast` 빈 배열 | `출연 · 제작`을 그리지 않습니다 |
| `averageRating: 0`, `ratingCount: 0` | `★ 0.0` · `0명` |
| 추천 이유 스냅샷에 `summary` 없음 | `추천 이유` 영역을 그리지 않습니다 |

### 3.3 실패

| 경우 | 응답 | 화면 |
| --- | --- | --- |
| 없는 영화 | `404 RESOURCE_NOT_FOUND` | `영화를 찾을 수 없어요` · `홈으로`. 재시도를 주지 않습니다 |
| 잘못된 ID(`/movies/NaN`) | `400 VALIDATION_FAILED` | `영화 정보를 불러오지 못했어요` · `다시 시도` |
| 백엔드 정지 | 프록시 오류 | 같은 오류 상태이며 백엔드를 살리고 `다시 시도`로 복구됩니다 |

### 3.4 이어지는 화면

- 2.5 영화 평가도 같은 API-030을 읽습니다. 실제 영화로 들어가면 별점 · 한줄평이 서버
  값으로 채워지고 수정 모드로 열립니다
- 대표 맛이 없는 영화를 평가하면 2.7의 맛 이름이 빈칸입니다. 평가 저장이 아직 목업이고
  목업 맛 기준정보에는 실제 맛 코드가 없기 때문입니다(4장 3번)

## 4. 계약과 다른 것 · 알아 둘 것

1. **추천 이유에 `summary`가 없을 수 있습니다.** `reason`은 추천 생성 시점의 JSON
   스냅샷을 그대로 돌려주므로(API-030 처리 규칙) 서버가 모양을 맞춰 주지 않습니다.
   화면은 문구가 있을 때만 추천 이유를 그립니다
2. **선택 필드 `null`이 화면에 그대로 도착합니다.** 목업에는 없던 경우라 타입을
   계약대로 `null` 가능으로 고쳤습니다(`types/movie.ts`)
3. **평가는 아직 목업입니다.** 2.5에서 남긴 평가는 세션 저장소에만 남고 2.4는 서버가
   주는 `myRating`만 보여줍니다. 두 쪽이 같은 값을 보려면 평가 API 연동
   (S15P21E106-160 · -213 · -214)이 필요합니다

## 5. 확인하지 못한 것

- **배포 환경.** 로컬에서만 확인했습니다. 배포 DB의 실제 수집 영화로는 보지 못했습니다
- **실제 포스터 · 배경 이미지.** 확인용 행에 이미지 URL을 넣지 않아 자리표시자 포스터만
  확인했습니다
- **비회원 조회.** 로컬은 mock 인증을 켜 두어 항상 사용자 1입니다. 토큰 없는 호출은
  `api/movies.test.ts`가 고정합니다
- **파티 추천 이유의 열람 권한.** 개인 추천만 확인했습니다

## 6. 목업으로 남는 것

이번 연동 뒤에도 2.4 안에서 목업으로 남는 것과 이유입니다(업무 완료 조건).

| 영역 | 왜 목업인가 |
| --- | --- |
| 유사한 영화 (API-031) | 백엔드 구현이 S15P21E106-216으로 진행 중입니다 |
| 다른 사용자 한줄평 (API-032) | 목록이 S15P21E106-161로 예정만 되어 있고, 평가 API도 아직 없어 한줄평 자체가 만들어지지 않습니다 |
| OTT 링크 클릭 · 감상 상태 (API-033 · API-034) | 별도 업무 S15P21E106-477에서 연동합니다 |
| 내 별점 · 감상평 저장 (API-036 · API-037) | 평가 API가 아직 없습니다 |

**실제 영화에서 유사 영화와 한줄평은 빈 목록입니다.** 목업이 목업 `movieId`로만 값을
들고 있기 때문이며, 화면은 `비슷한 영화를 아직 찾지 못했어요` · `아직 공개된 한줄평이
없어요`를 보여줍니다.

## 7. 지금의 한계 — 목업 화면에서 들어오면 404

2.2 오늘의 추천 · 7.5 추천 기록 · 4.x 검색 · 7.6 · 7.7은 아직 목업이라 카드의 `movieId`가
실제 DB에 없습니다. 그 카드를 누르면 2.4는 `영화를 찾을 수 없어요`, 2.5는 오류 상태가
됩니다. 각 화면이 실제 API로 바뀌면 함께 풀립니다(검색 -476, 추천 기록 -478, 평가 계열
-160 · -213 · -214).

실제 영화로 들어가려면 지금은 주소로 직접 엽니다(`/app/movies/{실제 movieId}`).
