# 계정 부가 기능 연동 검증 기록

2026-09-15, 실제 백엔드를 띄우고 계약 응답을 직접 확인한 결과입니다. 대상은 비밀번호
재설정·변경과 닉네임 사용 가능 확인(S15P21E106-391, API-010 · API-011 · API-012 ·
API-016)입니다.

**이 기록은 로컬 확인 결과이며 배포 환경 검증 완료를 뜻하지 않습니다.** 확인하지 못한
것은 5장에 있습니다.

인증 세션과 가입 흐름은 [S15P21E106-376.md](./S15P21E106-376.md)에 있습니다.

## 1. 왜 남기는가

이 연동에서 화면이 의존하는 것은 **오류 코드와 부수 효과**입니다. 세 API 모두 성공
응답에 본문이 없어(`202` · `204`) 자동 테스트가 고정할 수 있는 것은 "무엇을 보냈는가"
까지입니다. 정작 화면 동작을 가르는 것은 서버가 어떤 코드로 거절하는지와, 성공 뒤에
세션이 어떻게 되는지입니다. 둘 다 응답 본문에 드러나지 않습니다.

메일 링크 주소도 그렇습니다. 0.7-A는 **백엔드가 만든 주소로 열리는 화면**이라 프론트
라우트와 `feelm.mail.password-reset-url`이 어긋나면 링크를 눌러도 화면이 없습니다.
이것은 코드 어느 쪽을 봐도 알 수 없고 실제로 눌러 봐야 합니다.

## 2. 환경

| 항목 | 값 |
| --- | --- |
| 백엔드 | `local` 프로파일, `MAIL_MODE=log` |
| DB · Redis | `infra/compose`의 로컬 PostgreSQL · Redis |
| 프론트 | Vite dev 서버. **5173이 사용 중이라 5174**에서 띄웠습니다 |
| 계정 | 가입(API-001) 후 인증 메일 링크로 활성화한 확인용 계정 |

`[!]` **5174에서 띄운 첫 요청이 `403`이었습니다.** dev 프록시의 `changeOrigin`은 Host만
바꾸고 Origin은 그대로 보내므로, 백엔드의 `allowed-origins`(기본
`http://localhost:5173`)에 없는 출처가 됩니다. 화면 결함이 아니라 포트가 다른 탓이며,
`CORS_ALLOWED_ORIGINS`에 5174를 더해 확인을 이어갔습니다. 5173으로 띄우면 나지 않습니다.

## 3. 확인한 것

### API-010 비밀번호 재설정 요청

| 요청 | 응답 |
| --- | --- |
| 가입된 이메일 | `202` (본문 없음) |
| 가입되지 않은 이메일 | `202` (본문 없음). 메일 로그도 남지 않았습니다 |
| 같은 이메일 1분 내 재요청 | `429 RATE_LIMITED` |

- 계정 유무로 응답이 갈리지 않습니다. 화면이 `보냈어요`라고 단정하면 안 되는 근거이며,
  0.7은 `가입된 계정이 있다면 …`으로 적습니다
- `429`에 `Retry-After`가 없습니다(계약 처리 규칙과 같습니다). 화면도 남은 시간을 적지
  않고 `잠시 후 다시 시도해 주세요`로만 안내합니다

로그에 남은 링크는 다음과 같았습니다.

```text
http://localhost:5173/app/account/reset?token=GrG3F-N2HkwgkCy7M7sGYuAmf_XeSvorFDxXBXYXN_E
```

**`/app/account/reset`이 0.7-A의 경로와 같습니다**(`routes/paths.ts`의 `passwordReset`에
Vite base `/app/`이 붙은 값). 이 주소를 브라우저에서 그대로 열어 화면이 떴습니다.

### API-011 비밀번호 재설정

| 요청 | 응답 |
| --- | --- |
| 정상 | `204` |
| 없는 토큰 | `400 RESET_TOKEN_INVALID` |
| 방금 쓴 토큰 재사용 | `400 RESET_TOKEN_INVALID` |
| `newPassword: "abcdefgh"` | `400 VALIDATION_FAILED` |
| 재설정 뒤 옛 비밀번호로 로그인 | `401 INVALID_CREDENTIALS` |

- 위조와 재사용이 **같은 코드**입니다. 화면도 두 경우를 가르지 않고 `링크가 올바르지
  않아요` 하나로 안내합니다
- `[!]` `VALIDATION_FAILED`의 `message`는 `요청 값이 올바르지 않습니다.`뿐이고, 무엇이
  틀렸는지는 `details.errors[].reason`에 있습니다. 화면은 지금 `message`만 보여주므로
  서버만 아는 규칙에 걸리면 이유가 사라집니다. S15P21E106-448이 화면 규칙을 계약과
  같게 맞추면 이 경로에 거의 닿지 않지만, `details`를 읽는 것은 별도로 볼 문제입니다(5장)

### API-012 비밀번호 변경

| 요청 | 응답 |
| --- | --- |
| 정상 | `204` |
| 현재 비밀번호 불일치 | `401 INVALID_CREDENTIALS` |
| `newPassword: "abcdefgh"` | `400 VALIDATION_FAILED` |
| 변경 뒤 기존 쿠키로 `POST /auth/token/refresh` | `401 UNAUTHORIZED` |
| 변경 뒤 새 비밀번호로 로그인 | `200` |

- **성공하면 Refresh Token이 실제로 폐기됩니다.** 화면이 세션을 끊고 0.6으로 보내는
  근거입니다. 끊지 않으면 Access Token이 만료되는 순간(30분) 아무 화면에서나 갑자기
  로그아웃됩니다
- `[!]` **현재 비밀번호가 틀리면 요청이 두 번 나갑니다.** 브라우저 네트워크 기록에
  `PUT /users/me/password` `401`이 연달아 두 번 찍혔습니다. 공통 클라이언트가 401을
  토큰 만료로 보고 재발급 뒤 한 번 재시도하기 때문입니다(`api/client.ts`). 재시도해도
  같은 코드가 와서 화면이 받는 오류는 같고, 요청이 한 번 더 나가는 것만 다릅니다.
  계약이 `401`을 두 뜻으로 쓰는 탓이라 클라이언트를 고치지 않았습니다(5장)

### API-016 닉네임 사용 가능 확인

| 요청 | 응답 |
| --- | --- |
| 쓰지 않는 닉네임 | `{"nickname":"검증391","available":true,"reason":null}` |
| 이미 쓰는 닉네임 | `{"nickname":"검증391","available":false,"reason":"DUPLICATED"}` |
| `a` (한 글자) | `{"nickname":"a","available":false,"reason":"INVALID_FORMAT"}` |

- 형식 위반도 `400`이 아니라 `200`에 `available: false`입니다. 7.2가 `reason`으로
  중복과 형식을 갈라 안내하는 근거입니다
- 토큰 없이 부를 수 있습니다(공개). 0.4가 가입 전에 부르는 자리와 같습니다

## 4. 브라우저에서 밟은 경로

실제 Chrome에서 5174의 dev 서버로 확인했습니다.

| # | 한 일 | 결과 |

## 5. 확인하지 못한 것

| 항목 | 이유 |
| --- | --- |
| 7.2 닉네임 확인의 브라우저 동작 | 자동화 입력이 화면에 닿지 않아 중단했습니다. API-016 응답과 화면 테스트(`ProfileEditPage.test.tsx`)로만 고정돼 있습니다 |
| 메일 클라이언트에서 링크를 누른 경우 | `MAIL_MODE=log`라 실제 메일을 받지 않았습니다. 주소는 같지만 메일 앱이 링크를 감싸는 경우는 보지 못했습니다 |
| 만료된 재설정 토큰(`410 RESET_TOKEN_EXPIRED`) | 유효기간이 30분이라 기다리지 못했습니다. 화면 분기는 테스트로만 고정돼 있습니다 |
| 소셜 전용 계정의 `409 PASSWORD_NOT_SET` | 로컬에 소셜 제공자 자격증명이 없어 계정을 만들지 못했습니다 |
| `VALIDATION_FAILED`의 `details` 표시 | 화면은 `message`만 보여줍니다. 후속으로 볼 항목입니다 |
| API-012의 401 재시도 | 요청이 두 번 나가는 것을 확인만 했고 고치지 않았습니다. 후속으로 볼 항목입니다 |
| 배포 환경 | 로컬만 확인했습니다 |

`src/pages/auth/PasswordResetPage/PasswordResetPage.test.tsx` ·
