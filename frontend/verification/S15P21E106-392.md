# 취향 필름·팝콘 연동 검증 기록

2026-09-16, 로컬 백엔드를 띄우고 실제 응답으로 화면을 확인한 결과입니다. 대상은 취향
필름과 팝콘(S15P21E106-392, API-041 · API-042 · API-043 · API-044)입니다.

**이 기록은 로컬 확인 결과이며 배포 환경 검증 완료를 뜻하지 않습니다.** 확인하지 못한
것은 5장에 있습니다.

계정 부가 기능은 [S15P21E106-391.md](./S15P21E106-391.md), 인증 세션과 가입 흐름은
[S15P21E106-376.md](./S15P21E106-376.md)에 있습니다.

## 1. 왜 남기는가

이 연동에서 화면이 의존하는 것은 **비어 있거나 `null`인 값**입니다. 평가 API가 아직
없어 어떤 사용자도 프레임을 만들 수 없고, 팝콘 맛 기준정보도 아직 적재되지 않았습니다.
그래서 지금 배포에서 이 화면들이 실제로 그리는 것은 전부 빈 상태입니다.

자동 테스트는 "응답이 이렇게 오면 이렇게 그린다"까지만 고정합니다. 정작 확인이 필요한
것은 **서버가 실제로 무엇을 주는가**입니다. 대표 맛이 배정되지 않은 영화, 개봉일이 없는
영화, 기준정보가 없는 DB는 계약 예시에 나오지 않습니다.

## 2. 환경

| 항목 | 값 |
| --- | --- |
| 백엔드 | `local` 프로파일, `AUTH_MOCK_ENABLED=true`(고정 사용자 1) |
| DB · Redis | `infra/compose`의 로컬 PostgreSQL · Redis |
| 프론트 | Vite dev 서버 5173 (`/api` → `localhost:8080`) |
| 데이터 | 비어 있는 DB로 먼저 확인한 뒤, 확인용 행을 직접 넣고 다시 확인하고 지웠습니다 |

확인용으로 넣은 것은 팝콘 맛 2종, 영화 3편(대표 맛 있음 2 · 없음 1), 사용자 1의 평가와
프레임 3건입니다. 평가 API가 없어 화면으로는 프레임을 만들 수 없기 때문입니다.
확인 뒤 모두 삭제해 DB는 원래대로 비어 있습니다.

## 3. 확인한 것

### 3.1 데이터가 없을 때 (지금의 배포 상태)

| 호출 | 응답 |
| --- | --- |
| `GET /popcorn-flavors` | `200` `{"items":[]}` |
| `GET /users/me/frames` | `200` `{"totalCount":0,"items":[],"nextCursor":null,"hasNext":false}` |
| `GET /users/me/popcorn` | `200` `{"totalCount":0,"flavors":[]}` |
| `GET /frames/1` | `404 RESOURCE_NOT_FOUND` |

- 3.1은 `아직 감긴 프레임이 없어요`, 3.2는 `아직 담긴 팝콘이 없어요`를 보여주고 둘 다
  `추천 영화 보기`로 이어집니다. 실패 상태가 아니라 빈 상태입니다
- **API-041이 `flavors`를 빈 배열로 줍니다.** 계약은 8개 맛을 항상 준다고 정하지만
  기준정보가 없으면 줄 것이 없습니다. 화면을 여기에 맞추지 않았습니다(4장)
- 없는 프레임과 남의 프레임은 `404`이고 3.1-A는 `프레임을 불러오지 못했어요`로 갑니다

### 3.2 데이터가 있을 때

| 화면 | 확인한 것 |
| --- | --- |
| 3.1 취향 필름 | 프레임 3칸과 `3개의 프레임이 감겼어요`, 팝콘 범례가 응답의 `displayName`·`color`로 그려집니다 |
| 3.1-A 프레임 상세 | `2013 · 드라마 · 스릴러`, 별점 `4.5`, 공개 한줄평이 나옵니다 |
| 3.2 100알의 취향 | `2 · KERNELS`, `짭짤한 스릴 쪽으로 기울었어요`, 맛별 알 수와 `★ 4.5` |
| 7.1 MY 대시보드 | `3프레임`과 필름 카드의 프레임 썸네일, 팝콘 `2` |

- 평균 평점은 `4.5000000000000000`처럼 소수 자리가 길게 옵니다. 화면은 `toFixed(1)`로
  줄이므로 `★ 4.5`로 보입니다
- 별점은 `4.5` 같은 반 칸 값이 그대로 옵니다(API-036 반 칸 평가)

### 3.3 값이 비어 있는 항목

| 경우 | 응답 | 화면 |
| --- | --- | --- |
| 대표 맛이 배정되지 않은 영화 | `flavorCode: null` | 3.1 · 3.1-A 모두 맛을 쓰지 않아 영향 없음 |
| 개봉일이 없는 영화 | `releaseYear: null` | 3.1-A의 `연도 · 장르` 줄에서 연도를 뺍니다 |
| 장르가 없는 영화 | `genres: []` | 줄에 남는 것이 없으면 줄 자체를 그리지 않습니다 |
| 포스터가 없는 영화 | `posterUrl: null` | 기존 자리표시자 포스터가 나옵니다 |

## 4. 계약과 다른 것

1. **`flavorCode`가 `null`일 수 있습니다.** 백엔드가 `popcorn_flavors`를 LEFT JOIN하므로
   대표 맛이 배정되지 않은 영화의 프레임은 맛이 없습니다. 계약 예시(API-042 · API-043)에는
   `null`이 없습니다. 타입에만 반영하고 화면은 바꾸지 않았습니다
2. **팝콘 알 총수가 프레임 수보다 적을 수 있습니다.** 확인에서 프레임 3개에 팝콘 2알이
   나왔습니다. 대표 맛이 없는 영화의 평가는 어느 맛에도 담기지 않기 때문입니다. 평가
   하나가 프레임 1개와 팝콘 1알을 만든다는 FR-07 · FR-09와 어긋나 보이는 자리입니다
3. **검증 당시 팝콘 맛 기준정보가 없었습니다.** 이 후속 항목은 S15P21E106-466의
   ADR-0020·migration·A~H 기준정보로 해소됐으며, 배포 뒤 3.1 범례와 3.2를 재확인합니다

## 5. 확인하지 못한 것

- **프레임이 만들어지는 흐름.** 평가 API(API-035~039)가 없어 화면으로는 프레임을 만들 수
  없습니다. 확인용 행을 DB에 직접 넣어 대신했습니다
- **배포 환경.** 로컬에서만 확인했습니다. 배포 DB에는 기준정보도 영화 대표 맛도 아직
  없어 빈 상태만 나옵니다
- **페이지네이션.** 3.1 · 7.1 · 7.6은 첫 페이지만 씁니다. `cursor` · `size` · `flavorCode`
  질의는 쓰는 화면이 없어 확인하지 않았습니다
