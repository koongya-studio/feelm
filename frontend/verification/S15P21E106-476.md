# 검색 화면 연동 검증 기록

2026-09-16, 로컬 백엔드를 띄우고 4.1 ~ 4.4를 실제 응답으로 돌려 본 결과입니다. 대상은
검색 화면(S15P21E106-476, API-028 · API-029)입니다.

**이 기록은 로컬 확인 결과이며 배포 환경 검증 완료를 뜻하지 않습니다.** 확인하지 못한
것은 5장에 있습니다.

인증 세션과 가입 흐름은 [S15P21E106-376.md](./S15P21E106-376.md)에 있습니다.

## 1. 왜 남기는가

검색은 **데이터가 있어야 성립합니다.** 목업일 때는 10편이 코드 안에 있었지만 실제
연동에서는 DB에 무엇이 들어 있느냐가 화면을 바꿉니다. 자동 테스트는 응답을 흉내 낼 뿐
`genre=ACTION&genre=DRAMA`가 서버에서 정말 OR로 묶이는지, 20편을 넘겼을 때 커서가
이어지는지를 고정하지 못합니다.

필터 선택지도 그렇습니다. API-029는 **실제 영화와 연결된 기준정보만** 내려주므로,
와이어프레임이 그린 장르 6 · 국가 6은 고정된 수가 아닙니다. 데이터가 적으면 시트가
비어 보이는데, 그것이 결함인지 데이터 문제인지는 한 번 돌려 봐야 구분됩니다.

## 2. 환경

| 항목 | 값 |
| --- | --- |
| 백엔드 | 이 작업 브랜치 소스, `local` 프로파일, `MAIL_MODE=log`, `AUTH_MOCK_ENABLED=true` |
| 백엔드 포트 | **8081**. 다른 작업의 백엔드가 8080을 쓰고 있어 비켜 띄웠습니다 |
| DB · Redis | `infra/compose`의 로컬 PostgreSQL · Redis |
| 프론트 | Vite dev 서버 **5175**(5173도 사용 중), `VITE_API_PROXY_TARGET=http://localhost:8081` |
| 데이터 | 아래 3장의 임시 시드. 확인 뒤 전부 지웠습니다 |

`AUTH_MOCK_ENABLED=true`로 둔 것은 API-028이 회원 전용이라 로그인 없이 화면을 확인할 수
없기 때문입니다. 계정을 가르는 확인이 아니므로 고정 사용자 하나로 충분합니다. `watched`가
요청한 사용자 기준이라는 것만 감상 기록 한 건으로 확인했습니다.

## 3. 시드 데이터

로컬 DB의 `movies` · `genres`가 비어 있어(수집 파이프라인을 돌리지 않은 상태) 직접
넣었습니다. **id는 901~930, 9901~9903 대역**을 썼고 확인이 끝난 뒤 역순으로 전부
삭제해 원래 상태(0행)로 되돌렸습니다.

- 영화 25편 `검증영화 1` ~ `검증영화 25` — 개봉연도 2001~2025, 평점 1.0~4.2,
  장르는 `DRAMA` 고정 + `ACTION`/`SF` 교대, 국가 `KR`/`US` 교대, OTT 5종 순환
- 영화 1편 `검증영화 무연도` — **`original_title`과 `release_date`가 NULL**, 평가 없음,
  OTT 연결 없음
- 인물 1명 `검증감독`을 `검증영화 1`의 `DIRECTOR`로, 그 영화에 사용자 1의
  `WATCHED_UNRATED` 감상 기록

`[!]` `psql`로 한글을 넣을 때 `docker exec -e PGCLIENTENCODING=UTF8`이 없으면 깨집니다.
컨테이너 안 경로를 쓸 때는 `MSYS_NO_PATHCONV=1`이 필요합니다.

`[!]` **curl로 한글 검색어를 확인할 때는 직접 percent-encoding해야 합니다.** Git Bash가
인자를 UTF-8이 아닌 코드페이지로 넘기면 Tomcat이 질의 문자열을 디코딩하지 못하고
`500 INTERNAL_ERROR`가 됩니다(`Character decoding failed`). 브라우저는 UTF-8로 보내므로
화면에서는 생기지 않는 상황이며, 도구 문제이지 계약 위반이 아닙니다. 다만 규약을 지키지
않는 클라이언트가 `400`이 아니라 `500`을 받는 것은 맞으므로 백엔드 쪽 후속 후보로 적어
둡니다.

## 4. 확인한 것

### 계약 응답으로 확인한 것

| 요청 | 응답 |
| --- | --- |
| API-029 `GET /movies/filter-options` | `200` · 장르 3 · 국가 2(`한국`·`미국`) · `yearRange {2001, 2025}` · OTT 5종 |
| API-028 `genre=DRAMA&size=20` | `totalCount: 26` · `items` 20 · `hasNext: true` · `nextCursor` 있음 |
| API-028 같은 조건 + `cursor` | 나머지 6편, `hasNext: false` |
| API-028 `genre=ACTION` / `genre=SF` | 각각 `totalCount: 8` |
| API-028 `genre=ACTION&genre=SF` | `totalCount: 16` — **같은 필터의 복수 값은 OR** |
| API-028 `genre=ACTION&country=KR` | `totalCount: 4` — **서로 다른 필터는 AND** |
| API-028 `q=검증감독` | `totalCount: 1` · `watched: true` — 감상 기록이 있는 영화 |
| API-028 `q=존재하지않는영화zzz` | `200` · `totalCount: 0` · 빈 `items` |
| API-028 조건 없음(`sort`만) | `400 VALIDATION_FAILED` |
| API-028 `yearFrom=2020&yearTo=2010` | `400 VALIDATION_FAILED` |
| API-028 `genre[0]=DRAMA` | `400 VALIDATION_FAILED` — 인덱스 표기는 거절 |

- **`검증영화 무연도`는 `originalTitle: null` · `releaseYear: null` · `ottProviders: []` ·
  `averageRating: 0.0`으로 옵니다.** 타입을 이 모양에 맞춘 근거입니다. `average_rating`은
  NOT NULL 집계 열이라 평가가 없어도 `null`이 아니라 `0`입니다

### 화면에서 확인한 것

| 확인 | 결과 |
| --- | --- |
| 4.1 검색 홈 | 급상승(목업)과 최근 검색어가 그대로. 필터 버튼이 열립니다 |
| 4.2 결과 | `검색 결과 26건` + 20행 + `더 보기` |
| 4.2 `더 보기` | 나머지 6행이 **아래에 이어 붙고** 버튼이 사라집니다 |
| 4.2 메타 줄 | `검증영화 무연도`는 `드라마 · ★0.0` — 연도가 빠진 자리에 `null`이 새지 않습니다 |
| 4.2 OTT 없음 | `시청 가능한 OTT 없음` |
| 4.3 시트 선택지 | 장르 `액션`·`드라마`·`SF`, 국가 `전체`·`한국`·`미국` — API-029 응답 그대로 |
| 4.3 `결과 보기 · N편` | 검색어만일 때 `26편`, `액션`을 고르면 줄고, `SF`를 더하면 `16편` |
| 4.3 → 4.2 | 고른 조건으로 다시 검색해 `검색 결과 16건` |
| 4.4 결과 없음 | `검색 결과가 없어요` + `검색어 초기화` |
| 실패 | 백엔드를 내린 뒤 제출하면 `검색하지 못했어요` + `다시 시도` |

브라우저가 실제로 보낸 질의(개발자 도구 네트워크)입니다. **배열이 같은 이름의 반복으로
실리고**, 개수 세기만 `size=1`인 것이 여기서 드러납니다.

```
/api/v1/movies/search?q=검증영화&sort=RELEVANCE&size=1                        (시트 열림)
/api/v1/movies/search?q=검증영화&genre=ACTION&sort=RELEVANCE&size=1           (액션 선택)
/api/v1/movies/search?q=검증영화&genre=ACTION&genre=SF&sort=RELEVANCE&size=1  (SF 추가)
/api/v1/movies/search?q=검증영화&genre=ACTION&genre=SF&sort=RELEVANCE&size=20 (결과 보기)
```

## 5. 확인하지 못한 것

- **로그인하지 않은 상태의 401.** `AUTH_MOCK_ENABLED=true`로 띄워 이 경로를 만들 수
  없었습니다. 자동 테스트(`api/search.test.ts`)가 401이 그대로 올라오는 것까지만
  고정합니다. 화면은 다른 실패와 같은 `검색하지 못했어요`를 보여줍니다
- **`더 보기` 실패 뒤 `다시 시도`.** 두 번째 장만 실패하는 상황을 로컬에서 만들지
  못했습니다. 자동 테스트가 목록이 남는 것과 버튼 문구가 바뀌는 것을 고정합니다
- **조건이 바뀐 커서의 `400`.** 화면이 조건을 바꿀 때 커서를 버리므로 이 경로를 만들 수
  없습니다. 백엔드 쪽 시험이 고정하고 있습니다
- **실제 수집 데이터.** 넣은 26편은 검색을 확인하기 위한 값이며, 한국어 형태소·유사도
  검색의 품질(어느 검색어가 어떤 영화를 얼마나 위로 올리는지)은 실제 데이터로 다시
  봐야 합니다
- **배포 환경.** 배포 DB에 영화가 들어 있는지는 확인하지 않았습니다. 비어 있으면 검색은
  항상 4.4입니다
