## API-059 내 리포트 목록

`GET` `/api/v1/users/me/reports`

| 항목 | 값 |
|---|---|
| 단계 | 2차 MVP |
| 인증 | 회원 |
| 관련 요구사항 | FR-23 |
| 화면 | ⑦ 리포트 발급, ⑪-1 취향 리포트 |
| 미정 사항 | 있음 |
| 비고 | - |

### 설명

반기별 취향 리포트 목록을 조회한다.

### 인증 및 권한

- 회원

### Path Parameters

없음

### Query Parameters

없음

### Request Body

없음

### Response

`200 OK`

```json
{
  "items": [
    {
      "reportId": 301,
      "period": { "year": 2026, "half": "H1" },
      "status": "READY",
      "title": "2026 상반기 취향 리포트",
      "createdAt": "2026-06-30T14:57:00Z"
    }
  ]
}
```

### 오류 응답

- 공통 오류만 해당

### 처리 규칙

- 반기당 사용자 리포트는 하나다. 기간과 발급 시각은 `Asia/Seoul` 기준이다.
- 상반기(`H1`) 리포트의 필름 반영 마감은 6월 30일 23:50, 뽑기 가능 시각은 7월 1일 00:00이다. 하반기(`H2`)는 12월 31일 23:50 마감, 다음 해 1월 1일 00:00부터 뽑을 수 있다. 마감 이후 자정까지의 필름·평가 변경은 해당 리포트에 반영하지 않으며, 다른 기능에는 정상 반영한다. 이 10분에 **새로 필름에 추가된 프레임**은 누락하지 않고 다음 반기 리포트의 집계 구간에 포함한다. 따라서 H1의 실질 집계 구간은 전년도 12월 31일 23:50부터 해당 연도 6월 30일 23:50 직전까지, H2는 해당 연도 6월 30일 23:50부터 12월 31일 23:50 직전까지다(모두 한국시간). 화면에는 각 리포트의 `6월 30일 23:50 기준` 또는 `12월 31일 23:50 기준`을 알린다.
- 마감 후 리포트를 미리 집계·검증한다. 정상 경로에서는 준비된 결과를 자정에 뽑기 가능하게 공개한다. 자정에 계산을 시작하거나 사용자 버튼으로 집계를 시작하지 않는다. 준비가 실패하거나 지연되면 불완전한 결과를 발급하지 않고 `준비 중`으로 표시해 재시도·운영 알림 대상으로 삼는다.
- `READY`는 계산 완료 상태이지 목록 공개 여부가 아니다. 사용자가 `새 리포트 뽑기`를 누르면 준비된 결과를 발급하고 프론트가 인화 애니메이션을 보여준 뒤 4컷 목록에 노출한다. 발급하지 않은 리포트는 목록에서 숨긴다. 다음 반기의 예정 공개 시각(7월 1일 또는 다음 해 1월 1일 00:00 KST)이 되면 미발급 이전 `READY` 리포트를 자동으로 목록에 공개한다. 새 반기 리포트가 평가 부족·집계 실패·지연으로 없거나 아직 `READY`가 아니어도 이전 리포트 공개는 늦추지 않는다.
- `createdAt`은 저장된 리포트의 생성 시각(UTC)이며 필름 반영 마감 시각이나 버튼 발급 시각이 아니다. 발급 시각을 노출할지는 발급 API 계약에서 정한다.
- 발급·목록 공개 상태는 브라우저 세션이 아니라 서버에서 일관되게 판정·보존해야 한다. 발급 요청 경로와 저장 필드, API-059의 미발급/`GENERATING` 응답 형태는 FE·BE 연동 전에 별도 확정한다.
- 마감 스냅샷의 필름에 남아 있으면서 해당 반기 집계 구간에 생성된 프레임이 3개 미만이면 리포트를 생성하지 않는다. 프레임 없이 `봤어요` 기록만 있는 영화는 포함하지 않는다. 현재 프레임은 평가와 1:1로 연결되어 있지만 집계 기준은 평가 변경 이력이 아니라 필름 프레임이다.
- 반기 집계는 Spring+PostgreSQL이 담당한다. 마감 시각의 필름·연결 평가 상태를 정확히 고정하는 방법과 10분 내 준비 성능은 생성 구현에서 검증한다.

### 상태값

- ReportStatus: `GENERATING`, `READY` (계산 상태이며 발급/목록 공개 상태와 별개)
- `half`: `H1`, `H2`

### 미정 사항

- [x] 생성 시점: 마감일 23:50 이후 사전 집계·검증, 다음 날 00:00부터 준비된 결과를 뽑기 가능하게 공개. 버튼은 발급 동작
- [x] 최소 집계 수: 마감 시점 필름에 남은 해당 구간의 프레임 3개 이상
- [x] 생성 주체: Spring+PostgreSQL. 마감 시각의 필름·연결 평가 상태 고정 방법은 생성 구현에서 검증
- [x] 다음 반기 예정 공개 시각에 이전 미발급 `READY` 리포트 자동 공개. 새 반기 리포트의 존재·완료 여부와 무관
- [ ] 발급 API·서버 공개 상태와 API-059 목록/준비 중 응답 형태의 FE·BE 계약

### 설명

### 인증 및 권한

- 회원. 본인 리포트만

- `reportId`

### Query Parameters

### Request Body

없음

### Response

`201 Created`

```json

  "format": "PNG",
  "downloadUrl": "https://storage.example.com/...?X-Amz-Expires=600&...",
```

### 오류 응답

- `404 RESOURCE_NOT_FOUND`
- `409 REPORT_GENERATING`

### 처리 규칙

- 파일 형식은 PNG만. PDF는 제공하지 않는다

- 이미 생성된 이미지가 있으면 재렌더링하지 않고 새 서명 URL만 발급한다(가정)
- 공유는 클라이언트가 다운로드한 이미지를 OS 공유 시트로 전달하는 방식이며 서버 측 SNS 연동은 없다

## API-064 급상승 영화

`GET` `/api/v1/movies/trending`

| 항목 | 값 |
|---|---|
| 단계 | 2차 MVP |
| 인증 | 공개 |
| 관련 요구사항 | FR-27 |
| 화면 | 검색 홈 4.1(화면 연동은 후속 업무) |
| 미정 사항 | 구현 세부값은 실측 후 조정 |
| 비고 | 실시간 조회 이벤트 집계(ADR-0017) |

### 설명

최근 로그인 사용자의 영화 상세 조회 추이를 기반으로 급상승 영화를 제공한다. 비회원 상세 조회는 `VIEW` 발행 대상이 아니다([스트리밍 계약](./streaming-contract.md#43-이벤트별-payload)). 순위는 Spark Structured Streaming이 사전 집계하며 API 요청 시 다시 계산하지 않는다(ADR-0017).

### 인증 및 권한

- 공개

### Path Parameters

없음

### Query Parameters

- `size` (integer, 기본 10, 허용 1~30). 범위를 벗어나거나 정수가 아니면 `400 VALIDATION_FAILED`

### Request Body

없음

### Response

`200 OK`

```json
{
  "period": { "from": "2026-09-18T11:00:00Z", "to": "2026-09-18T12:00:00Z" },
  "updatedAt": "2026-09-18T12:00:00Z",
  "stale": false,
  "items": [
    {
      "rank": 1,
      "rankDelta": null,
      "movie": { "movieId": 550, "title": "파이트 클럽", "posterUrl": "https://..." },
      "ratingCount": 120,
      "averageScore": 4.3,
      "trendScore": 1.0
    }
  ]
}
```

### 오류 응답

- `400 VALIDATION_FAILED`: `size`가 정수가 아니거나 1~30 범위를 벗어남
- `503 TREND_UNAVAILABLE`: 최신 집계 결과와 마지막 정상 결과를 모두 읽을 수 없음(첫 집계 전·결과 유실·Redis 조회 장애 등)
- 그 외 공통 오류 적용

### 처리 규칙

- 여러 사용자의 `VIEW` 이벤트는 Spark Structured Streaming이 사전 집계하고 Spring Boot는 Redis 결과를 조회한다
- `to`는 UTC 5분 경계다. 현재 구간 `[to-60분, to)`의 영화별 고유 조회 회원 수 `C`와 직전 구간 `[to-120분, to-60분)`의 고유 조회 회원 수 `P`를 비교한다. 구간 시작은 포함하고 끝은 제외한다.
- 같은 `eventId`의 재전달은 스트리밍 계약의 watermark 기반 중복 판정 창에서 제거한다. 서로 다른 `eventId`여도 같은 회원이 같은 영화를 한 구간에서 여러 번 조회했다면 고유 조회자 1명으로 센다. `dwellMs`는 순위에 사용하지 않는다.
- `C >= 3`이고 증가분 `D = C - P > 0`인 영화만 후보로 삼는다. `D` 내림차순, `C` 내림차순, `movieId` 오름차순으로 정렬해 최대 30편을 게시한다. 후보가 없으면 정상적인 빈 `items` 스냅샷을 게시한다.
- API는 게시된 목록의 정렬 순서에서 앞 `size`편만 반환한다. `rank`와 `rankDelta`는 최대 30편 전체 스냅샷을 기준으로 계산하며 `size`에 따라 다시 계산하지 않는다.
- 후보 중 최대 증가분을 `Dmax`라 할 때 각 영화의 `trendScore = D / Dmax`다. 후보가 있을 때 값의 범위는 `(0, 1]`이며 평점이 아니다.
- `rankDelta`는 직전 게시 스냅샷의 순위에서 현재 순위를 뺀 값이다. 직전 목록에 없으면 신규 진입으로 `null`, 순위가 같으면 `0`이다. 현재 목록에서 이탈한 영화는 응답하지 않는다.
- 급상승 결과는 입력 이벤트가 없는 때에도 UTC 5분 경계마다 새로 게시한다. Spark의 이벤트 소비·마이크로배치 실행 주기는 별도로 정한다. 정상 도착한 `VIEW`의 발생부터 결과 게시까지 10분 이내를 초기 운영 목표로 삼고 실측한다.
- API 요청 시 인기 순위를 다시 계산하지 않는다
- 최신 집계 결과(`feelm:trending:current`, TTL 15분)를 읽으면 `stale=false`로 `200 OK`를 반환한다. 최신 결과를 읽을 수 없고 마지막 정상 결과(`feelm:trending:last-good`, TTL 2시간)를 읽을 수 있으면 그 스냅샷의 `period`·`updatedAt`을 유지하고 `stale=true`로 `200 OK`를 반환한다. 빈 `items`도 정상 스냅샷이다.
- 마지막 정상 결과도 읽을 수 없으면 `503 TREND_UNAVAILABLE`을 반환한다. Redis 조회 장애로 두 결과 모두 읽을 수 없는 경우도 같다.

### 상태값

없음
