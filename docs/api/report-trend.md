## API-059 내 리포트 목록

`GET` `/api/v1/users/me/reports`

| 항목 | 값 |
|---|---|
| 단계 | 2차 MVP |
| 인증 | 회원 |
| 관련 요구사항 | FR-23 |

| 미정 사항 | 있음 |
| 비고 | - |

### 설명

반기별 취향 리포트 목록을 조회한다.

### 인증 및 권한

- 회원

### Path Parameters

없음

### Query Parameters

없음

### Request Body

없음

### Response

`200 OK`

```json
{
  "items": [
    {
      "reportId": 301,
      "period": { "year": 2026, "half": "H1" },
      "status": "READY",
      "title": "2026 상반기 취향 리포트",

```

### 오류 응답

- 공통 오류만 해당

### 처리 규칙

- 반기당 사용자 리포트는 하나다. 기간과 발급 시각은 `Asia/Seoul` 기준이다.
- 상반기(`H1`) 리포트의 **새 프레임 포함 마감**은 6월 30일 23:50, 뽑기 가능 시각은 7월 1일 00:00이다. 하반기(`H2`)는 12월 31일 23:50 마감, 다음 해 1월 1일 00:00부터 뽑을 수 있다. 23:50 이후 새로 필름에 추가된 프레임은 이번 리포트에서 제외하고 다음 반기 집계 구간에 포함한다. 따라서 H1의 프레임 생성 구간은 전년도 12월 31일 23:50부터 해당 연도 6월 30일 23:50 직전까지, H2는 해당 연도 6월 30일 23:50부터 12월 31일 23:50 직전까지다(모두 한국시간).
- 기존 프레임·연결 평가·영화 메타데이터의 상태는 마감 시각부터 **최대 5분 뒤(23:55)까지** 획득한 PostgreSQL 일관 스냅샷을 사용한다. 따라서 23:50 이후 스냅샷 획득 전까지 기존 평가를 수정하거나 프레임을 삭제한 내용은 이번 리포트에 반영될 수 있다. 스냅샷 획득 이후 변경은 반영하지 않는다. 23:55까지 스냅샷을 얻지 못하면 늦은 현재 데이터를 과거 상태로 추정해 공개하지 않고 `준비 중` 및 운영 알림 대상으로 둔다. 화면의 `23:50 기준`은 정확한 데이터 상태 시각으로 표기하지 않고, 프레임 포함 마감과 실제 스냅샷 시각의 차이를 구분한다.
- 마감 후 리포트를 미리 집계·검증한다. 정상 경로에서는 준비된 결과를 자정에 뽑기 가능하게 공개한다. 자정에 계산을 시작하거나 사용자 버튼으로 집계를 시작하지 않는다. 준비가 실패하거나 지연되면 불완전한 결과를 발급하지 않고 `준비 중`으로 표시해 재시도·운영 알림 대상으로 삼는다.
- `READY`는 계산 완료 상태이지 목록 공개 여부가 아니다. 사용자가 `새 리포트 뽑기`를 누르면 준비된 결과를 발급하고 프론트가 인화 애니메이션을 보여준 뒤 4컷 목록에 노출한다. 발급하지 않은 리포트는 목록에서 숨긴다. 다음 반기의 예정 공개 시각(7월 1일 또는 다음 해 1월 1일 00:00 KST)이 되면 미발급 이전 `READY` 리포트를 자동으로 목록에 공개한다. 새 반기 리포트가 평가 부족·집계 실패·지연으로 없거나 아직 `READY`가 아니어도 이전 리포트 공개는 늦추지 않는다.
- `createdAt`은 저장된 리포트의 생성 시각(UTC)이며 필름 반영 마감 시각이나 버튼 발급 시각이 아니다. 발급 시각을 노출할지는 발급 API 계약에서 정한다.
- 발급·목록 공개 상태는 브라우저 세션이 아니라 서버에서 일관되게 판정·보존해야 한다. 발급 요청 경로와 저장 필드, API-059의 미발급/`GENERATING` 응답 형태는 FE·BE 연동 전에 별도 확정한다.
- 마감 스냅샷의 필름에 남아 있으면서 해당 반기 집계 구간에 생성된 프레임이 3개 미만이면 리포트를 생성하지 않는다. 프레임 없이 `봤어요` 기록만 있는 영화는 포함하지 않는다. 현재 프레임은 평가와 1:1로 연결되어 있지만 집계 기준은 평가 변경 이력이 아니라 필름 프레임이다.
- 반기 최종 준비가 성공했으나 대상 사용자가 0명이면 리포트 행은 없고 기간별 배치 완료 기록만 남긴다. 이는 준비 실패·지연과 다르며, 목록 API의 구체적인 응답 형태는 API-059 연동 계약에서 확정한다.
- 반기 집계는 Spring+PostgreSQL이 담당한다. 마감 후 5분 이내 스냅샷 획득과 자정까지의 준비 성능은 생성 구현에서 검증한다.

### 상태값

- ReportStatus: `GENERATING`, `READY` (계산 상태이며 발급/목록 공개 상태와 별개)
- `half`: `H1`, `H2`

### 미정 사항

- [x] 생성 시점: 마감일 23:50 이후 사전 집계·검증, 다음 날 00:00부터 준비된 결과를 뽑기 가능하게 공개. 버튼은 발급 동작
- [x] 최소 집계 수: 마감 시점 필름에 남은 해당 구간의 프레임 3개 이상
- [x] 생성 주체: Spring+PostgreSQL. 새 프레임은 23:50에 끊고 기존 데이터의 상태는 23:50~23:55 사이의 일관 스냅샷으로 고정
- [x] 다음 반기 예정 공개 시각에 이전 미발급 `READY` 리포트 자동 공개. 새 반기 리포트의 존재·완료 여부와 무관
- [ ] 발급 API·서버 공개 상태와 API-059 목록/준비 중 응답 형태의 FE·BE 계약

## API-060 리포트 상세 조회

`GET` `/api/v1/reports/{reportId}`

| 항목 | 값 |
|---|---|
| 단계 | 2차 MVP |
| 인증 | 회원 |
| 관련 요구사항 | FR-23 |
| 화면 | ⑦-1 리포트 상세, ⑪-1-a 리포트 상세 |
| 미정 사항 | 있음 |
| 비고 | - |

### 설명

완성된 반기별 취향 4컷과 상세 리포트를 조회한다. 취향 4컷은 이번 반기 대표 장르 → 감독 → 배우 → 사용자의 필름 분석에 따른 캐릭터 순서이며, 상세 화면에는 장르·국가·시대 비율, 감독·배우 감상 편수, 캐릭터 설명, 지난 반기 비교를 표시한다.

### 인증 및 권한

- 회원. 본인 리포트만

### Path Parameters

- `reportId`

### Query Parameters

없음

### Request Body

없음

### Response

`200 OK`

```json
{
  "reportId": 301,
  "period": { "year": 2026, "half": "H1" },
  "summary": { "ratingCount": 38, "newFlavorCount": 2, "averageScore": 4.1 },
  "topGenres": [{ "code": "THRILLER", "name": "스릴러", "count": 12 }],
  "topActors": [{ "personId": 287, "name": "브래드 피트", "count": 3 }],
  "topDirectors": [{ "personId": 7467, "name": "데이비드 핀처", "count": 3 }],
  "characterCard": { "name": "타일러 더든", "movieTitle": "파이트 클럽", "description": "사용자의 필름 취향을 대표하는 캐릭터입니다.", "imageUrl": null },
  "flavorChanges": [{ "flavorCode": "FLAVOR_A", "before": 5, "after": 12 }],
  "createdAt": "2026-06-30T14:57:00Z",
  "fourCut": {
    "genre": { "name": "스릴러", "displayName": null, "image": { "url": null } },
    "director": { "name": "데이비드 핀처", "displayName": null, "image": { "url": null }, "work": null },
    "actor": { "name": "브래드 피트", "displayName": null, "image": { "url": null } },
    "character": { "name": "타일러 더든", "displayName": null, "image": { "url": null } }
  },
  "genreShares": [{ "label": "스릴러", "share": 49 }],
  "countryShares": [{ "label": "한국", "share": 42 }],
  "eraShares": [{ "label": "2010년대", "share": 38 }],
  "keywords": [],
  "comparisons": [{ "label": "범죄·스릴러", "delta": 12, "isNew": false }],
  "highlights": ["이번 반기의 영화 취향을 한 장에 담았어요"]
}
```

이 예시의 이름·비율·비교 수치는 응답 형태를 보여주는 목업 값이며 실제 선정·계산 결과가 아니다.

리포트의 집계 대상은 마감 스냅샷 시점에 **내 필름에 남아 있는 프레임**이다. `frames.created_at`이 해당 6개월 집계 구간에 속하는 프레임을 그 반기의 영화로 센다. 기존 응답의 `summary.ratingCount`도 이 프레임 수와 일치한다. 현재 스키마에서는 프레임이 평가와 1:1로 연결되지만, 집계의 기준은 평가 변경 이력이 아니라 필름이다. 한줄평 내용이나 별점 높낮이는 포함 여부를 바꾸지 않는다. 평가를 완전히 삭제해 프레임이 사라지면 이후 리포트의 집계·과거 판정에서 제외하고, `봤어요` 감상 기록만 남은 영화는 프레임이 없으므로 포함하지 않는다.

### 포함 섹션과 필드

| 화면 섹션 | 응답 필드 | 계약 |
|---|---|---|
| 취향 4컷 | `fourCut.genre`, `director`, `actor`, `character` | 네 칸은 같은 `period`의 리포트 결과다. 이름은 각각 `topGenres[0]`, `topDirectors[0]`, `topActors[0]`, `characterCard`와 일치한다. 대표 장르는 해당 반기 필름 프레임의 장르별 영화 편수가 많은 순으로 선정하고, 편수가 같을 때만 그 장르 영화의 평균 별점으로 순서를 정한다 |
| 4컷 이미지·표기 | 각 칸의 `name`, `displayName`, `image`; 감독의 `work` | `name`은 표시 이름이다. `displayName`은 큰 글자용 표기로 없으면 `null`이며 화면은 `name`을 사용한다. 이미지가 없으면 `image.url: null`, 감독 대표작 이미지가 없으면 `work: null`로 반환한다 |
| 상세 비율 | `genreShares`, `countryShares`, `eraShares` | 각 항목은 `{ "label": string, "share": number }`이며 `share`는 화면에 표시할 0~100의 **정수 퍼센트**로 최종 단계에서 반올림한다(`5/12 = 41.67%` → `42%`). 해당 반기에 추가되어 마감 스냅샷의 필름에 남은 **프레임 한 개(영화 한 편)를 한 표**로 세며 별점 크기로 가중하지 않는다. 상위 항목만 반환할 수 있어 배열 합계를 100으로 가정하지 않는다 |
| 감독·배우 | `topDirectors`, `topActors` | `count`는 해당 반기 리포트에 포함된 감상 영화 편수로 표시한다 |
| 캐릭터 설명 | `characterCard.description` | 4컷의 캐릭터에 대한 설명을 표시한다 |
| 지난 반기와 비교 | `comparisons` | 각 항목은 `{ "label": string, "delta": number, "isNew": boolean }`이다. 같은 마감 스냅샷에 남아 있는 프레임을 이번/직전 6개월 구간으로 나눠 각 비율을 계산한다. `delta`는 같은 항목의 **반올림 전** 이번 반기 비율에서 직전 반기 비율을 뺀 퍼센트포인트 차이를 마지막에 정수 반올림한 값이다(`41.67% − 30% = 11.67%p` → `+12%p`). 표시된 정수 비율이나 과거 리포트에 저장된 비율을 빼지 않는다. `isNew: true`는 이번 반기 전의 **필름에 남아 있는 모든 프레임**에서 해당 항목을 찾을 수 없을 때만 붙인다. 직전 6개월에만 없고 더 이전의 남아 있는 프레임에 있었다면 `false`다. 첫 리포트처럼 비교할 지난 반기 리포트가 없으면 빈 배열이다 |
| 발급 화면 요약 | `highlights` | 인화 화면의 주황색 표시 영역에 노출할 짧은 문장 최대 3개다. 생성된 반기 스냅샷의 실제 비교·신규 감독·새 팝콘 맛 등 확인 가능한 결과로 만들며, 목업 문구나 근거 없는 수치를 반환하지 않는다. 이전 반기 등 근거가 없으면 해당 비교 문구를 생략하거나 사실에 맞는 요약으로 대체한다 |
| 취향 키워드 | `keywords` | 이번 리포트 구현 범위에서는 분석·근거 생성을 하지 않아 빈 배열을 반환하고 화면은 이 섹션을 숨긴다. 후속 구현 시 `{ "code": string, "label": string, "rationale": string }` 항목을 사용한다 |

`fourCut.*.image`는 `{ "url": string | null, "cutoutUrl"?: string | null, "position"?: { "x": number, "y": number }, "zoom"?: number }` 형태를 사용한다. `cutoutUrl`은 배경이 제거된 이미지, `position.x/y`는 0~100 범위의 크롭 위치다. `cutoutUrl`, `position`, `zoom`은 없으면 생략할 수 있다. 이미지가 없어도 네 칸의 이름과 상세 데이터는 반환하며 화면은 텍스트 대체 표시를 사용한다.

감독·배우 칸의 `image.url`은 리포트에 선정된 `personId`의 기존 `people.profile_url`을 반기 결과에 보존해 반환한다. 기존 TMDb 적재가 `profile_path`를 이 필드에 저장하므로 리포트 조회나 인화 버튼에서 TMDb를 다시 호출하지 않는다. 해당 인물의 URL이 없거나 사진 표시가 허용되지 않으면 `null`이며, 프론트는 이름만 있는 카드로 대체한다. `cutoutUrl`이나 영문 `displayName`을 사진 URL에서 추측해 만들지 않는다. 외부 PNG에 사진을 합성해 공유하는 권한은 앱 안에서 URL을 표시하는 경우와 별도로 확인한다.

`createdAt`은 저장된 리포트 행의 생성 시각이며 사용자가 버튼을 눌러 뽑은 시각이 아니다. 4컷의 인화 월(`H1`의 다음 7월, `H2`의 다음 해 1월)은 `period`에서 정한다.

상세 화면의 저장·공유 버튼은 이 조회 응답의 별도 상태가 아니다. 두 버튼과 공유 시트의 `이미지로 저장`은 API-061의 같은 취향 4컷 PNG를 사용한다. `저장`을 단순 화면 이탈로 처리하지 않는다.

### 오류 응답

- `404 RESOURCE_NOT_FOUND`
- `409 REPORT_GENERATING`

### 처리 규칙

- 리포트는 생성 시점 스냅샷이며 이후 평가 변경을 반영하지 않는다
- API-060은 `READY` 상태의 저장된 결과를 반환하며 조회할 때 현재 평가 데이터를 다시 분석하지 않는다
- 반기 비율과 대표 장르는 그 6개월 동안 필름에 추가되어 마감 시점에도 남은 프레임의 **영화 편수**를 기준으로 하며 별점은 대표 장르의 편수 동률일 때만 사용한다. 비율과 퍼센트포인트 차이는 각각 원본 분자·분모로 계산한 뒤 마지막에 정수 반올림한다. 과거 리포트의 표시용 정수 비율만으로 차이를 다시 계산하지 않는다. 화면 목업 수치를 실제 계산 결과로 사용하지 않는다
- `isNew`는 단순히 직전 반기 0%라는 뜻이 아니라 리포트 기준 스냅샷에 **남아 있는 이전 기간의 필름 프레임 전체**에 해당 항목이 없다는 뜻이다. 삭제되어 필름에서 사라진 프레임은 과거 이력으로 세지 않으며, 평가 삭제 후 남은 `봤어요` 감상 기록도 세지 않는다. 따라서 과거 리포트에 나타난 항목이어도 관련 과거 프레임이 모두 사라졌다면 다시 `신규`가 될 수 있다. 이전 리포트 스냅샷 자체는 바꾸지 않는다

### 상태값

- ReportStatus

### 미정 사항

- [x] 포함 섹션: 취향 4컷, 상세 비율, 감독·배우, 캐릭터 설명, 지난 반기 비교, 발급 요약. 취향 키워드 분석은 후속 범위
- [x] 지난 반기 비교의 `delta` 단위와 표시: 같은 항목의 반기별 비율 차이를 `%p`로 표시
- [x] 비율과 대표 장르의 집계 단위: 해당 6개월에 필름에 추가되어 마감 시점에 남은 프레임 한 개가 한 표. 별점 가중 없음; 대표 장르 편수 동률일 때만 평균 별점 사용
- [x] 비율·`delta`는 동일한 마감 스냅샷에서 반기별로 나눈 프레임의 원본 비율로 계산한 뒤 정수 반올림; `isNew`는 이번 반기 전 필름에 남아 있는 모든 프레임에서 처음 나온 항목. 삭제된 프레임은 제외
- [x] 메타데이터 결측 프레임도 전체 영화 편수 분모에는 포함하되 결측 항목 자체는 순위·비율 목록에 표시하지 않는다. 따라서 상위 항목 배열 합계는 100%보다 작을 수 있으며, 선정 결과가 없으면 해당 카드·배열을 `null` 또는 빈 배열로 반환한다

## API-064 급상승 영화

`GET` `/api/v1/movies/trending`

| 항목 | 값 |
|---|---|
| 단계 | 2차 MVP |
| 인증 | 공개 |
| 관련 요구사항 | FR-27 |
| 화면 | 검색 홈 4.1(화면 연동은 후속 업무) |
| 미정 사항 | 구현 세부값은 실측 후 조정 |
| 비고 | 실시간 조회 이벤트 집계(ADR-0017) |

### 설명

최근 로그인 사용자의 영화 상세 조회 추이를 기반으로 급상승 영화를 제공한다. 비회원 상세 조회는 `VIEW` 발행 대상이 아니다([스트리밍 계약](./streaming-contract.md#43-이벤트별-payload)). 순위는 Spark Structured Streaming이 사전 집계하며 API 요청 시 다시 계산하지 않는다(ADR-0017).

첫 유효한 급상승 목록이 생기기 전에는 아래 고정 초기 순서 A를 보여준다. 첫 비어 있지 않은
집계 결과 B가 생기면 B로 전환하고, 이후 새 유효 B가 없으면 마지막 B를 기간 제한 없이
유지한다. 빈 5분 집계는 A로 되돌리거나 B를 지우지 않는다. KOBIS는 초기 목록에 사용하지 않는다.

| --- | --- | ---: |
| 1 | 오디세이 | 134626 |
| 2 | 왕과 사는 남자 | 124813 |
| 3 | 스파이더맨: 브랜드 뉴 데이 | 86995 |
| 4 | 프로젝트 헤일메리 | 80719 |

| 6 | 옵세션 | 36815 |

| 9 | 트로이 | 522 |
| 10 | 스파이더맨: 파 프롬 홈 | 68176 |

### 인증 및 권한

- 공개

### Path Parameters

없음

### Query Parameters

- `size` (integer, 기본 10, 허용 1~30). 범위를 벗어나거나 정수가 아니면 `400 VALIDATION_FAILED`

### Request Body

없음

### Response

`200 OK`

```json
{
  "source": "VIEW",
  "period": { "from": "2026-09-18T11:00:00Z", "to": "2026-09-18T12:00:00Z" },
  "updatedAt": "2026-09-18T12:00:00Z",
  "stale": false,
  "items": [
    {
      "rank": 1,
      "rankDelta": null,
      "movie": { "movieId": 550, "title": "파이트 클럽", "posterUrl": "https://..." },
      "ratingCount": 120,
      "averageScore": 4.3,
      "trendScore": 1.0
    }
  ]
}
```

초기 A는 `source="DEFAULT"`, `period=null`, `updatedAt=null`, `stale=false`로 반환한다.
각 항목의 `rankDelta`와 `trendScore`는 `null`이며 `rank`는 위 고정 순서다.
영화 메타데이터와 평점 필드는 기존 영화 데이터에서 채운다. B는 `source="VIEW"`이고
위 예시처럼 집계 시각과 점수를 포함한다. `size`는 선택된 목록의 앞부분에 적용한다.

### 오류 응답

- `400 VALIDATION_FAILED`: `size`가 정수가 아니거나 1~30 범위를 벗어남
- `503 TREND_UNAVAILABLE`: Redis 조회 장애 등으로 최신 또는 마지막 정상 급상승 결과(B)를 조회할 수 없고 초기 고정 목록(A)으로 안전하게 대체할 수도 없음
- 그 외 공통 오류 적용

### 처리 규칙

- 여러 사용자의 `VIEW` 이벤트는 Spark Structured Streaming이 사전 집계하고 Spring Boot는 Redis 결과를 조회한다
- `to`는 UTC 5분 경계다. 현재 구간 `[to-60분, to)`의 영화별 고유 조회 회원 수 `C`와 직전 구간 `[to-120분, to-60분)`의 고유 조회 회원 수 `P`를 비교한다. 구간 시작은 포함하고 끝은 제외한다.
- 같은 `eventId`의 재전달은 스트리밍 계약의 watermark 기반 중복 판정 창에서 제거한다. 서로 다른 `eventId`여도 같은 회원이 같은 영화를 한 구간에서 여러 번 조회했다면 고유 조회자 1명으로 센다. `dwellMs`는 순위에 사용하지 않는다.
- `C >= 3`이고 증가분 `D = C - P > 0`인 영화만 후보로 삼는다. `D` 내림차순, `C` 내림차순, `movieId` 오름차순으로 정렬해 최대 30편을 게시한다. 후보가 없으면 기존 유효 B를 덮어쓰지 않는다.
- API는 게시된 목록의 정렬 순서에서 앞 `size`편만 반환한다. `rank`와 `rankDelta`는 최대 30편 전체 스냅샷을 기준으로 계산하며 `size`에 따라 다시 계산하지 않는다.
- 후보 중 최대 증가분을 `Dmax`라 할 때 각 영화의 `trendScore = D / Dmax`다. 후보가 있을 때 값의 범위는 `(0, 1]`이며 평점이 아니다.
- `rankDelta`는 직전 게시 스냅샷의 순위에서 현재 순위를 뺀 값이다. 직전 목록에 없으면 신규 진입으로 `null`, 순위가 같으면 `0`이다. 현재 목록에서 이탈한 영화는 응답하지 않는다.
- 입력 이벤트가 없는 때에도 UTC 5분 경계마다 집계를 확인하며, 유효한 후보가 있을 때만 새 B를 게시한다. Spark의 이벤트 소비·마이크로배치 실행 주기는 별도로 정한다. 정상 도착한 `VIEW`의 발생부터 결과 게시까지 10분 이내를 초기 운영 목표로 삼고 실측한다.
- API 요청 시 인기 순위를 다시 계산하지 않는다
- 최신 유효 B(`feelm:trending:current`, TTL 15분)를 읽으면 `stale=false`로 `200 OK`를 반환한다. 최신 결과가 없고 마지막 유효 B(`feelm:trending:last-good`, 만료 없음)를 읽을 수 있으면 원래 `period`·`updatedAt`을 유지하고 `stale=true`로 반환한다. 오래되었다는 이유만으로 B를 폐기하지 않는다.
- 유효 B가 아직 없으면 초기 A를 `200 OK`로 반환한다. Redis 조회 장애로 최신 또는 마지막 정상 급상승 결과(B)를 조회할 수 없으면 `503 TREND_UNAVAILABLE`을 반환한다. Redis 전체 유실 시 마지막 B의 보존은 보장할 수 없으며, 저장된 B가 없음을 정상적으로 조회한 뒤 A를 사용한다.

없음
