# 물리 스키마 규칙과 마이그레이션 정책

[논리 ERD](./erd.md)를 PostgreSQL 물리 스키마로 옮길 때 담당 3인이 같은 기준을 쓰도록
정의한다. 도메인별 테이블은 각 담당이 이 규칙에 맞춰 작성한다(S15P21E106-179/180/181).

규칙과 다르게 만들어야 하면 임의로 진행하지 않고 합의 후 이 문서를 먼저 수정한다.

## 1. 명명 규칙

| 대상 | 규칙 | 예 |
|---|---|---|
| 테이블 | snake_case 복수형. ERD 이름을 그대로 사용 | `watch_records` |
| 컬럼 | snake_case | `confirm_due_at` |
| 기본키 제약 | PostgreSQL 기본값(`<table>_pkey`)을 그대로 둔다 | `users_pkey` |
| 외래키 | `fk_<table>_<column>` | `fk_movies_representative_flavor_id` |
| 유일 제약 | `uk_<table>_<columns>` | `uk_users_email` |
| 부분·함수 유일 인덱스 | `uix_<table>_<의미>` | `uix_users_nickname_normalized` |
| 일반 인덱스 | `ix_<table>_<columns>` | `ix_movies_representative_flavor_id` |
| CHECK 제약 | `ck_<table>_<규칙>` | `ck_users_status` |

기본키를 제외한 모든 제약과 인덱스는 **이름을 명시한다.** 이름을 생략하면 PostgreSQL이
자동으로 만들어 환경마다 이름이 달라지고, 이후 제약을 변경하는 마이그레이션이 깨진다.

## 2. 식별자

- 내부 기본키와 외래키는 `bigint`다(ADR-0008, ERD D-1).
- 생성은 `bigint GENERATED BY DEFAULT AS IDENTITY`. JPA는 `GenerationType.IDENTITY`를 쓴다.
  `BY DEFAULT`이므로 적재 스크립트에서 식별자를 직접 지정할 수 있다.
- 연결 테이블(`movie_genres`, `movie_countries`, `movie_people`, `user_otts`,
  `party_members`)은 대리키를 추가하지 않고 ERD대로 복합 기본키를 쓴다.
- `taste_analyses`, `notification_settings`는 `user_id`가 기본키이자 외래키다.
- `users.public_id`는 `uuid`이며 기본값 `gen_random_uuid()`를 둔다. 애플리케이션은
  `UUID.randomUUID()`로 생성한다. 공개 URL에는 이 값만 노출한다.

## 3. 타입

| 논리 | 물리 | 비고 |
|---|---|---|
| 시각 | `timestamptz` | 예외 없이 통일한다. Java는 `Instant` |
| 날짜 | `date` | `birth_date`, `release_date` |
| 코드·열거값 | `varchar(n)` + CHECK | 허용값은 [API 공통 규약의 상태값](./api/README.md)과 일치시킨다 |
| 자유 텍스트 | `text` | 이름, 제목, 줄거리, URL 등 계약상 상한이 없는 값 |
| 길이 제한이 계약에 있는 문자열 | `varchar(n)` | 예: 닉네임 `varchar(20)`, 한줄평 `varchar(200)` |
| 평점 | `smallint` + CHECK(1~5) | `ratings.score` |
| 평균 평점 | `numeric(3,2)` + CHECK(0~5) | `movies.average_rating` |
| 국가 코드 | `varchar(2)` | ISO 3166-1 alpha-2 |
| 구조화 데이터 | `jsonb` | `reason`, `analysis`, `keywords`, `content` |
| 불리언 | `boolean NOT NULL DEFAULT false` | |
| 임베딩 | `vector(n)` | 테이블과 차원은 미설계. 아래 8장 참조 |

**PostgreSQL enum 타입을 쓰지 않는다.** 값을 추가할 때마다 `ALTER TYPE`이 필요하고
Hibernate 매핑이 번거롭다. `varchar` + CHECK로 통일한다.

## 4. NULL과 기본값

- ERD에 "NULL 가능"이 명시된 컬럼만 nullable로 두고 나머지는 `NOT NULL`이다.
- 다음 세 가지는 nullable이며, ERD에도 표기를 남긴다. 값이 없는 상태와 채워진 상태를
  구분하는 것이 컬럼의 목적이므로, 기본값으로 채우면 그 구분이 사라진다.
  - **상태 머신의 전이 시각** — 해당 전이 전까지 NULL이다.
    `watch_records`의 `clicked_at`·`confirm_due_at`·`expires_at`·`watched_at`·
    `rated_at`·`expired_at`, `users.withdrawn_at`, 1회용 토큰의 `used_at`
  - **계약이 조건부로만 요구하는 값** — `ratings.visibility`는 API-036이 `comment`가
    있을 때만 요구한다
  - **원천 데이터에 없을 수 있는 적재 항목** — TMDb·MovieLens에서 내려오지 않는 값과
    배치·모델이 나중에 채우는 값. `movies`의 상세 정보와 `representative_flavor_id`·
    `taste_model_version`·`synced_at`, `movie_people.character_name`·`display_order`,
    `movie_ott_providers.watch_url`·`synced_at`, `people.profile_url`, `otts.logo_url`
- `created_at`은 `NOT NULL DEFAULT now()`다. 실제 값은 JPA Auditing이 채우며, DB
  기본값은 Seed나 적재 파이프라인의 직접 삽입에 대한 방어다.
- 상태 컬럼에는 기본값을 두지 않는다. 삽입 시 명시적으로 지정하게 한다.
  단 `users.visibility`는 ERD가 기본 `PRIVATE`을 규정하므로 예외다.
- `updated_at`은 ERD가 해당 컬럼을 가진 테이블에만 둔다. `users`에는 없다.

## 5. 외래키 삭제 정책

기본값은 `ON DELETE RESTRICT`이며 아래만 예외다. 정책은 반드시 명시한다.

| 정책 | 대상 | 근거 |
|---|---|---|
| CASCADE | `users` → `user_auth_providers`, `email_verification_tokens`, `password_reset_tokens`, `notification_settings`, `user_otts`, `user_blocks`, `onboarding_preferences` | 계정에 종속된 데이터 |
| CASCADE | `ratings` → `frames` → `popcorns` | ERD 3장에 명시된 규칙 |
| CASCADE | `recommendation_sets` → `recommendation_items` | 세트 없는 아이템은 의미가 없음 |
| CASCADE | `parties` → `party_members`, `party_invitations` | 파티에 종속 |
| CASCADE | `taste_reports` → `report_images` | 리포트에 종속 |
| SET NULL | `recommendation_items` → `recommendation_dismissals.recommendation_item_id` | 아이템이 사라져도 관심없음 이력은 남는다 |
| RESTRICT | 기준정보 참조 전부(`movies`, `genres`, `people`, `otts`, `popcorn_flavors`) | 기준정보는 삭제하지 않는다 |
| RESTRICT | `ratings.watch_record_id` → `watch_records` | 감상 기록은 삭제하지 않고 상태만 전이한다 |

탈퇴는 물리 삭제가 아니라 상태 전이 + 익명화이므로(ERD D-9) `users` 대상 CASCADE는
평상시 발동하지 않는다. 개인정보 삭제 요청에 대응하기 위해 정의만 남긴다.

`ratings.user_id`는 공개 한줄평 처리 방식(삭제 vs '탈퇴한 사용자' 익명 유지)이 정해지면
그에 맞춰 확정한다. 담당은 BE-B다.

## 6. 제약과 인덱스

- ERD의 유일 제약을 모두 만든다.
- 조건이 붙는 유일성은 부분 유일 인덱스로 만든다. 해당하는 곳은 세 군데다.
  - `watch_records` — 사용자·영화별 활성 기록 1개(`EXPIRED`가 아닌 행)
  - `flavor_cluster_mappings` — `is_active`가 true인 버전 1개
  - `party_invitations` — `PENDING`인 (`party_id`, `invitee_id`) 유일
- 정규화 값으로 판단하는 유일성은 별도 컬럼을 두지 않고 함수 기반 유일 인덱스를 쓴다.
  규칙이 한 곳에만 있어야 조회 질의와 어긋나지 않는다. 조회 질의는 인덱스와 **같은 식**을
  써야 인덱스를 탄다.
  - `users` 닉네임: `lower(replace(nickname, ' ', ''))`
- **PostgreSQL은 외래키 컬럼에 인덱스를 자동으로 만들지 않는다.** 조회 조건이나 조인에
  쓰이는 외래키 컬럼에는 인덱스를 명시적으로 만든다. 판단은 도메인 담당이 조회 패턴을
  근거로 한다.

## 7. 확장

`vector`(ADR-0014)와 `pg_trgm`(ADR-0010)을 쓴다. 생성은 공통 선행 마이그레이션이
`CREATE EXTENSION IF NOT EXISTS`로 수행한다. 컨테이너 초기화 스크립트에 두지 않는 이유는
그 스크립트가 데이터 디렉터리가 비어 있을 때만 실행되어, 나중에 확장을 추가하면 이미
볼륨을 가진 환경에 반영되지 않기 때문이다.

`vector`는 이미지에 pgvector가 설치되어 있어야 한다(S15P21E106-177).

## 8. Flyway

### 위치와 파일명

- `backend/src/main/resources/db/migration` (Spring Boot 기본 경로)
- `V<YYYYMMDDHHmm>__<snake_case 설명>.sql`

**순번(`V1`, `V2`) 대신 타임스탬프를 쓴다.** 3인이 병렬로 작업하면 순번은 반드시 충돌하고,
충돌을 병합에서 푸는 사이 이미 적용된 개발 DB와 어긋난다.

한 파일은 한 가지 논리적 변경만 담는다. 도메인이 다르면 파일을 나눈다.

### 적용 정책

| 환경 | 적용 | 재생성 |
|---|---|---|
| local | 애플리케이션 기동 시 자동 | 자유. 볼륨을 지우고 다시 만들어도 된다 |
| test | 기본 테스트는 Flyway를 끄고 H2를 쓴다. 마이그레이션 자체는 Testcontainers 테스트가 검증한다 | 매 실행 |
| dev·스테이징 | 애플리케이션 기동 시 자동 | 금지 |

`spring.jpa.hibernate.ddl-auto`는 `none`을 유지한다. 스키마의 유일한 출처는 마이그레이션이다.

**롤백은 없다.** Flyway Community에는 undo가 없으므로 잘못된 마이그레이션은 앞으로 가는
마이그레이션으로 고친다. **이미 적용된 마이그레이션 파일은 수정하지 않는다.** 체크섬 검증에
걸려 다른 사람의 애플리케이션이 기동에 실패한다.

`out-of-order`는 `false`다. 병렬 작성으로 병합 순서와 버전 순서가 어긋나면 로컬은 볼륨을
재생성한다. 스테이징은 병합 순서를 버전 순서에 맞춘다.

### 병합 순서

외래키가 도메인을 가로지르므로 공통 선행 마이그레이션(확장, `users`, `movies`, `genres`,
`otts`, `people`, `popcorn_flavors`)이 먼저 병합되어야 도메인별 마이그레이션이 병렬로
진행된다.

### 테스트

`com.feelm.backend.migration`의 Testcontainers 테스트가 인프라와 합의한 것과 같은 이미지로
PostgreSQL 컨테이너를 띄우고 마이그레이션 전체를 적용한다. 공통 선행은 `V1MigrationTest`가
맡고, 도메인별 마이그레이션은 각 담당이 같은 패키지에 테스트를 추가한다. Flyway SQL은
PostgreSQL 문법이라 H2에서 실행되지 않으므로, 마이그레이션이 실제로 도는지 확인하는 지점은
이 테스트들뿐이다. 실행에 Docker가 필요하다.

## 9. 미결

- **영화 임베딩 테이블이 논리 ERD에 없다.** ADR-0014와 API-031이 pgvector 저장·조회를
  전제하는데 해당 엔티티가 정의되어 있지 않다. 테이블 구조, 벡터 차원,
  `embedding_model_version` 계약을 정해야 한다. 모델이 확정되지 않아 차원이 바뀔 수 있으므로
  `movies` 본체가 아닌 별도 테이블을 권한다.
- **닉네임 길이·허용 문자**가 API-001 미정 사항이다. 현재 `varchar(20)`은 명세의 가정값을
  반영한 것이다. 확정되면 `ALTER TABLE`로 조정한다.
- **기준정보 Seed** — `popcorn_flavors` 8종 코드(A-6)와 `otts` 목록(API-025)이 확정되지
  않아 빈 테이블만 만들었다. 확정 후 별도 마이그레이션으로 넣는다.
- **CI에서 Docker 사용 가능 여부** — Testcontainers 테스트의 전제다(S15P21E106-88).
