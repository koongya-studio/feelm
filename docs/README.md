# Documentation

프로젝트의 설계 및 협업 문서를 관리합니다.

추천의 최신 구현·학습 근거는 [v26 GBT 안내](../pipeline/docs/gbt-v26/README.md)에서 시작합니다.
ALS·초기 v1 문서는 역사와 현행 계약을 구분해 읽습니다. 아키텍처 소급 정리는
[ADR-0025 제안](adr/0025-v26-gbt-personal-party-recommendation.md)에 연결합니다.

## 문서 역할과 우선순위

규칙은 한 문서에만 정의하고 다른 문서는 링크로 참조합니다. 문서 종류별 역할은 다음과 같습니다.

| 종류 | 문서 | 역할 |
| --- | --- | --- |
| 설계·계약 | 요구사항 정의서, API 명세, 논리 ERD, 물리 스키마 규칙, ADR | 무엇을 만들지와 영역 간 계약을 정의합니다. 구현은 계약을 따르고, 계약을 바꿀 때는 문서를 먼저 수정합니다 |
| 코드 규칙 | 백엔드 개발 컨벤션 | 어떤 코드가 좋은 코드인지, 구현 시 지켜야 할 규칙을 정의합니다 |
| 협업 규칙 | Git 컨벤션, Secret 및 환경변수 관리 규칙, 백엔드 역할 분배 | 브랜치·커밋·MR, 설정과 인증정보, 담당 영역처럼 팀이 함께 지키는 규칙을 정의합니다 |
| 병렬 작업 조직 | AI 병렬 작업 및 충돌 방지 규칙 | 여러 작업자와 AI가 같은 저장소에서 동시에 작업할 때의 작업 공간 분리, 충돌 위험 분류, 합의가 필요한 변경을 정의합니다 |
| AI 작업 절차 | 루트 [`AGENTS.md`](../AGENTS.md), 작업 대상 영역의 `AGENTS.md` | 루트 공통 절차와 변경 경로에 해당하는 영역 지침만 적용합니다. `backend/**`에는 [`backend/AGENTS.md`](../backend/AGENTS.md), `pipeline/**`에는 [`pipeline/AGENTS.md`](../pipeline/AGENTS.md)를 적용합니다. 각 `CLAUDE.md`는 같은 디렉터리의 `AGENTS.md`를 가리킵니다 |
| 산출물 양식 | 플랜·리뷰 [템플릿](./templates/) | 영역 `AGENTS.md`가 요구하는 산출물의 양식만 제공합니다. 규칙을 새로 정의하지 않습니다 |
| 절차 안내 | Jira-GitLab 개발 흐름, Jira 업무 생성 자동화 | 규칙을 실제로 수행하는 순서와 도구 사용법을 설명합니다 |
| 실행 안내 | 각 디렉터리의 `README.md` | 실행, 빌드, 환경 변수, 배포, 상태 확인을 안내합니다. 규칙을 새로 정의하지 않고 규칙 문서를 링크합니다 |

같은 수준의 문서가 서로 다르게 말하면 규칙 문서(코드 규칙, 협업 규칙, AI 작업 절차)가 안내 문서(실행 안내, 절차 안내)보다 우선합니다.
설계·계약 문서와 사용자 지시, Jira 요구사항 사이의 우선순위는 루트 [`AGENTS.md`](../AGENTS.md) 1장을 따릅니다.

5. [기술 결정 기록(ADR)](./adr/README.md)

요구사항 정의서는 기능·비기능 요구사항 목록과 항목별 인수 조건, 미결 사항의 기준 문서입니다.
API 명세는 공통 규약과 도메인별 REST API 계약(요청·응답·오류·처리 규칙·미정 사항)의 기준 문서입니다.
논리 ERD는 PostgreSQL 엔티티·관계와 물리 스키마 전에 결정할 사항을 정리한 문서입니다.
물리 스키마 규칙은 논리 ERD를 PostgreSQL 스키마로 옮길 때의 명명·타입·제약·외래키 삭제 정책과 Flyway 마이그레이션 정책을 정의합니다.
ADR은 아키텍처와 핵심 기술 선택을 결정 1건당 문서 1개로 기록합니다. 데이터 모델·API 규약·제품 정책 결정은 ERD·API 명세·요구사항 정의서에 남깁니다.

Git 컨벤션은 브랜치, 커밋, Merge Request 및 병합 규칙의 기준입니다.
개발 흐름 문서는 Jira 업무 항목을 시작해 GitLab에 병합하기까지의 실제 절차를 설명합니다.
AI 협업 문서는 AI를 활용한 병렬 작업, 로컬 작업 공간 분리 및 충돌 방지 기준을 설명합니다.
Secret 및 환경변수 관리 규칙은 로컬, CI/CD 및 운영 환경에서 설정과 인증정보를 안전하게
관리하는 기준을 설명합니다.
Jira 자동화 문서는 검토된 YAML 계획으로 Jira 업무를 안전하게 생성하는 방법과 스토리 포인트 산정 기준을 설명합니다.
백엔드 역할 분배 문서는 백엔드 3인의 초기 담당 도메인, 공통 기반 선행 원칙과 도메인 간 경계 규칙을 정의합니다. 실제 구현 기여는 [루트 README의 팀 구성](../README.md#9-팀-구성)을 참고합니다.
백엔드 개발 컨벤션은 코드 스타일(Google Java Style AOSP, Spotless), 패키지 구조, 계층별 책임, DTO·Entity·JPA·트랜잭션·예외 처리 규칙을 정의합니다.
