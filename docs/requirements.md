# 요구사항 정의서

FEELM 서비스의 기능·비기능 요구사항과 항목별 인수 조건을 정리한 문서입니다.
Notion 「요구사항 정의서」 데이터베이스(담당 박시현, 상태 검토 중, 최종 편집 2026-08-30)를 내보내 정리했으며,
저장소의 이 문서를 기준 문서로 관리합니다.

## 범례

- **ID**: `FR-nn` 기능 요구사항, `NFR-nn` 비기능 요구사항. FR-29는 사용하지 않는 번호입니다.
- **단계**: `1차 MVP` → `2차 MVP` → `확장` 순으로 구현합니다.
- **영역**: `Backend`, `Web`, `AI`, `Data`, `Infra`
- **화면**: `README.md` 와이어프레임 번호(①~⑫)를 가리킵니다.
- **※**: 요구사항 통합본에 근거가 없어 FR 문장에서 도출한 인수 조건입니다. 팀 확인이 필요합니다.
- 모든 항목의 진행 상태는 현재 `미착수`입니다. 진행 상태는 Jira에서 관리합니다.

## 3. 기능 요구사항 상세

### FR-01 이메일 회원가입·로그인

사용자는 이메일 계정으로 회원가입, 로그인, 로그아웃을 할 수 있어야 한다.

**인수 조건**

- [ ] 이메일·비밀번호·닉네임·나이·성별을 입력해 가입을 요청할 수 있다
- [ ] 이메일 인증을 마쳐야 계정이 활성화되고 로그인할 수 있다
- [ ] 이미 가입된 이메일로는 새 계정을 만들 수 없다
- [ ] 다른 사용자와 같은 닉네임(공백·대소문자 무시)은 사용할 수 없다
- [ ] 실명은 수집하지 않는다
- [ ] ※ 로그아웃 시 인증 세션이 종료된다

### FR-02 초기 취향 설정

최초 가입 시 영화 카드의 거리 기반 좋아요·싫어요로 초기 취향을 설정할 수 있어야 한다.

**인수 조건**

- [ ] 카드를 거리 기반으로 밀어 LIKE/DISLIKE를 선택하고 명시적으로 선택한 값만 저장한다
- [ ] 카드를 제외하면 취향값 없이 목록에서만 제거한다
- [ ] `차차 찾아갈래요`로 초기 설정 전체를 건너뛸 수 있다
- [ ] 온보딩 LIKE/DISLIKE는 감상 후 평가(0.5~5.0점, 0.5점 단위)와 구분해 저장한다

### FR-03 OTT 설정

사용자는 구독 중인 OTT를 설정하고 변경할 수 있어야 한다.

**인수 조건**

- [ ] ※ 온보딩에서 구독 OTT를 복수 선택할 수 있다
- [ ] ※ 설정 화면에서 구독 OTT를 조회·변경할 수 있다

### FR-04 취향 분석

사용자의 평가 데이터를 장르, 국가, 시대, 감독 등의 요소로 분석해야 한다.

**인수 조건**

- [ ] ※ 분석 요소는 최소 장르·국가·시대·감독을 포함한다
- [ ] ※ 평가가 추가·삭제되면 분석 결과에 반영된다

### FR-10 취향 기반 추천

사용자 데이터를 기반으로 선호 가능성이 높은 영화를 추천해야 한다.

맞춤(`TASTE`)은 이벤트마다 PostgreSQL의 현재 평가·온보딩 선택을 다시 읽어 결정론적으로 계산한다.
같은 영화의 실제 별점은 온보딩 선택보다 우선하며, 온보딩 LIKE/DISLIKE는 DB 별점으로 저장하지
않고 ALS Fold-in adapter의 확정값으로만 사용한다. 서로 다른 유효 입력 영화 수와 관계없이 가용한
ALS·콘텐츠 성분으로 후보를 계산하고, 한 성분 이상이 점수를 낼 수 있을 때 각 지원 모집단의 백분위를
결합해 최대 500편을 게시한다. 콘텐츠 산출물은 선택 사항이며, 설정하지 않으면 ALS만 사용한다. 입력이
없거나 두 성분 모두 사용자 프로필을 만들 수 없으면 서비스 가능한 영화에 모두 `0.0`을 부여하고
`movieId` 오름차순의 동점 후보를 게시한다.

발견(`DISCOVERY`)은 439의 고정 8×128 내부 영화 그룹 결과를 먼저 사용하되 항상 최대 100편을
게시한다. 그룹 결과가 없거나 100편보다 적으면 TASTE 상위 500편 밖의 후보를 먼저 사용하고, 그래도
부족하면 TASTE와의 중복을 허용해 개인 후보 순서로 채운다. 서비스 가능한 고유 후보가 100편 미만일
때만 그 수만 게시한다.

**인수 조건**

- [ ] 기본 추천은 3편 = 취향 기반 2편 + 취향 발견 1편으로 구성하고 영화마다 추천 유형을 표시한다
- [ ] 취향 발견 후보가 없으면 취향 기반 3편으로 채운다
- [ ] 서비스 가능한 고유 후보가 100편 이상이면 DISCOVERY 후보를 항상 100편 게시한다
- [ ] 서로 다른 유효 입력 영화 수와 관계없이 TASTE 후보를 최대 500편 계산·게시한다. 사용자 프로필을
      만들 수 없으면 서비스 가능한 영화에 `0.0` 동점 점수를 부여하고 `movieId` 오름차순으로 게시한다
- [ ] 실제 별점과 온보딩 선택이 겹치면 실제 별점을 사용하고 온보딩 선택을 별점으로 저장하지 않는다
- [ ] 추천 입력(평가·관심없음 등)이 바뀌지 않으면 같은 결과를 유지한다
- [ ] 감상 기록이 있는 영화는 평가 여부와 무관하게 제외한다
- [ ] 추천 카드에서 관심없음 또는 평가가 발생하면 나머지 노출 카드는 유지하고, 해당 카드의 추천 유형을 서버가 판별해 빈 자리 1편만 보충한다
- [ ] `TASTE`가 비면 다음 `TASTE` 후보를 보충하고, `DISCOVERY`가 비면 다음 `DISCOVERY` 후보를 우선 보충한다. 사용 가능한 `DISCOVERY` 후보가 없으면 `TASTE` 후보로 보충해 3편을 모두 취향 기반 추천으로 구성한다
- [ ] 보충된 `TASTE`는 기존 유효한 `TASTE` 뒤, `DISCOVERY` 앞에 배치한다. 예를 들어 `A(TASTE), B(TASTE), X(DISCOVERY)`에서 A가 빠지면 `B, C, X` 순서가 된다
- [ ] 보충 가능한 후보가 없으면 현재 유효한 카드를 다른 카드로 교체하거나 3편을 한꺼번에 추가하지 않고, 추천 버퍼 소진 및 새 세트 생성 흐름에서 처리한다

**검증**

- [ ] NDCG@10
- [ ] Recall@10
- [ ] 베타테스트 만족도

활성 파티의 파티원 팝콘 정보를 한 화면에서 볼 수 있어야 한다.

**인수 조건**

- [ ] 실행 시 팝콘 기계에 넣고 터지는 애니메이션 뒤 결과를 표시한다
- [ ] `PRIVATE` 멤버도 같은 활성 파티의 현재 멤버에게 팝콘 집계를 공개한다. 개별 필름·프레임·평가의 공개 범위는 확대하지 않는다
- [ ] 팝콘 공유·추가 비교 분석은 범위에 포함하지 않는다

### FR-22 파티 영화 추천

파티원들의 취향을 고려해 함께 보기 좋은 영화를 추천해야 한다.

**검증**

- [ ] Average·Least Misery 대비 최저 만족도 상승
- [ ] 사용자 간 만족도 편차 감소
- [ ] 평균 만족도 유지 이상
- [ ] ※ 실제 파티 대상 만족도 확인

### FR-23 반기 취향 리포트

반기마다 감상·취향 변화를 분석한 리포트 하나를 제공해야 한다.

**인수 조건**

- [ ] 장르·배우·감독·나와 맞는 캐릭터 카드와 기타 상세 정보를 포함한다
- [ ] ※ 반기당 리포트는 하나다

### FR-24 리포트 공유

반기 취향 리포트를 이미지 카드로 저장·공유할 수 있어야 한다.

- 비고: 다운로드 URL 유효시간 미정 (운영 보안 정책)

**인수 조건**

- [ ] 파일 형식은 PNG이며 PDF는 제공하지 않는다
- [ ] 저장된 PNG는 비공개로 보관하고 짧은 유효기간의 다운로드 URL로만 접근한다

### FR-25 공개 프로필

공개 설정한 사용자의 필름과 팝콘을 다른 사용자가 조회하고 취향을 비교할 수 있어야 한다.

**인수 조건**

- [ ] `PUBLIC` 사용자의 닉네임·프로필 요약·필름·팝콘·공개 평가는 비회원도 조회할 수 있다
- [ ] `PRIVATE`이면 프로필·필름·팝콘과 프로필의 평가 목록은 본인만 조회할 수 있다. 단, 영화별 한줄평(API-032)에서 `PUBLIC`으로 작성한 한줄평은 FR-26에 따라 다른 로그인 회원에게 노출된다
- [ ] 취향 비교는 로그인 사용자만 `PUBLIC` 사용자를 대상으로 수행한다
- [ ] 차단 관계에서는 노출하지 않는다 (→ FR-39)

### FR-26 한줄평

영화별 한줄평을 작성·수정·삭제하고 공개 한줄평을 다른 사용자에게 노출해야 한다.

- 비고: 2차 → 1차 이동 (팀 결정 2026-08-28). 입력은 FR-19와 공유

**인수 조건**

- [ ] 한줄평은 평가(FR-19)의 선택 항목으로 작성·수정·삭제한다
- [ ] 다른 사용자에게는 `PUBLIC` 한줄평만 노출한다
- [ ] 작성자 프로필이 `PRIVATE`여도 `PUBLIC` 한줄평은 영화별 목록에 노출한다. 작성자의 비공개 프로필은 본인 외 접근할 수 없다
- [ ] `ACTIVE` 회원만 Access Token으로 한줄평을 조회할 수 있고, 양방향 차단 상대의 한줄평은 제외한다
- [ ] 한줄평에 대한 댓글은 범위에서 제외한다

### FR-27 급상승 영화

최근 전체 사용자의 영화 조회 추이를 실시간 집계해 급상승 영화를 제공해야 한다.

- 비고: Python Fold-in과 분리된 Spark Structured Streaming 집계로 처리한다(ADR-0017). 세부 집계 기준은 미정이다

**인수 조건**

- [ ] 여러 사용자의 영화 조회 이벤트를 Spark Structured Streaming으로 집계한다
- [ ] 집계 결과를 급상승 영화 목록으로 제공한다
- [ ] ※ 집계 윈도우·중복 처리·최소 사용자 수·점수식·반영 지연 확정 후 상세 작성

### FR-28 사용자 랭킹

팝콘 수와 새로운 맛 발견 횟수 등을 기준으로 사용자 랭킹을 제공해야 한다.

- 비고: 랭킹 기준·집계 주기 미정

**인수 조건**

- [ ] ※ 랭킹 기준과 집계 주기 확정 후 작성

### FR-30 오늘의 영화

날씨, 계절, 기념일, 최근 트렌드 등 외부 요소를 반영해 하루 한 편을 추천할 수 있어야 한다.

- 비고: 외부 데이터 소스 미정

**인수 조건**

- [ ] ※ 외부 데이터 소스 확정 후 작성

### FR-31 커뮤니티

사용자가 감상 의견과 추천을 공유할 수 있어야 한다.

- 비고: 범위 미정

**인수 조건**

- [ ] ※ 범위 확정 후 작성

### FR-32 발견 표시

새로운 맛의 팝콘이 버킷에 추가되면 해당 위치에 새로운 취향 발견임을 표시해야 한다.

- 비고: 통합본 ID FP-32를 FR-32로 정정 (확인 필요)

**인수 조건**

- [ ] `발견`은 새로운 맛의 영화를 감상하고 평가한 경우에만 성립한다 (조회·클릭·시청 의도는 불충분)

### FR-33 추천 이력

추천받은 영화 이력을 최신순으로 조회할 수 있어야 한다.

**인수 조건**

- [ ] 추천 세트마다 추천 시각·추천 유형·추천 이유·당시 후보를 함께 저장한다
- [ ] 최신순으로 조회한다

### FR-34 영화 상세

영화 상세에 시놉시스, OTT 제공처·바로가기, 공개 한줄평, 평균 별점을 표시해야 한다.

**인수 조건**

- [ ] 추천 경로로 진입하면 추천 이유를 추가 표시한다
- [ ] 비회원도 비개인화 상세 정보를 조회할 수 있다
- [ ] 차단 관계인 사용자의 평가·한줄평은 표시하지 않는다 (→ FR-39)
- [ ] AI 영화 요약은 범위에서 제외한다

### FR-35 소셜 회원가입·로그인

Google·Kakao·Naver 계정으로 회원가입·로그인할 수 있어야 한다.

- 비고: 신규 — 통합본 AR-02 승격

**인수 조건**

- [ ] 연결된 사용자가 없는 소셜 계정이면 닉네임·나이·성별을 입력해 새 계정을 만든다
- [ ] 이미 연결된 소셜 계정이면 해당 사용자로 로그인한다
- [ ] 같은 이메일의 기존 계정을 자동으로 통합하지 않는다
- [ ] 로그인 후 설정에서 기존 계정에 소셜 계정을 연결할 수 있다

### FR-36 관심없음

추천된 영화를 관심없음으로 표시해 이후 추천에서 제외할 수 있어야 한다.

- 비고: 신규 — 통합본 AR-07.4 승격

**인수 조건**

- [ ] 관심없음 영화는 이후 추천에서 제외한다
- [ ] 같은 추천 유형의 새 후보 1편으로 즉시 교체한다
- [ ] 관심없음은 평가가 아니며 평가와 분리해 저장한다

### FR-37 계정 관리

비밀번호 복구·변경과 회원 탈퇴를 할 수 있어야 한다.

- 비고: 신규 — 통합본 AR-04.1~4.3 승격

**인수 조건**

- [ ] 이메일 확인 절차를 거쳐 비밀번호를 재설정할 수 있다
- [ ] 로그인한 이메일 계정은 본인 확인 후 비밀번호를 변경할 수 있다
- [ ] 탈퇴는 연결된 모든 로그인 수단(이메일·소셜)에 적용된다

### FR-38 프로필·설정

프로필, 공개 범위, 알림 설정을 조회·변경할 수 있어야 한다.

- 비고: 신규 — 통합본 AR-04.4~4.6 승격. 알림 발송 기능 FR 부재 → 확인 필요

**인수 조건**

- [ ] 닉네임 등 프로필 값을 조회·변경할 수 있다 (닉네임 중복 규칙은 FR-01과 동일)
- [ ] 프로필 공개 범위는 `PRIVATE/PUBLIC`이며 기본값은 `PRIVATE`다
- [ ] 평가·추천·마케팅 알림 설정을 조회·변경할 수 있다

### FR-39 사용자 차단

다른 사용자를 차단·해제할 수 있어야 하며, 차단 관계에서는 서로의 콘텐츠가 노출되지 않아야 한다.

- 비고: 신규 — 통합본 AR-09.2~9.5 승격. 화면 미정
- 비고: 차단 등록·해제·목록(API-020~022)과 사용자 검색의 상호 제외(API-019)는 구현됐고, 공동 파티 탈퇴와 파티장 승계·종료(아래 2·4행)는 미구현이다. 파티 인원 규칙은 FR-20을 따르며 차단의 파티 연계 구현 시 함께 적용한다

**인수 조건**

- [ ] 차단하고 해제할 수 있다
- [ ] 차단자는 파티장 여부와 관계없이 상대와 함께 속한 모든 활성 파티에서 탈퇴한다. 파티장 승계·인원 부족 종료는 FR-20을 따른다
- [ ] 차단 전에 공동 파티 탈퇴와 파티장 변경·종료 가능성을 안내한다
- [ ] 차단 저장과 공동 파티 탈퇴·승계·종료는 함께 성공하거나 함께 취소된다
- [ ] 한쪽이라도 차단한 관계는 같은 활성 파티에 합류할 수 없다. 초대·수락 시 대상과 현재 파티원 전원의 양방향 차단 관계를 검사한다
- [ ] 차단 해제만으로 탈퇴한 파티에 복귀하거나 무효화된 초대를 복원하지 않는다
- [ ] 사용자 검색과 파티 초대 후보에서 서로 제외한다
- [ ] 프로필·필름·팝콘을 서로에게 노출하지 않는다
- [ ] 영화 상세의 평가·한줄평 등 작성자 콘텐츠를 서로에게 노출하지 않는다

### FR-40 OTT 구독 추천

개인 추천 후보 중 시청 가능한 미감상 영화가 많은 순으로 OTT를 추천하고 OTT별 대표 영화를 함께 제시해야 한다.

- 비고: 첫 버전은 Redis TASTE 후보 최대 500편 전체를 사용한다. 후보 밖 영화는 집계하지 않으며 취향 입력 0건의 동점 후보도 포함한다. 인기 기반 개선은 S15P21E106-483 이후 연동한다

**인수 조건**

- [ ] OTT별로 Redis TASTE 추천 후보 최대 500편에 속한 시청 가능 미감상 영화 수를 집계해 순위를 제공한다
- [ ] 실제 감상·평가한 영화, 만료되지 않은 OTT 링크 클릭 영화와 관심없음 영화는 집계에서 제외한다. 만료된 링크 클릭 기록만 있으면 포함한다 (→ FR-18, FR-36)
- [ ] OTT마다 후보 점수 상위 대표 영화 최대 3편을 함께 제공하며, 점수를 유사도·확률로 표시하지 않는다
- [ ] ※ 순위는 절대 편수 기준이며 카탈로그 크기로 정규화하지 않는다 (구독 효용 판단이 목적)
