# 요구사항 정의서

FEELM 서비스의 기능·비기능 요구사항과 항목별 인수 조건을 정리한 문서입니다.
Notion 「요구사항 정의서」 데이터베이스(담당 박시현, 상태 검토 중, 최종 편집 2026-08-30)를 내보내 정리했으며,
저장소의 이 문서를 기준 문서로 관리합니다.

## 범례

- **ID**: `FR-nn` 기능 요구사항, `NFR-nn` 비기능 요구사항. FR-29는 사용하지 않는 번호입니다.
- **단계**: `1차 MVP` → `2차 MVP` → `확장` 순으로 구현합니다.
- **영역**: `Backend`, `Web`, `AI`, `Data`, `Infra`
- **화면**: `README.md` 와이어프레임 번호(①~⑫)를 가리킵니다.
- **※**: 요구사항 통합본에 근거가 없어 FR 문장에서 도출한 인수 조건입니다. 팀 확인이 필요합니다.
- 모든 항목의 진행 상태는 현재 `미착수`입니다. 진행 상태는 Jira에서 관리합니다.

## 3. 기능 요구사항 상세

### FR-01 이메일 회원가입·로그인

사용자는 이메일 계정으로 회원가입, 로그인, 로그아웃을 할 수 있어야 한다.

**인수 조건**

- [ ] 가입할 이메일로 인증번호를 받아 확인할 수 있다
- [ ] 인증번호 확인을 마쳐야 가입을 완료할 수 있다
- [ ] 비밀번호·닉네임·나이·성별을 입력해 가입을 완료할 수 있다
- [ ] 가입이 끝난 계정은 별도 활성화 단계 없이 즉시 로그인 상태가 된다
- [ ] 이미 가입된 이메일로는 새 계정을 만들 수 없다
- [ ] 다른 사용자와 같은 닉네임(공백·대소문자 무시)은 사용할 수 없다
- [ ] 실명은 수집하지 않는다
- [ ] ※ 로그아웃 시 인증 세션이 종료된다

### FR-02 초기 취향 설정

### FR-10 취향 기반 추천

사용자 데이터를 기반으로 선호 가능성이 높은 영화를 추천해야 한다.

맞춤(`TASTE`)은 `RATING`·`ONBOARDING`·`DISMISS` 이벤트마다 PostgreSQL의 현재 `ratings`와
`user_movie_dismissals`를 다시 읽어 결정론적으로 계산한다. 세 이벤트는 모두 사용자 추천 재계산 신호이며 payload 자체는 계산 입력으로
쓰지 않는다. 온보딩 LIKE/DISLIKE는 Backend가 각각 4.0점·2.0점 평가로 저장하므로(→ FR-02)
다른 평가와 같은 원천으로 처리한다. `onboarding_preferences`는 화면·감사 기록으로 유지하지만
Consumer가 직접 조회하지 않는다. 실제 평가가 없는 관심없음은 계산 시점에만 버전이 있는 설정의
1.0점의 DISMISS 기반 가상 평점 입력으로 사용하고, 같은 영화의 실제 평가를 우선하며 `ratings`에는
저장하지 않는다.
서로 다른 유효 입력
영화 수와 관계없이 가용한 ALS·콘텐츠 성분으로 후보를 계산하고, 한 성분 이상이 점수를 낼 수 있을 때 각 지원 모집단의 백분위를
결합해 최대 500편을 게시한다. 콘텐츠 산출물은 선택 사항이며, 설정하지 않으면 ALS만 사용한다. 입력이
없거나 두 성분 모두 사용자 프로필을 만들 수 없으면 서비스 가능한 영화에 모두 `0.0`을 부여하고
`movieId` 오름차순의 동점 후보를 게시한다.

발견(`DISCOVERY`)은 439의 고정 8×128 내부 영화 그룹 결과를 먼저 사용하되 항상 최대 100편을
게시한다. 상위 10개 그룹에서 그룹별 10편을 먼저 고르고 부족하면 같은 그룹들의 11위, 12위 순으로
층별 확장한다. 상위 10개 그룹을 모두 소진해도 부족하면 11번째 이후 적격 그룹을 적합도 순으로
하나씩 소진한다. 그룹 결과가 없으면 빈 배열, 모든 적격 그룹 후보가 소진되면 100편 미만을 게시하며
전체 개인화 모집단으로 보충하지 않는다.

**인수 조건**

- [ ] 모바일 기본 추천은 3편 = 취향 기반 2편 + 취향 발견 1편, PC 기본 추천은 6편 = 취향 기반 3편 + 취향 발견 3편으로 구성하고 영화마다 추천 유형을 표시한다
- [ ] 취향 발견 후보가 화면별 목표보다 적으면 부족한 슬롯마다 취향 기반 후보로 채워 요청한 편수까지 노출한다
- [ ] 모든 적격 DISCOVERY 그룹 후보가 소진되면 100편 미만 게시를 허용한다
- [ ] 서로 다른 유효 입력 영화 수와 관계없이 TASTE 후보를 최대 500편 계산·게시한다. 사용자 프로필을
      만들 수 없으면 서비스 가능한 영화에 `0.0` 동점 점수를 부여하고 `movieId` 오름차순으로 게시한다
- [ ] Fold-in·콘텐츠·DISCOVERY의 사용자 선호 계산 원천은 `ratings`로 단일화한다. 온보딩으로 생성된
      4.0·2.0 평가도 같은 평가 행으로 사용하며 `onboarding_preferences`를 별도 병합하지 않는다 (→ FR-02)
- [ ] 추천 입력(평가·관심없음 등)이 바뀌지 않으면 같은 결과를 유지한다
- [ ] 감상 기록이 있는 영화는 평가 여부와 무관하게 제외한다
- [ ] 평점 이력이 없는 영화(`movies.movielens_id`가 없는 영화)는 추천 순위를 크게 내린다. 제외가 아니라 하향이며 후보가 모자라지 않아야 한다 (팀 결정 2026-09-18, S15P21E106-668)
- [ ] 한국어 제목이 아닌 영화도 같은 방식으로 추천 순위를 내린다 (→ FR-14, S15P21E106-615)
- [ ] 추천 카드에서 관심없음 또는 평가가 발생하면 나머지 노출 카드는 유지하고, 해당 카드의 추천 유형을 서버가 판별해 빈 자리 1편만 보충한다
- [ ] `TASTE`가 비면 다음 `TASTE` 후보를 보충하고, `DISCOVERY`가 비면 다음 `DISCOVERY` 후보를 우선 보충한다. 사용 가능한 `DISCOVERY` 후보가 부족하면 슬롯마다 `TASTE` 후보로 보충해 최대 6편을 구성한다
- [ ] 보충된 `TASTE`는 기존 유효한 `TASTE` 뒤, `DISCOVERY` 앞에 배치한다. 예를 들어 `A(TASTE), B(TASTE), X(DISCOVERY)`에서 A가 빠지면 `B, C, X` 순서가 된다
- [ ] 보충 가능한 후보가 없으면 현재 유효한 카드를 다른 카드로 교체하거나 6편을 한꺼번에 추가하지 않고, 추천 버퍼 소진 및 새 세트 생성 흐름에서 처리한다

**검증**

- [ ] NDCG@10
- [ ] Recall@10
- [ ] 베타테스트 만족도

### FR-12 취향 발견 추천

**인수 조건**

- [ ] 모바일 기본 추천 3편 중 1편, PC 기본 추천 6편 중 3편으로 노출되며 `취향 발견 추천` 유형을 표시한다 (→ FR-10)

- [ ] 한국어 제목이 확인된 영화는 한국어 제목으로 표시하고, 원제로도 검색할 수 있다 (S15P21E106-615)
- [ ] 평점 이력이 없는 영화(`movies.movielens_id`가 없는 영화)와 한국어 제목이 아닌 영화는 검색 순위를 크게 내린다. 제외가 아니라 하향이며 결과가 비지 않아야 한다 (팀 결정 2026-09-18, S15P21E106-614)
- [ ] 검색 홈의 `평점 높은 영화`는 검색어·장르·국가·OTT·종료 연도 없이, 최초 조회의
      한국 기준 연도보다 1 작은 시작 연도만 지정한 API-028 `RATING` 조회다. 최초 조회의
      한국 날짜에 이미 개봉한
      `release_date`가 있는 영화만 포함해 오늘 개봉작은 포함하고 미래 개봉작과 개봉일이
      없는 영화는 제외한다. 최초 기준일은 cursor 페이지에서도 유지한다 (S15P21E106-768)
- [ ] 검색 홈 평점 목록은 평균 평점 내림차순, 평가 수 내림차순, 영화 ID 내림차순으로
      정렬하고 cursor 페이지도 같은 순서를 유지한다. 최소 평가 수 하한은 두지 않으며 다른
      키워드·필터 검색과 추천 목록에는 이 개봉 기준을 적용하지 않는다 (S15P21E106-768)

### FR-19 감상 평가

감상한 영화에 0.5~5.0점 평가(0.5점 단위)와 선택적 한줄평을 남길 수 있어야 한다.

2026-09-07 합의로 [MovieLens 32M 평점 범위와 간격](https://files.grouplens.org/datasets/movielens/ml-32m-README.html)에 맞춘다.

**인수 조건**

- [ ] 점수(0.5~5.0점, 0.5점 단위)는 필수, 한줄평(200자 이하)은 선택이다
- [ ] 허용 점수는 0.5, 1.0, 1.5, 2.0, 2.5, 3.0, 3.5, 4.0, 4.5, 5.0이다. 범위 밖이나 0.5의 배수가 아닌 값은 반올림하지 않고 거절한다
- [ ] 한줄평이 있으면 공개 범위 `PUBLIC/PRIVATE`를 선택한다
- [ ] 평가 저장 시 프레임·팝콘이 생성되고 삭제 시 함께 삭제된다 (→ FR-07, FR-09)
- [ ] ※ 평가를 수정·삭제할 수 있다
- [ ] 평가한 영화 목록은 첫 장에서 끊기지 않고 다음 장을 이어 볼 수 있다 (S15P21E106-611)
- [ ] 평가한 영화 목록에서 영화를 선택하면 영화 상세로 이동한다 (S15P21E106-638)
- [ ] 온보딩에서 선택한 영화는 이미 평가가 있으므로 이후 감상 평가는 새로 만들지 않고 수정한다 (→ FR-02)

### FR-20 파티 생성·초대

함께 볼 영화를 고르기 위한 파티를 만들고 회원을 초대할 수 있어야 한다.

**인수 조건**

- [ ] 파티는 파티장 포함 최대 4명이다
- [ ] 사용자당 참여 가능한 활성 파티는 최대 10개다. 파티 생성과 초대 수락이 동시에 실행되어도 상한을 넘지 않는다
- [ ] 고유 닉네임으로 회원을 검색해 초대한다
- [ ] 초대받은 사용자는 앱 안에서 수락 또는 거절한다
- [ ] 초대는 자동 만료되지 않고, 거절한 사용자에게 재초대할 수 있다
- [ ] 탈퇴·강퇴 후 1명 이상 남으면 기존 파티를 유지한다. 1인 파티도 활성이며 새 멤버를 초대할 수 있고, 마지막 멤버가 탈퇴해 0명이 될 때만 종료한다(API-055)
- [ ] 파티장 탈퇴 시 1명 이상 남으면 가입 시각, 사용자 ID 오름차순으로 파티장을 승계한다
- [ ] 활성 파티의 파티장만 다른 현재 멤버를 강퇴할 수 있다. 본인은 강퇴 대신 탈퇴한다(API-069)
- [ ] 강퇴는 해당 파티의 멤버 자격만 제거한다. 차단을 생성하지 않으며 차단 관계가 없으면 재초대를 허용한다
- [ ] 차단 관계인 사용자는 초대 후보에서 제외한다 (→ FR-39)

### FR-23 반기 취향 리포트

반기마다 감상·취향 변화를 분석한 리포트 하나를 제공해야 한다.

**인수 조건**

- [ ] 장르·배우·감독·나와 맞는 캐릭터 카드와 기타 상세 정보를 포함한다
- [ ] 캐릭터 카드는 고정된 16종 중 하나를 배정한다. 네 개의 축(탐험·정착 / 빛·그림자 / 가슴·머리 / 다작·정독)을 각각 두 값으로 판정한 조합이며 `ELHV` 형태의 4글자 코드로 식별한다. 코드는 불변이고 사용자에게도 노출한다 (→ API-060)
- [ ] 판정은 그 반기 리포트 대상자 전체의 중앙값을 기준으로 한 상대 판정이다. 중앙값은 집계 배치가 한 번 구해 리포트와 함께 스냅샷으로 저장하고 이후 재계산하지 않는다
- [ ] 카드 이름은 보통명사이며 퍼블릭 도메인 원형 인물은 설명문 안에서 비유로만 사용한다. 카드 이름에 상표·2차 창작 리스크를 걸지 않는다
- [ ] 리포트가 생성되는 조건(프레임 3편 이상)을 만족하면 캐릭터 카드도 항상 발급한다. 카드에 별도 하한을 두지 않는다
- [ ] 프레임이 10편 미만이면 소량 표본임을 응답으로 알리고 화면이 기준 편수를 함께 안내한다
- [ ] 이전 반기 카드와의 변화 비교는 이 요구사항의 범위에 포함하지 않는다 (후속 범위)
- [ ] ※ 반기당 리포트는 하나다

- [ ] 서버가 Java2D headless 렌더링으로 공유용 PNG를 생성하며, 기존 파일이 있으면 재사용하고 새 서명 URL만 발급한다

### FR-25 공개 프로필

### FR-26 한줄평

**인수 조건**

- [ ] 다른 사용자에게는 `PUBLIC` 한줄평만 노출한다
- [ ] 작성자 프로필이 `PRIVATE`여도 `PUBLIC` 한줄평은 영화별 목록에 노출한다. 작성자의 비공개 프로필은 본인 외 접근할 수 없다
- [ ] `ACTIVE` 회원만 Access Token으로 한줄평을 조회할 수 있고, 양방향 차단 상대의 한줄평은 제외한다
- [ ] 한줄평에 대한 댓글은 범위에서 제외한다

### FR-27 급상승 영화

최근 로그인 사용자의 영화 상세 조회 추이를 실시간 집계해 급상승 영화를 제공해야 한다.

- 비고: 비회원 상세 조회는 `VIEW` 발행 대상이 아니다. Python Fold-in과 분리된 Spark Structured Streaming 집계로 처리한다(ADR-0017). 최소 조회자 수와 구간 길이는 실측 후 보정할 수 있다

**인수 조건**

- [ ] 유효한 Access Token으로 정상 조회한 회원의 영화 상세 `VIEW`만 집계 입력으로 사용한다. 비회원 조회는 제외한다
- [ ] 여러 사용자의 영화 조회 이벤트를 Spark Structured Streaming으로 집계한다
- [ ] 최근 60분과 직전 60분의 영화별 고유 조회 회원 수를 비교해, 최근 3명 이상이며 증가분이 양수인 영화를 증가분 순으로 최대 30편 게시한다
- [ ] 입력 이벤트가 없어도 UTC 5분 경계마다 집계를 확인한다. 늦게 도착한 `VIEW`는 이벤트 시간 watermark 초기값 10분을 적용해 처리한다
- [ ] 첫 유효한 급상승 목록 전에는 API-064의 고정 초기 10편 A를 정해진 순서로 표시한다. 첫 비어 있지 않은 B부터는 B를 제공한다
- [ ] 이후 빈 집계와 2시간 이상 새 결과가 없는 때에도 마지막 B를 유지한다. 최신 B가 아니면 `stale=true`로 표시한다. 정상 도착한 조회의 10분 이내 결과 게시를 초기 목표로 관측한다
- [ ] Redis 조회 장애로 최신 또는 마지막 정상 급상승 결과(B)를 조회할 수 없고 초기 고정 목록(A)으로 안전하게 대체할 수도 없으면 `503`을 반환한다

### FR-34 영화 상세

영화 상세에 시놉시스, OTT 제공처·바로가기, 공개 한줄평, 평균 별점을 표시해야 한다.

**인수 조건**

- [ ] 추천 경로로 진입하면 추천 이유를 추가 표시한다
- [ ] 비회원도 비개인화 상세 정보를 조회할 수 있다
- [ ] 차단 관계인 사용자의 평가·한줄평은 표시하지 않는다 (→ FR-39)
- [ ] 평균 별점과 평가 인원수는 서비스 평가 집계와 일치한다 (S15P21E106-636)
- [ ] 온보딩 선택으로 생긴 평가도 공개 평균 별점과 평가 인원수에 포함한다 (팀 결정 2026-09-18, → FR-02)
- [ ] 대표 맛이 배정된 영화는 그 영화가 어느 팝콘 맛인지 표시한다 (S15P21E106-631)
- [ ] 한국어 제목이 확인된 영화는 한국어 제목으로 표시한다 (S15P21E106-615)
- [ ] AI 영화 요약은 범위에서 제외한다

### FR-35 소셜 회원가입·로그인

Google·Kakao·Naver 계정으로 회원가입·로그인할 수 있어야 한다.

- 비고: 신규 — 통합본 AR-02 승격

**인수 조건**

- [ ] 연결된 사용자가 없는 소셜 계정이면 닉네임·나이·성별을 입력해 새 계정을 만든다
- [ ] 이미 연결된 소셜 계정이면 해당 사용자로 로그인한다
- [ ] 같은 이메일의 기존 계정을 자동으로 통합하지 않는다
- [ ] 로그인 후 설정에서 기존 계정에 소셜 계정을 연결할 수 있다

### FR-36 관심없음

추천된 영화를 관심없음으로 표시해 이후 추천에서 제외할 수 있어야 한다.

- 비고: 신규 — 통합본 AR-07.4 승격

**인수 조건**

- [ ] 관심없음 영화는 이후 추천에서 제외한다
- [ ] 같은 추천 유형의 새 후보 1편으로 즉시 교체한다
- [ ] 관심없음은 평가가 아니며 평가와 분리해 저장한다

### FR-37 계정 관리

비밀번호 복구·변경과 회원 탈퇴를 할 수 있어야 한다.

- 비고: 신규 — 통합본 AR-04.1~4.3 승격

**인수 조건**

- [ ] 이메일 확인 절차를 거쳐 비밀번호를 재설정할 수 있다
- [ ] 로그인한 이메일 계정은 본인 확인 후 비밀번호를 변경할 수 있다
- [ ] 탈퇴는 연결된 모든 로그인 수단(이메일·소셜)에 적용된다

### FR-38 프로필·설정

프로필, 공개 범위, 알림 설정을 조회·변경할 수 있어야 한다.

- 비고: 신규 — 통합본 AR-04.4~4.6 승격. 실제 인앱 알림과 푸시 전달은 FR-41에서 정의한다

**인수 조건**

- [ ] 닉네임 등 프로필 값을 조회·변경할 수 있다 (닉네임 중복 규칙은 FR-01과 동일)
- [ ] 프로필 공개 범위는 `PRIVATE/PUBLIC`이며 기본값은 `PRIVATE`다
- [ ] 평가·추천·마케팅 알림 설정을 조회·변경할 수 있다

### FR-39 사용자 차단

다른 사용자를 차단·해제할 수 있어야 하며, 차단 관계에서는 서로의 콘텐츠가 노출되지 않아야 한다.

- 비고: 신규 — 통합본 AR-09.2~9.5 승격. 화면 미정
- 비고: 차단 등록·해제·목록(API-020~022)과 사용자 검색의 상호 제외(API-019)는 구현됐고, 공동 파티 탈퇴와 파티장 승계·종료(아래 2·4행)는 미구현이다. 파티 인원 규칙은 FR-20을 따르며 차단의 파티 연계 구현 시 함께 적용한다

**인수 조건**

- [ ] 차단하고 해제할 수 있다
- [ ] 차단자는 파티장 여부와 관계없이 상대와 함께 속한 모든 활성 파티에서 탈퇴한다. 파티장 승계·인원 부족 종료는 FR-20을 따른다
- [ ] 차단 전에 공동 파티 탈퇴와 파티장 변경·종료 가능성을 안내한다
- [ ] 차단 저장과 공동 파티 탈퇴·승계·종료는 함께 성공하거나 함께 취소된다
- [ ] 한쪽이라도 차단한 관계는 같은 활성 파티에 합류할 수 없다. 초대·수락 시 대상과 현재 파티원 전원의 양방향 차단 관계를 검사한다
- [ ] 차단 해제만으로 탈퇴한 파티에 복귀하거나 무효화된 초대를 복원하지 않는다
- [ ] 사용자 검색과 파티 초대 후보에서 서로 제외한다
- [ ] 프로필·필름·팝콘을 서로에게 노출하지 않는다
- [ ] 영화 상세의 평가·한줄평 등 작성자 콘텐츠를 서로에게 노출하지 않는다

### FR-40 OTT 구독 추천

개인 추천 후보 중 시청 가능한 미감상 영화가 많은 순으로 OTT를 추천하고 OTT별 대표 영화를 함께 제시해야 한다.

- 비고: 첫 버전은 Redis TASTE 후보 최대 500편 전체를 사용한다. 후보 밖 영화는 집계하지 않으며 취향 입력 0건의 동점 후보도 포함한다. 인기 기반 개선은 S15P21E106-483 이후 연동한다
- 비고: 화면은 7.8 설정의 `나에게 맞는 OTT 찾기` 배너에서 들어가는 EXT-01 ~ EXT-05다. 취향 일치도 %와 OTT별 추천 이유는 화면에서도 표시하지 않는다(S15P21E106-563)

**인수 조건**

- [ ] OTT별로 Redis TASTE 추천 후보 최대 500편에 속한 시청 가능 미감상 영화 수를 집계해 순위를 제공한다
- [ ] 실제 감상·평가한 영화, 만료되지 않은 OTT 링크 클릭 영화와 관심없음 영화는 집계에서 제외한다. 만료된 링크 클릭 기록만 있으면 포함한다 (→ FR-18, FR-36)
- [ ] OTT마다 후보 점수 상위 대표 영화 최대 3편을 함께 제공하며, 점수를 유사도·확률로 표시하지 않는다
- [ ] ※ 순위는 절대 편수 기준이며 카탈로그 크기로 정규화하지 않는다 (구독 효용 판단이 목적)

### FR-41 인앱 알림·푸시

파티 초대·수락과 감상 확인 알림을 서버에 저장해 여러 세션에서 같은 읽음·숨김 상태를 제공하고, 파티 초대·수락은 브라우저 푸시로 전달할 수 있어야 한다. 감상 확인은 OTT 클릭 24시간 후 앱 진입 시 인앱 알림으로 노출한다.

- 비고: 1차 MVP의 도메인 API 폴링(ADR-0011)을 2차 알림 정본으로 전환한다. 푸시 발송·구독은 S15P21E106-582, 프론트 API·서비스 워커 연동은 S15P21E106-583에서 구현한다

**인수 조건**

- [ ] 파티 초대·수락과 감상 확인 대상이 중복 없이 인앱 알림으로 저장된다
- [ ] 사용자는 최신순 알림 목록과 미확인 개수를 조회하고 개별·전체 읽음 및 개별 숨김 처리할 수 있다
- [ ] 읽음·숨김 상태는 새로고침과 재로그인 후에도 유지된다
- [ ] 원본 업무가 완료되거나 노출 기간이 지나면 알림 목록·미확인 개수에서 제외된다
- [ ] 알림 생성은 파티 초대·감상 기록 저장과 함께 성공하거나 함께 취소된다
- [ ] 파티 초대·수락 푸시는 클릭 시 대상 화면으로 이동하며, 감상 확인은 Web Push로 발송하지 않는다
- [ ] 브라우저별 구독은 등록·갱신·해제할 수 있고 해제·만료·탈퇴 시 endpoint와 암호화 키를 제거한다
- [ ] 발송은 알림·endpoint 조합당 한 번만 대기열에 넣고 일시 오류를 최대 5회 재시도하며 영구 만료 구독을 정리한다
