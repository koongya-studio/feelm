# 요구사항 정의서

FEELM 서비스의 기능·비기능 요구사항과 항목별 인수 조건을 정리한 문서입니다.
Notion 「요구사항 정의서」 데이터베이스(담당 박시현, 상태 검토 중, 최종 편집 2026-08-30)를 내보내 정리했으며,
저장소의 이 문서를 기준 문서로 관리합니다.

## 범례

- **ID**: `FR-nn` 기능 요구사항, `NFR-nn` 비기능 요구사항. FR-29는 사용하지 않는 번호입니다.
- **단계**: `1차 MVP` → `2차 MVP` → `확장` 순으로 구현합니다.
- **영역**: `Backend`, `Web`, `AI`, `Data`, `Infra`
- **화면**: `README.md` 와이어프레임 번호(①~⑫)를 가리킵니다.
- **※**: 요구사항 통합본에 근거가 없어 FR 문장에서 도출한 인수 조건입니다. 팀 확인이 필요합니다.
- 모든 항목의 진행 상태는 현재 `미착수`입니다. 진행 상태는 Jira에서 관리합니다.

## 3. 기능 요구사항 상세

### FR-01 이메일 회원가입·로그인

사용자는 이메일 계정으로 회원가입, 로그인, 로그아웃을 할 수 있어야 한다.

**인수 조건**

- [ ] 이메일·비밀번호·닉네임·나이·성별을 입력해 가입을 요청할 수 있다
- [ ] 이메일 인증을 마쳐야 계정이 활성화되고 로그인할 수 있다
- [ ] 이미 가입된 이메일로는 새 계정을 만들 수 없다
- [ ] 다른 사용자와 같은 닉네임(공백·대소문자 무시)은 사용할 수 없다
- [ ] 실명은 수집하지 않는다
- [ ] ※ 로그아웃 시 인증 세션이 종료된다

### FR-02 초기 취향 설정

최초 가입 시 영화 카드의 거리 기반 좋아요·싫어요로 초기 취향을 설정할 수 있어야 한다.

**인수 조건**

- [ ] 카드를 거리 기반으로 밀어 LIKE/DISLIKE를 선택하고 명시적으로 선택한 값만 저장한다
- [ ] 카드를 제외하면 취향값 없이 목록에서만 제거한다
- [ ] `차차 찾아갈래요`로 초기 설정 전체를 건너뛸 수 있다
- [ ] 온보딩 LIKE/DISLIKE는 감상 후 평가(0.5~5.0점, 0.5점 단위)와 구분해 저장한다

### FR-03 OTT 설정

사용자는 구독 중인 OTT를 설정하고 변경할 수 있어야 한다.

**인수 조건**

- [ ] ※ 온보딩에서 구독 OTT를 복수 선택할 수 있다
- [ ] ※ 설정 화면에서 구독 OTT를 조회·변경할 수 있다

### FR-04 취향 분석

사용자의 평가 데이터를 장르, 국가, 시대, 감독 등의 요소로 분석해야 한다.

**인수 조건**

- [ ] ※ 분석 요소는 최소 장르·국가·시대·감독을 포함한다
- [ ] ※ 평가가 추가·삭제되면 분석 결과에 반영된다

### FR-05 취향 키워드 추출

FR-04의 분석 수치를 사전 정의된 취향 키워드로 변환해 제공해야 한다.

**인수 조건**

- [ ] 키워드는 사전 정의된 목록에서만 선택된다
- [ ] 사용자당 3~5개를 제공한다

### FR-06 팝콘 버킷 시각화

사용자의 취향 분포를 8개 팝콘 맛으로 시각화해야 한다.

- 비고: 팝콘 맛은 E5 영화 임베딩을 K-Means로 분류한 8개 취향 유형을 사용한다(ADR-0015). 8개 맛을 모두 표시하며 평가 영화가 없는 맛은 0개로 표시한다

**인수 조건**

- [ ] 맛별 팝콘 수(감상량)와 맛 선호도(평균 평점)를 구분해 표시한다
- [ ] 8개 맛은 기준정보(불변 코드·표시명·색상·대표 키워드)를 따르며 표시명·색상은 변경할 수 있다
- [ ] 취향 발견 추천의 `새로운 맛` 판정은 팝콘 수 임계값을 사용하지 않고 FR-12의 별도 기준으로 정의한다

### FR-07 프레임 생성

감상 확인과 평가를 완료하면 해당 영화의 프레임을 생성해 필름에 추가해야 한다.

**인수 조건**

- [ ] 최초 평가 저장 시 프레임을 생성하고 필름에 추가한다
- [ ] 링크 클릭·감상 확인만으로는 프레임을 생성하지 않는다
- [ ] 평가 삭제 시 해당 프레임을 삭제한다

### FR-08 프레임 상세 조회

필름의 프레임을 선택해 영화 정보, 평가, 감상 기록을 확인할 수 있어야 한다.

**인수 조건**

- [ ] ※ 프레임 선택 시 영화 정보·내 평점·한줄평·감상 시점을 표시한다

### FR-09 팝콘 생성

감상 확인과 평가를 완료하면 해당 영화의 대표 맛에 팝콘 1알을 추가해야 한다.

**인수 조건**

- [ ] 팝콘은 프레임과 1:1 대응하며 프레임 없이 존재하지 않는다
- [ ] 최초 평가 저장 시 팝콘을 추가하고 취향 집계에 반영한다
- [ ] 평가 삭제 시 팝콘을 삭제하고 집계에서 제거한다
- [ ] 영화는 K-Means 취향 군집으로 배정된 대표 맛 하나에만 팝콘이 추가된다

### FR-10 취향 기반 추천

사용자 데이터를 기반으로 선호 가능성이 높은 영화를 추천해야 한다.

맞춤(`TASTE`)은 사용자 평가·온보딩 선호를 반영한 개인 기본 순위로 생성한다. 발견(`DISCOVERY`)은
향후 K-Means 영화 군집을 기반으로 별도 선정한다. 군집 산출물과 선정 정책이 준비되기 전에는
발견 슬롯을 맞춤으로 채운다.

**인수 조건**

- [ ] 기본 추천은 3편 = 취향 기반 2편 + 취향 발견 1편으로 구성하고 영화마다 추천 유형을 표시한다
- [ ] 취향 발견 후보가 없으면 취향 기반 3편으로 채운다
- [ ] 추천 입력(평가·관심없음 등)이 바뀌지 않으면 같은 결과를 유지한다
- [ ] 감상 기록이 있는 영화는 평가 여부와 무관하게 제외한다
- [ ] `추가 영화 추천`으로 현재 결과를 유지한 채 같은 구성 규칙의 3편을 추가한다

**검증**

- [ ] NDCG@10
- [ ] Recall@10
- [ ] 베타테스트 만족도

### FR-11 유사 영화 추천

**인수 조건**

- [ ] 영화 상세 화면에서 제공한다
- [ ] ※ 기준 영화 자체는 결과에 포함하지 않는다

### FR-12 취향 발견 추천

기존 취향과 연결되면서 새로운 맛에 속하는 영화를 추천해야 한다.

- 비고: 정식 명칭 취향 발견 추천 (팀 결정 2026-08-28). 탐험 추천 사용하지 않음

**인수 조건**

- [ ] K-Means 취향 군집을 기반으로 기존 취향과 연결되면서 새로운 맛인 후보를 고른다
- [ ] K-Means 군집을 사용할 DISCOVERY 선정 방식과 기준값은 합의 후 적용한다. `팝콘 수 < 임계치`는 검토 후보이며 확정 규칙이 아니다
- [ ] 기본 추천 3편 중 1편으로 노출되며 `취향 발견 추천` 유형을 표시한다 (→ FR-10)
- [ ] 감상 기록이 있는 영화는 제외한다

### FR-13 추천 설명(XAI)

링크 클릭 2일 후 접속 시 감상 여부를 확인하고 상태를 전이해야 한다.

**인수 조건**

- [ ] 감상하지 않았다고 답하거나 7일까지 응답이 없으면 만료 처리한다
- [ ] 만료는 추천 신호로 사용하지 않는다
- [ ] 평가는 감상 확인 즉시가 아니라 나중에도 남길 수 있다
- [ ] 평가를 삭제해도 감상 이력은 `감상 완료(평가 전)`으로 유지된다

### FR-19 감상 평가

감상한 영화에 0.5~5.0점 평가(0.5점 단위)와 선택적 한줄평을 남길 수 있어야 한다.

2026-09-07 합의로 [MovieLens 32M 평점 범위와 간격](https://files.grouplens.org/datasets/movielens/ml-32m-README.html)에 맞춘다.

**인수 조건**

- [ ] 사용자·영화 조합마다 평가는 하나다
- [ ] 점수(0.5~5.0점, 0.5점 단위)는 필수, 한줄평(200자 이하)은 선택이다
- [ ] 허용 점수는 0.5, 1.0, 1.5, 2.0, 2.5, 3.0, 3.5, 4.0, 4.5, 5.0이다. 범위 밖이나 0.5의 배수가 아닌 값은 반올림하지 않고 거절한다
- [ ] 한줄평이 있으면 공개 범위 `PUBLIC/PRIVATE`를 선택한다
- [ ] 평가 저장 시 프레임·팝콘이 생성되고 삭제 시 함께 삭제된다 (→ FR-07, FR-09)
- [ ] ※ 평가를 수정·삭제할 수 있다

### FR-20 파티 생성·초대

함께 볼 영화를 고르기 위한 파티를 만들고 회원을 초대할 수 있어야 한다.

**인수 조건**

- [ ] 파티는 파티장 포함 최대 4명이다
- [ ] 사용자당 참여 가능한 활성 파티는 최대 10개다. 파티 생성과 초대 수락이 동시에 실행되어도 상한을 넘지 않는다
- [ ] 고유 닉네임으로 회원을 검색해 초대한다
- [ ] 초대받은 사용자는 앱 안에서 수락 또는 거절한다
- [ ] 초대는 자동 만료되지 않고, 거절한 사용자에게 재초대할 수 있다
- [ ] 탈퇴·강퇴 후 1명 이상 남으면 기존 파티를 유지한다. 1인 파티도 활성이며 새 멤버를 초대할 수 있고, 마지막 멤버가 탈퇴해 0명이 될 때만 종료한다(API-055)
- [ ] 파티장 탈퇴 시 1명 이상 남으면 가입 시각, 사용자 ID 오름차순으로 파티장을 승계한다
- [ ] 활성 파티의 파티장만 다른 현재 멤버를 강퇴할 수 있다. 본인은 강퇴 대신 탈퇴한다(API-069)
- [ ] 강퇴는 해당 파티의 멤버 자격만 제거한다. 차단을 생성하지 않으며 차단 관계가 없으면 재초대를 허용한다
- [ ] 차단 관계인 사용자는 초대 후보에서 제외한다 (→ FR-39)

### FR-21 파티원들의 팝콘 보기

활성 파티의 파티원 팝콘 정보를 한 화면에서 볼 수 있어야 한다.

**인수 조건**

- [ ] 실행 시 팝콘 기계에 넣고 터지는 애니메이션 뒤 결과를 표시한다
- [ ] `PRIVATE` 멤버도 같은 활성 파티의 현재 멤버에게 팝콘 집계를 공개한다. 개별 필름·프레임·평가의 공개 범위는 확대하지 않는다
- [ ] 팝콘 공유·추가 비교 분석은 범위에 포함하지 않는다

- [ ] `발견`은 새로운 맛의 영화를 감상하고 평가한 경우에만 성립한다 (조회·클릭·시청 의도는 불충분)

### FR-33 추천 이력

추천받은 영화 이력을 최신순으로 조회할 수 있어야 한다.

**인수 조건**

- [ ] 추천 세트마다 추천 시각·추천 유형·추천 이유·당시 후보를 함께 저장한다
- [ ] 최신순으로 조회한다

### FR-34 영화 상세

영화 상세에 시놉시스, OTT 제공처·바로가기, 공개 한줄평, 평균 별점을 표시해야 한다.

**인수 조건**

- [ ] 추천 경로로 진입하면 추천 이유를 추가 표시한다
- [ ] 비회원도 비개인화 상세 정보를 조회할 수 있다
- [ ] 차단 관계인 사용자의 평가·한줄평은 표시하지 않는다 (→ FR-39)
- [ ] AI 영화 요약은 범위에서 제외한다

### FR-35 소셜 회원가입·로그인

Google·Kakao·Naver 계정으로 회원가입·로그인할 수 있어야 한다.

- 비고: 신규 — 통합본 AR-02 승격

**인수 조건**

- [ ] 연결된 사용자가 없는 소셜 계정이면 닉네임·나이·성별을 입력해 새 계정을 만든다
- [ ] 이미 연결된 소셜 계정이면 해당 사용자로 로그인한다
- [ ] 같은 이메일의 기존 계정을 자동으로 통합하지 않는다
- [ ] 로그인 후 설정에서 기존 계정에 소셜 계정을 연결할 수 있다

### FR-36 관심없음

추천된 영화를 관심없음으로 표시해 이후 추천에서 제외할 수 있어야 한다.

- 비고: 신규 — 통합본 AR-07.4 승격

**인수 조건**

- [ ] 관심없음 영화는 이후 추천에서 제외한다
- [ ] 같은 추천 유형의 새 후보 1편으로 즉시 교체한다
- [ ] 관심없음은 평가가 아니며 평가와 분리해 저장한다

### FR-37 계정 관리

비밀번호 복구·변경과 회원 탈퇴를 할 수 있어야 한다.

- 비고: 신규 — 통합본 AR-04.1~4.3 승격

**인수 조건**

- [ ] 이메일 확인 절차를 거쳐 비밀번호를 재설정할 수 있다
- [ ] 로그인한 이메일 계정은 본인 확인 후 비밀번호를 변경할 수 있다
- [ ] 탈퇴는 연결된 모든 로그인 수단(이메일·소셜)에 적용된다

### FR-38 프로필·설정

프로필, 공개 범위, 알림 설정을 조회·변경할 수 있어야 한다.

- 비고: 신규 — 통합본 AR-04.4~4.6 승격. 알림 발송 기능 FR 부재 → 확인 필요

**인수 조건**

- [ ] 닉네임 등 프로필 값을 조회·변경할 수 있다 (닉네임 중복 규칙은 FR-01과 동일)
- [ ] 프로필 공개 범위는 `PRIVATE/PUBLIC`이며 기본값은 `PRIVATE`다
- [ ] 평가·추천·마케팅 알림 설정을 조회·변경할 수 있다

### FR-39 사용자 차단

다른 사용자를 차단·해제할 수 있어야 하며, 차단 관계에서는 서로의 콘텐츠가 노출되지 않아야 한다.

- 비고: 신규 — 통합본 AR-09.2~9.5 승격. 화면 미정
- 비고: 차단 등록·해제·목록(API-020~022)과 사용자 검색의 상호 제외(API-019)는 구현됐고, 공동 파티 탈퇴와 파티장 승계·종료(아래 2·4행)는 미구현이다. 파티 인원 규칙은 FR-20을 따르며 차단의 파티 연계 구현 시 함께 적용한다

**인수 조건**

- [ ] 차단하고 해제할 수 있다
- [ ] 차단자는 파티장 여부와 관계없이 상대와 함께 속한 모든 활성 파티에서 탈퇴한다. 파티장 승계·인원 부족 종료는 FR-20을 따른다
- [ ] 차단 전에 공동 파티 탈퇴와 파티장 변경·종료 가능성을 안내한다
- [ ] 차단 저장과 공동 파티 탈퇴·승계·종료는 함께 성공하거나 함께 취소된다
- [ ] 한쪽이라도 차단한 관계는 같은 활성 파티에 합류할 수 없다. 초대·수락 시 대상과 현재 파티원 전원의 양방향 차단 관계를 검사한다
- [ ] 차단 해제만으로 탈퇴한 파티에 복귀하거나 무효화된 초대를 복원하지 않는다
- [ ] 사용자 검색과 파티 초대 후보에서 서로 제외한다
- [ ] 프로필·필름·팝콘을 서로에게 노출하지 않는다
- [ ] 영화 상세의 평가·한줄평 등 작성자 콘텐츠를 서로에게 노출하지 않는다

### FR-40 OTT 구독 추천

사용자 취향과 유사한 미감상 영화가 많은 순으로 OTT를 추천하고 OTT별 대표 영화를 함께 제시해야 한다.

- 비고: 신규 — 팀 제안(2026-08-31). 유사도 임계치·갱신 주기 미정

**인수 조건**

- [ ] OTT별로 사용자 취향 벡터와 유사도가 임계치 이상인 미감상 영화 수를 집계해 순위를 제공한다
- [ ] 감상 기록이 있는 영화와 관심없음 영화는 집계에서 제외한다 (→ FR-18, FR-36)
- [ ] OTT마다 유사도 상위 대표 영화 3편을 함께 제공한다
- [ ] ※ 순위는 절대 편수 기준이며 카탈로그 크기로 정규화하지 않는다 (구독 효용 판단이 목적)

Spark를 활용해 대규모 데이터 전처리와 추천 모델 학습을 분산 처리할 수 있어야 한다.

추천 시스템에 문제가 생겨도 기본 영화 조회·평가 등 핵심 기능은 사용할 수 있어야 한다.

**인수 조건**

- [ ] 추천 서비스 중단 상태에서 영화 조회·검색·평가가 정상 동작한다

### NFR-06 데이터 정합성

> 정합성 관련 인수 조건은 팀 확인 후 다시 작성합니다.

- [ ] ※ 인수 조건 확정 후 작성

### NFR-07 비공개 데이터 접근 차단

인증되지 않은 사용자가 개인 취향과 비공개 감상 기록에 접근할 수 없어야 한다.

**인수 조건**

- [ ] 비인증 사용자는 `PRIVATE` 프로필·필름·팝콘·평가에 접근할 수 없다
- [ ] 리포트 PNG는 단기 URL 없이는 접근할 수 없다
