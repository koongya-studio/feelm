# 백엔드 역할 분배

백엔드 3인의 초기 담당 도메인과 도메인 간 경계 규칙을 정의한다. 아래 담당 표와 착수 순서는
초기 분업 계획을 기록한 것이다. 팀 전체의 실제 구현 기여는 커밋 분석을 바탕으로
[루트 README의 팀 구성](../README.md#9-팀-구성)에 요약한다. 현재 진행 중인 업무의 담당·리뷰어는 해당 Jira 항목에서 확인한다.
API 범위는 [API 명세](./api/README.md), 초기 업무 항목은 `docs/jira/plans/backend-role-split.yml`을 기준으로 한다.

## 분배 원칙

- **도메인 수직 분할**: 한 사람이 담당 도메인의 컨트롤러부터 저장소·테스트까지 소유한다.
  계층(레이어)별 분담은 하지 않는다.
- **공통 기반 선행**: 전원이 의존하는 공통 골격(응답·오류 규약, 인증 골격, Kafka 공통
  모듈)은 도메인 구현 전에 별도 업무로 먼저 병합한다.
- **도메인 소유는 리뷰 책임을 포함한다**: 담당자는 해당 도메인 MR의 1차 리뷰어다.
- 공통 계약(DTO·오류 코드·DB Schema·이벤트 스키마) 변경은 담당 간 합의 후 별도
  브랜치로 처리한다(`AGENTS.md` 5장).

## 담당

| 담당 | 이름 | 도메인 | 도메인 패키지 | 1차 MVP 범위 | Epic |
|---|---|---|---|---|---|
| BE-A | 박시현 | 계정·온보딩 | `auth`, `user`, `onboarding`, `ott` | 사용자(API-001~022), 온보딩·OTT(API-023~027) | S15P21E106-142 |
| BE-B | 서유정 | 콘텐츠·감상·소셜 | `search`, `movie`, `watch`, `social`, `report`, `trend` | 영화·검색(API-028~030), 감상(API-033~039), 한줄평(API-032), 데이터 적재 | S15P21E106-143 |
| BE-C | 김서현 | 취향·추천·파티 | `taste`, `recommendation`, `party` | 취향(API-040~044), 추천(API-031, 045~048), 파티(API-049~058) | S15P21E106-144 |

도메인 패키지 이름과 위치는 [백엔드 개발 컨벤션 3장](./backend-convention.md#3-패키지-구조)을 따른다.

공통 기반 업무(Epic S15P21E106-141)는 BE-A(스캐폴드·인증 골격), BE-C(Kafka 계약·공통
발행 모듈)가 나눠 맡는다. 추천 파이프라인(Spark) 자체는 S15P21E106-124 소관이며,
S15P21E106-144는 Spring 서빙 측만 다룬다.

2차 MVP 이후 범위는 1차 진행 상황을 반영해 별도 계획으로 산정하되, 기본 배분은 다음과 같다.

- BE-A: 알림 발송(A-11 2차)
- BE-B: 리포트(API-059~061), 공개 프로필·취향 비교(API-062~063), 급상승 영화(API-064)
- BE-C: 오늘의 영화(API-066), OTT 구독 추천(API-068)

## 선행 작업과 착수 순서

1. **BE-A**: 프로젝트 스캐폴드 + 공통 응답·오류(A-9) + JWT 인증 골격(A-8) + dev mock
   인증을 최우선 병합한다. 이 병합 전까지 회원 인증이 필요한 API 구현을 시작하지 않는다.
2. **BE-B**: 인증과 무관한 TMDb·MovieLens 적재 파이프라인을 첫 업무로 착수한다.
3. **BE-C**: Kafka 이벤트 계약·Redis 키 설계 문서를 AI 담당과 합의해 확정하고, 공통
   발행 모듈을 구현한다.

## 도메인 간 경계 규칙

- **Kafka 공통 층**(토픽 상수, 이벤트 DTO, 직렬화·프로듀서 설정, 재시도 정책)은 BE-C가
  소유한다. 각 도메인은 공통 발행 컴포넌트 호출만으로 이벤트를 발행하고 Kafka 설정을
  직접 수정하지 않는다.
- **행동 이벤트 발행**: 발행 코드는 이벤트가 발생하는 도메인 담당이 작성한다(평가·클릭은
  BE-B, 온보딩은 BE-A). 이벤트 스키마·발행 시점의 계약은 BE-C가 소비 측(AI)과 합의해
  확정한다.
- **차단 필터**: BE-A가 공통 컴포넌트로 제공하고 한줄평(BE-B)·파티 초대(BE-C)가
  사용한다.
- **회원 탈퇴의 도메인별 정리**: 탈퇴(API-013)가 다른 도메인의 데이터를 지워야 하면, 그
  도메인이 탈퇴 전용 진입점(`*ForWithdrawal`)을 제공하고 계정 도메인은 그것만 호출한다.
  반복·잠금·부분 실패 처리는 소유 도메인이 정한다. 차단(`UserBlockService`)과
  파티(`PartyWithdrawalService`)가 이 형태이며, 앞으로 평가·한줄평 등이 같은 판단을
  반복하지 않도록 규칙으로 둔다 (S15P21E106-436).
- **평가와 취향 적립**: 평가 API는 BE-B, 평가에 따른 프레임·팝콘 적립 규칙은 BE-C
  소관이며 연동 지점은 두 담당이 합의해 확정한다.
- 이벤트 스키마는 API 계약과 같은 등급의 공통 계약으로 취급한다. 변경은 발행·소비 담당
  합의 후 별도 브랜치로 처리한다.
