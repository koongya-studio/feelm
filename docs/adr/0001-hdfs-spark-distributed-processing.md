# ADR-0001: 분산 저장·처리에 Hadoop HDFS와 Spark(PySpark)를 사용한다

| 항목 | 값 |
|---|---|
| 상태 | 채택 |
| 결정일 | 2026-08 (기술 스택 확정, README 10장) |
| 결정자 | 팀 전체 |
| 관련 | NFR-02, NFR-03, README 3·7장 |

## 맥락

프로젝트 주제가 빅데이터 분산 처리 특화이며, MovieLens 32M(평점 3,200만 건)을 원천 데이터로 ALS 학습·전처리를 수행해야 한다. 데이터 1M → 32M, Worker 1 → N 확장 시 처리 시간·Speedup·Throughput을 검증하는 것이 NFR-03의 검증 항목이다.

## 결정

원천·가공 데이터와 Item Factor는 HDFS/Parquet에 저장하고, 전처리·ALS 학습·후보 생성은 Spark 배치로 수행한다. 구현 언어는 PySpark다.

## 고려한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| HDFS + Spark (선택) | 분산 처리 검증 요건 충족, MLlib ALS 내장, Parquet 컬럼 저장 | EC2 2대 자원으로 클러스터 운영 부담, 배치 지연 |
| 단일 서버 pandas/scikit | 단순 | 32M 규모에서 메모리 한계, 분산 처리 검증 불가 — 프로젝트 요건 미충족 |
| Spark만 (S3/로컬 저장) | HDFS 운영 생략 | HDFS 사용이 NFR-02 요건 |

## 결과

- **얻는 것**: 요건 충족, 학습·후보 생성의 수평 확장
- **감수하는 것**: 클러스터 운영·모니터링, 배치 주기(하루 1회 가정) 동안 추천 반영 지연
- **후속 작업**: Spark 자원 계획(README 7장) 검증, 배치 스케줄 확정, HDFS 레이아웃 문서
