# ADR-0004: 서비스 데이터는 PostgreSQL, 캐시·후보는 Redis에 저장한다

| 항목 | 값 |
|---|---|
| 상태 | 채택 |
| 결정일 | 2026-08 (기술 스택 확정, README 7·10장) |
| 결정자 | BE·데이터 담당, 팀 합의 |
| 관련 | NFR-01, NFR-06, docs/erd.md |

## 맥락

회원·영화·평가·감상 같은 영속 데이터는 정합성(NFR-06)이 중요하고, 사전 계산한 Candidate Top-500과 추천 결과는 빠른 조회(NFR-01)가 중요하다. 두 요구의 저장 특성이 다르다.

## 결정

영속 데이터는 PostgreSQL(관계·트랜잭션·JSONB), Candidate Top-500·최종 추천 캐시·Refresh Token(ADR-0009)은 Redis에 둔다. Spark 배치가 Redis에 직접 적재한다.

## 고려한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| PostgreSQL + Redis (선택) | 정합성과 속도를 각각 최적, JSONB로 추천 이유 스냅샷 저장 | 두 저장소 운영 |
| PostgreSQL 단독 | 운영 단순 | 추천 캐시 조회 지연, 배치 적재 시 부하 |
| MySQL + Redis | 친숙 | JSONB·부분 유일 인덱스·full-text 등 필요한 기능이 PostgreSQL이 우세 |

## 결과

- **얻는 것**: 트랜잭션 정합성 + 추천 조회 성능
- **감수하는 것**: Redis 키 설계·만료 정책 문서가 별도로 필요, 두 저장소 간 정합성은 애플리케이션 책임
- **후속 작업**: Redis 키 설계 문서, 물리 스키마·마이그레이션(ERD 5장 결정 확정 후)
