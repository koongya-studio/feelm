# ADR-0023: 리포트 이미지를 서비스 노드 비공개 디렉터리에 저장한다

| 항목 | 값 |
|---|---|
| 상태 | 채택 |
| 결정일 | 2026-09-22 |
| 결정자 | S15P21E106-549 작업 승인, S15P21E106-557 렌더 정본 정정 |
| 관련 | FR-24, NFR-07, API-061, S15P21E106-549, S15P21E106-557, S15P21E106-761 |

## 맥락

API-061은 화면과 같은 리포트 PNG를 재사용하면서 짧게 유효한 다운로드 URL을 제공해야 한다. 배포 환경에는 AWS S3 버킷과 IAM 권한이 제공되지 않았고, 리포트 이미지만을 위해 MinIO 서비스를 새로 운영하면 현재 단일 서비스 노드 MVP에 배포·백업·관제 부담이 추가된다. 프로필 사진 업무 S15P21E106-761도 서비스 노드 호스트 디렉터리를 컨테이너에 bind mount하는 저장 방식을 사용한다.

리포트 PNG는 프로필 사진과 달리 공개 정적 자원이 아니다. NFR-07에 따라 파일 경로를 알아도 직접 접근할 수 없어야 하고, API-061에서 본인 소유를 확인한 사용자만 제한 시간 동안 사용할 수 있는 다운로드 capability를 받아야 한다.

## 결정

리포트 PNG는 서비스 노드의 `/srv/feelm/data/report-images`에 저장하고 Backend 컨테이너의 `/data/report-images`에 읽기·쓰기로 bind mount한다. 프로필 사진 저장소와 디렉터리를 분리하고 Nginx 정적 공개 경로에는 연결하지 않는다. DB에는 서버가 생성한 상대 `storage_key`만 저장한다.

Frontend는 화면에 실제 표시한 공용 `ReportFourCut` DOM/CSS/서체/에셋을 1080×3268 PNG로 캡처한다. 저장 전용 디자인과 Backend 렌더러는 두지 않는다. Backend는 큰 본문을 읽기 전에 본인 `READY` 리포트인지 확인하고, 동시 처리 수를 제한한 뒤 PNG 전체 decode·25MB·규격을 검증해 저장한다. API-061은 전용 Secret의 HMAC-SHA256 서명을 포함한 다운로드 URL을 발급하며, URL은 발급 시점부터 10분 동안 유효하다. 다운로드 엔드포인트는 만료 시각과 서명을 검증하고 동시 처리 상한 안에서 파일을 반환한다. 이 전용 Secret은 JWT Secret과 분리하고 저장소에 기록하지 않는다.

이미지 메타데이터와 실제 파일이 모두 있으면 새 업로드로 덮어쓰지 않고 새 서명 URL만 발급한다. DB 행만 남고 파일이 유실된 경우에는 프론트가 같은 컴포넌트에서 다시 캡처해 보낸 PNG로 복구한다.

## 고려한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| 서비스 노드 비공개 호스트 디렉터리 + 애플리케이션 서명 URL (선택) | 현재 단일 노드와 761의 영속 파일 운영 방식을 재사용하고 별도 서비스를 추가하지 않는다 | 인스턴스·볼륨 장애에 취약하고 다중 Backend 인스턴스에서 공유할 수 없다 |
| AWS S3 비공개 버킷 + presigned URL | 관리형 내구성과 수평 확장, 표준 presigned URL을 제공한다 | 현재 버킷과 IAM 권한이 제공되지 않아 배포할 수 없다 |
| 자체 호스팅 MinIO + presigned URL | S3 호환 API와 비공개 객체 저장을 제공한다 | 리포트 이미지 하나를 위해 서비스·볼륨·자격 증명·백업·관제를 추가해야 한다 |
| 기존 `ReportFourCut` DOM 캡처 후 저장 (선택) | 화면과 저장 이미지가 하나의 디자인 구현을 공유한다 | 외부 이미지 CORS에 의존하고 업로드 검증 경로가 필요하다 |
| Backend Java2D 재구현 | 브라우저와 외부 이미지 CORS에 덜 의존한다 | 프론트 DOM/CSS와 별도 디자인 구현이 생겨 화면과 PNG가 어긋난다 |

## 결과

- **얻는 것**: 현재 인프라에서 배포 가능한 비공개 PNG 저장, 10분으로 제한된 공유 capability, 동일 이미지 재사용, 화면과 저장 이미지의 단일 디자인 정본
- **감수하는 것**: 서비스 노드 또는 호스트 볼륨 손실 시 저장 PNG가 유실된다. PNG는 사용자가 상세 화면에서 다시 캡처해 복구할 수 있지만 별도 백업과 다중 노드 공유 저장은 제공하지 않는다. 캡처는 외부 이미지 CORS와 브라우저 기능에 의존한다
- **신뢰 경계**: Backend는 업로드 PNG가 실제 DOM에서 왔는지와 픽셀의 의미를 검증할 수 없다. 짧은 서명 URL은 접근 capability일 뿐 콘텐츠 보증이 아니므로 출시 전 재배포 권리·abuse 대응을 별도로 확정한다
- **후속 작업**: S15P21E106-761의 호스트 디렉터리 배포 방식이 병합된 뒤 리포트 전용 bind mount와 전용 Secret을 배포 계약에 추가한다. 프로세스가 파일 move와 DB insert 사이에 종료될 때 남을 수 있는 미참조 UUID 파일은 운영 정리 절차에 포함한다. Backend 다중 인스턴스 또는 이미지 장기 보존이 필요해지면 객체 스토리지 도입을 새 ADR로 재검토한다
