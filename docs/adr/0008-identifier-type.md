# ADR-0008: 내부 식별자는 bigint, 공개 URL에는 별도 public_id를 사용한다

| 항목 | 값 |
|---|---|
| 상태 | 채택 |
| 결정일 | 2026-08-30 |
| 결정자 | 박시현(BE). A 회의에서 팀 공유 |
| 관련 | A-1, ERD D-1, API-000 미정 사항, API-062, API-063 |

## 맥락

모든 테이블의 PK와 FK, 모든 API 응답의 ID 표현을 결정해야 한다. 식별자가 URL에 노출되는 곳은 공개 프로필(`/users/{userId}/profile`)이며, 비공개 리소스는 404로 응답하기로 했다(NFR-07).

## 결정

내부 식별자(PK/FK)는 `bigint` 시퀀스를 사용한다. 공개 URL에 노출되는 리소스에는 별도의 추측 불가능한 공개 식별자 컬럼(`public_id`)을 두고 URL에는 그것만 노출한다. 1차 MVP에서 `public_id`가 필요한 테이블은 `users`(공개 프로필)이며, 다른 리소스는 소유권 검사 + 404 응답으로 충분해 `bigint`를 그대로 노출한다.

## 고려한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| bigint 시퀀스 | 8바이트, 순차 인덱스 효율, JPA `IDENTITY` 한 줄, 디버깅 용이 | 값 예측 가능(열거), 가입자 수 노출, DB 저장 전 ID 미확정 |
| UUID v7 | 추측 불가, 서비스 간 사전 생성 가능, 병합 시 충돌 없음 | 16바이트로 인덱스·FK 2배, 가독성 낮음 |
| bigint 내부 + public_id 외부 (선택) | 내부 효율과 외부 비노출을 모두 확보 | `users.public_id` 컬럼·유일 인덱스와 조회 매핑 추가 |

## 결과

- **얻는 것**: 구현·운영 단순, 인덱스 효율, 공개 URL 열거 차단
- **감수하는 것**: `users.public_id` 컬럼·유일 인덱스와 조회 매핑 추가
- **후속 작업**: 반영 완료(S15P21E106-91) — ERD `users.public_id`, API-062·063 `publicId`, ERD 범례 갱신
