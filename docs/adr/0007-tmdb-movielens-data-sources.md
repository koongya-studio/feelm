# ADR-0007: 영화 메타데이터는 TMDb, 학습 원천은 MovieLens 32M을 사용하고 사용자는 연결하지 않는다

| 항목 | 값 |
|---|---|
| 상태 | 채택 |
| 결정일 | 2026-08 (README 6장) |
| 결정자 | 데이터·AI 담당, 팀 합의 |
| 관련 | FR-14, FR-16, FR-34, README 6장 |

## 맥락

ALS 학습에는 대규모 평점 데이터가, 서비스에는 포스터·줄거리·감독·배우·OTT 제공처 같은 메타데이터가 필요하다. 두 데이터의 사용자 체계는 다르다.

## 결정

학습 원천은 MovieLens 32M, 서비스 메타데이터는 TMDb API로 하고 영화는 TMDb ID 기준으로 매핑한다. MovieLens 사용자 ID는 학습 원천에만 두고 서비스 `user_id`와 연결하지 않으며, 서비스 사용자는 평가 기반 Fold-in으로 벡터를 만든다.

## 고려한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| MovieLens + TMDb (선택) | 규모·메타데이터 품질 모두 확보 | 두 소스 동기화, TMDb 호출 제한 |
| MovieLens 단독 | 단순 | 포스터·줄거리·OTT 정보 없음 |
| TMDb 평점만 학습 | 단일 소스 | 개인화 학습에 필요한 사용자-영화 상호작용 부족 |

## 결과

- **얻는 것**: 대규모 학습 데이터 + 서비스 품질 메타데이터
- **감수하는 것**: TMDb 동기화 주기·캐시 정책(API-030 미정), MovieLens에 없는 영화는 콘텐츠 기반으로만 추천
- **후속 작업**: TMDb 동기화 배치, 영화 매핑 테이블(ERD `movies.movielens_id`)
