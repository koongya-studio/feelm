# ADR-0011: 알림은 1차 MVP에서 폴링으로 전달하고 알림 발송 기능은 2차로 미룬다

| 항목 | 값 |
|---|---|
| 상태 | 채택 |
| 결정일 | 2026-08-31 |
| 결정자 | 박시현(BE). FE·기획 공유 예정 |
| 관련 | A-11, FR-38, API-017, API-051, API-034 |

## 맥락

1차 MVP에서 사용자에게 알려야 하는 사건은 파티 초대(FR-20)와 감상 확인 시점 도래(FR-18) 두 가지다. FR-38은 알림 **설정**을 정의하지만 알림을 **발송**하는 기능 요구사항은 없다.

## 결정

앱 진입 시 받은 초대(API-052)와 감상 확인 대상(API-034)을 조회하는 폴링 방식으로 처리하고, SSE/WebSocket 및 이메일·푸시 발송은 도입하지 않는다. 알림 발송 기능이 필요하면 FR을 추가한 뒤 2차에서 다룬다. `notification_settings`는 설정만 저장한다.

## 고려한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| 폴링 (선택) | 인프라·구현 없음, 1차 트리거 두 개에 충분 | 실시간성 없음 |
| SSE | 서버 → 클라이언트 실시간 | 연결 관리, 인프라 설정 |
| WebSocket | 양방향 | 1차 범위에 과함 |

## 결과

- **얻는 것**: 1차 범위 축소
- **감수하는 것**: 실시간 알림 부재. `notification_settings`는 설정만 저장
- **후속 작업**: FR-38 비고 정리(요구사항 문서·Notion), 2차 알림 발송 FR 후보 등록 — 미처리
