# ADR-0015: 팝콘 8개 취향 유형은 K-Means와 c-TF-IDF로 생성한다

| 항목 | 값 |
|---|---|
| 상태 | 채택 |
| 결정일 | 2026-08-31 |
| 결정자 | 팀 확정, S15P21E106-127에서 기록 |
| 관련 | ADR-0014, FR-04, FR-05, FR-06, FR-09, FR-12, API-040, API-041, API-044, ERD D-5·D-12, S15P21E106-127 |

## 맥락

팝콘 버킷은 영화를 8개 취향 유형 중 하나로 분류하고 사용자가 감상한 분포를 보여줘야 한다. 고정 장르 묶음은 복합 장르와 줄거리의 의미를 충분히 반영하지 못하고, 콘텐츠 추천에서 사용하는 임베딩과 취향 시각화가 서로 다른 기준을 갖게 된다.

## 결정

ADR-0014의 영화 임베딩을 K-Means의 입력으로 사용하고 `K=8`로 군집화한다. 각 영화는 가장 가까운 Centroid의 취향 유형 하나에 배정한다. 군집별 텍스트에 c-TF-IDF를 적용해 대표 키워드를 추출하고 사용자에게 표시할 취향 유형을 해석한다. 팝콘 버킷은 별도 행을 생성하지 않고 사용자의 평가와 영화의 대표 맛을 집계한다.

K-Means의 원시 Cluster ID는 공개 API에 노출하지 않는다. 고정된 8개 Centroid와 군집-맛 1:1 매핑을 사용하며 `popcorn_flavors`가 `cluster_id`, 불변 맛 코드, 표시명·색상과 대표 키워드를 함께 보관한다. 신규 영화는 같은 임베딩 전처리 후 기존 K-Means의 `predict`로 가장 가까운 Centroid에 배정하고 결과를 `movies.representative_flavor_id`에 저장한다. 맛 모델 버전과 재학습은 사용하지 않는다.

2026-09-07 합의 보완: 맞춤(`TASTE`)·발견(`DISCOVERY`) 추천은 모두 이 K-Means 군집을
기반으로 한다. 두 유형을 나누는 감상량·선호도·거리 등의 사용 방식과 기준값은 아직 미정이다.
군집 생성·대표 맛 배정의 채택이 `팝콘 수 < 임계치` 같은 특정 추천 판정식의 채택을 뜻하지 않는다.
구체 제품 기준은 [FR-10·FR-12](../requirements.md)와 [이벤트·Redis 계약](../api/streaming-contract.md)에 기록한다.

## 고려한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| E5 Embedding + K-Means + c-TF-IDF (선택) | 의미 기반 분류, 추천과 같은 콘텐츠 표현 재사용, 대표 키워드로 해석 가능 | 군집 안정성과 사용자 친화적 명명 검증 필요 |
| 고정 장르 8그룹 | 구현과 설명이 단순, 결과가 안정적 | 복합 장르·줄거리 의미 반영이 약함 |
| 사용자별 동적 군집 | 개인화된 취향 축 | 사용자 간 비교와 고정된 8색 UI 유지가 어려움 |

## 결과

- **얻는 것**: 유사 영화 추천과 일관된 8개 취향 유형, 데이터 기반 팝콘 분포와 발견 추천
- **감수하는 것**: 고정 Centroid가 장기적으로 신규 영화 분포 변화를 충분히 반영하지 못할 수 있음
- **후속 작업**: 고정 Random Seed, 군집 품질 지표, 8개 표시명·색상과 신규 영화 `predict` 파이프라인 확정
