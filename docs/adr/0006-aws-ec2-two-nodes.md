# ADR-0006: 인프라는 AWS EC2 2대로 Spark 클러스터와 서비스를 함께 운영한다

| 항목 | 값 |
|---|---|
| 상태 | 채택 |
| 결정일 | 2026-08 (기술 스택 확정, README 7·10장) |
| 결정자 | 인프라 담당, 팀 합의 |
| 관련 | NFR-03, NFR-04, NFR-05, README 7장 Spark 자원 계획 |

## 맥락

제공된 자원이 EC2 2대(각 8 vCPU/32GB)다. Spark Worker 2개로 분산 처리를 검증하면서 서비스(Spring, PostgreSQL, Redis, 필요 시 FastAPI)도 같은 장비에서 운영해야 한다.

## 결정

EC2 #1은 Spark Master + Worker 1(3 Core/12~14GB), EC2 #2는 Worker 2(5 Core/20GB)로 배치하고, 남는 자원에 서비스 컨테이너를 배치한다. Executor는 2 Core/8GB, EBS는 각 100~200GB SSD.

## 고려한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| EC2 2대 분할 운영 (선택) | 주어진 자원 내 분산 검증 가능 | 배치 실행 중 서비스 자원 경합, 단일 장애점 |
| 서비스용 장비 추가 | 격리 | 자원 없음 |
| EMR/관리형 Spark | 운영 부담 감소 | 비용, 분산 처리 직접 구성이라는 학습 목표와 불일치 |

## 결과

- **얻는 것**: 제한 자원 내 요건 충족
- **감수하는 것**: 배치와 서비스의 자원 경합 — 배치 시간대 조정, 컨테이너 자원 제한 필요. 서비스 배포 단위가 늘면(ADR-0012) 자원 재배분
- **후속 작업**: Docker Compose·배포 설정, 배치 스케줄, 모니터링
