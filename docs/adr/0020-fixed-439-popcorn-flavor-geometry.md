# ADR-0020: 팝콘 8개 취향 유형은 439의 고정 장르 기하를 사용한다

| 항목 | 값 |
|---|---|
| 상태 | 채택 |
| 결정일 | 2026-09-16 |
| 결정자 | 팀 확정, S15P21E106-439·466에서 기록 |
| 관련 | ADR-0015, FR-04, FR-05, FR-06, FR-09, FR-12, API-040, API-041, API-044, ERD D-5·D-12·D-13, S15P21E106-439·466 |

## 맥락

팝콘 버킷은 영화를 8개 취향 유형 중 하나로 분류하고 사용자가 감상한 분포를 보여줘야 한다.
ADR-0015는 E5 영화 임베딩을 K-Means로 군집화하고 c-TF-IDF로 해석하는 방식을 채택했지만,
서비스에 사용할 실제 고정 분류 산출물은 S15P21E106-439의 131차원 장르·키워드·줄거리 기하다.
DB와 공개 API가 실제 산출물과 다른 모델을 설명하면 신규 영화와 기존 영화의 맛이 재현되지 않는다.

## 결정

공개 팝콘 맛은 S15P21E106-439의 상위 `taste_id` 0~7을 그대로 사용한다. 상위 배정 입력은
`top_x = L2(concat(g, 0×k, 0×t))`이고, 고정된 `top_centers[8,131]`와의 float64 제곱
유클리드 거리 최솟값을 선택한다. 여기서 `g`는 고정된 TMDb 장르 19차원 축이며 키워드 64차원과
줄거리 48차원은 상위 맛 결정에는 기여하지 않는다. 같은 거리에서는 낮은 `taste_id`가 이긴다.

`taste_id`는 `popcorn_flavors.cluster_id`와 1:1로 저장하되 공개 API에는 노출하지 않는다.
불변 코드는 0부터 순서대로 `FLAVOR_A`~`FLAVOR_H`이며 표시명·색상은 바꿀 수 있다.
대표 키워드는 c-TF-IDF 산출물이 아니라 439 실배정의 장르 분포와 검토 영화로 확정한 해석 값이다.
팝콘 버킷은 별도 팝콘 행을 만들지 않고 사용자의 평가와 영화의 대표 맛을 집계한다.

`group_mapped=true`인 영화만 `movies.representative_flavor_id`에 저장한다. 장르 축이 지원되지 않아
`group_mapped=false`인 영화는 진단용 `taste_id`가 있어도 대표 맛을 `NULL`로 유지하고 팝콘 집계와
발견 추천에서 제외한다. S15P21E106-439 기준 237,817편 중 207,240편이 저장 대상이고
30,577편이 제외 대상이다.

신규 영화도 같은 고정 vocabulary·IDF·SVD·center와 동일한 거리 계산으로 배정한다. fit,
K-Means estimator `predict`, center 재정렬 또는 재학습을 하지 않는다. 새 영화가 서비스에 반영되려면
새 immutable catalog bundle을 생성·검증한 뒤 동일한 ID 매핑 절차로 DB에 적용한다.

맞춤(`TASTE`)은 사용자 평가·온보딩 선호 기반 개인 순위로 생성하며, 이 상위 맛을 유형 판정에
사용하지 않는다. 발견(`DISCOVERY`)은 439의 8×128 그룹 산출물을 바탕으로 별도 선정 정책을 적용한다.
군집 산출물과 선정 기준이 준비되기 전에는 발견 슬롯을 맞춤으로 채운다. 군집 생성·대표 맛 배정의
채택이 `팝콘 수 < 임계치` 같은 특정 발견 판정식의 채택을 뜻하지 않는다. 구체 제품 기준은
[FR-10·FR-12](../requirements.md)와 [이벤트·Redis 계약](../api/streaming-contract.md)에 기록한다.

## 고려한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| 439 고정 131차원 기하 (선택) | 기존 237,817편과 신규 영화의 배정 재현 가능, 발견 그룹과 같은 상위 축 사용 | 상위 맛은 장르 축만 사용하며 원 frozen 산출물 관리 필요 |
| E5 Embedding + K-Means + c-TF-IDF | 의미 기반 분류와 텍스트 해석 가능 | 실제 439 산출물과 다른 맛을 만들며 별도 모델 수명주기가 필요 |
| 수동 장르 8그룹 | 구현과 설명이 단순 | 복합 장르 처리와 기존 439 ID축을 재정의해야 함 |
| 사용자별 동적 군집 | 개인화된 취향 축 | 사용자 간 비교와 고정된 8색 UI 유지가 어려움 |

## 결과

- **얻는 것**: 공개 팝콘 맛과 439 발견 그룹의 상위 축 일치, 기존·신규 영화 배정 재현성
- **감수하는 것**: 고정 중심과 vocabulary가 장기적인 영화 분포 변화를 자동으로 학습하지 않음
- **운영 조건**: immutable bundle 검증, `(service_movie_id, tmdb_id)` 재결합 차단, dry-run 후 원자적 DB 반영
