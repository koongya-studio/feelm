# ADR-0026: 인앱 알림 변경을 SSE로 전달한다

| 항목 | 값 |
| --- | --- |
| 상태 | 채택 |
| 결정일 | 2026-09-26 |
| 결정자 | S15P21E106-934 사용자 플랜 승인 |
| 관련 | ADR-0021, API-085, FR-41 |

## 결정

PostgreSQL과 REST API를 알림 정본으로 유지한다. 로그인 세션의 fetch SSE 연결에
notification-changed 갱신 신호를 보내 열린 목록과 배지를 재조회한다.
S15P21E106-950에서는 같은 신호로 받은 초대와 참여 파티 목록도 갱신한다.
초대 알림 수신 OFF는 알림 저장·WebPush만 막으며 초대 목록 갱신 신호는 커밋 이후 전달한다.
기존 Bearer 인증과 Web Push 정책을 유지하며 토큰을 URL에 넣지 않는다.
알림 변경은 커밋 이후 발행한다. 예약 알림 도래·만료 및 일괄 리포트 발급은
연결별 15초 DB 지문 대조로 보완한다. 재연결 시 정본을 조회해 이벤트 재생 저장소를 추가하지 않는다.

## 운영 한계

현재 Compose는 단일 백엔드 컨테이너다. 다른 인스턴스에서 변경한 알림도
DB 대조로 최대 15초 지연 후 반영되며 인스턴스 간 즉시 전달은 보장하지 않는다.
연결은 5분마다 교체하고 각 전송 전 토큰과 활성 계정을 확인한다.
연결당 DB 대조 비용이 있으므로 대규모 접속 환경은 별도 용량 검증 후 확장한다.

알림 OFF인 초대의 변경 신호는 현재 단일 인스턴스의 커밋 이벤트로 전달한다.
이 변경은 알림 DB 지문에 없으므로 다른 인스턴스나 외부 DB 직접 변경까지 주기적으로 감지하지 않는다.
클라이언트 재연결 시 최초 신호로 파티 목록도 다시 조회한다.
