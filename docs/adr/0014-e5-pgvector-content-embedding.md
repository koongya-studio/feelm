# ADR-0014: 영화 콘텐츠는 다국어 임베딩과 pgvector로 검색한다

| 항목 | 값 |
|---|---|
| 상태 | 채택 |
| 결정일 | 2026-08-31 |
| 결정자 | 팀 확정, S15P21E106-127에서 기록 |
| 관련 | ADR-0002, ADR-0004, FR-11, API-031, S15P21E106-127 |

## 맥락

장르나 단어가 정확히 일치하지 않아도 줄거리와 키워드의 의미가 비슷한 영화를 찾아야 한다. 콘텐츠 표현은 유사 영화 추천, Hybrid 추천의 Content Score, 취향 군집의 공통 입력으로 재사용되어야 하며 한국어를 포함한 다국어 영화 메타데이터를 처리할 수 있어야 한다.

## 결정

TMDb의 영화 줄거리·키워드 등 텍스트를 다국어 임베딩 모델로 Dense Vector화한다. 임베딩은 PostgreSQL의 pgvector에 저장하고 HNSW 인덱스와 Cosine Similarity를 사용해 유사 영화를 검색한다. 임베딩 생성은 Spark/PySpark 오프라인 파이프라인에서 수행하고 모델 이름·Revision·벡터 차원을 함께 기록한다.

`multilingual-e5-base`는 최종 확정 모델이 아니라 MVP 베이스라인으로 사용한다. 최종 체크포인트는 한국어 영화 데이터로 `multilingual-e5-large`, `BAAI/bge-m3` 등과 비교한 뒤 확정한다. 유사 영화 검색은 Recall@K·NDCG@K, 취향 군집은 군집 안정성과 대표 키워드의 해석 가능성, 운영 측면은 임베딩 처리시간·메모리·인덱스 크기를 평가한다. 최종 모델명과 Revision은 설정 및 모델 산출물 메타데이터에서 관리한다.

## 고려한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| 다국어 임베딩 + pgvector (선택) | 다국어 의미 유사도, PostgreSQL 안에서 벡터 저장·검색, K-Means 입력 재사용 | 모델 비교 평가와 모델·인덱스 버전 관리 필요 |
| TF-IDF | 빠르고 대표 단어 추출에 유리 | 의미가 같아도 단어가 다르면 유사도를 잡기 어려움 |
| 별도 Vector DB | 벡터 검색 기능이 풍부함 | 운영 저장소와 배포 구성 증가 |

## 결과

- **얻는 것**: 의미 기반 유사 영화 검색, 콘텐츠 점수와 취향 군집의 공통 표현
- **감수하는 것**: 최종 모델 검증이 별도로 필요하며 모델 또는 벡터 차원 교체 시 전체 영화 재임베딩과 HNSW 인덱스 재구축 필요
- **후속 작업**: 한국어 영화 평가셋으로 후보 모델 비교, 입력 텍스트 조합과 배치 갱신 주기 결정, `embedding_model_version` 계약 확정
