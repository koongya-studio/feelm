# ADR-0014: 영화 콘텐츠는 다국어 임베딩과 pgvector로 검색한다

| 항목 | 값 |
|---|---|
| 상태 | 채택 |
| 결정일 | 2026-08-31 |
| 결정자 | 팀 확정, S15P21E106-127에서 기록 |
| 관련 | ADR-0002, ADR-0004, FR-11, API-031, S15P21E106-127, S15P21E106-419 |

## 맥락

장르나 단어가 정확히 일치하지 않아도 줄거리와 키워드의 의미가 비슷한 영화를 찾아야 한다. 콘텐츠 표현은 유사 영화 추천, Hybrid 추천의 Content Score, 취향 군집의 공통 입력으로 재사용되어야 하며 한국어를 포함한 다국어 영화 메타데이터를 처리할 수 있어야 한다.

## 결정

TMDb의 영화 줄거리·키워드 등 텍스트를 다국어 임베딩 모델로 Dense Vector화한다. 임베딩은 PostgreSQL의 pgvector에 저장하고 HNSW 인덱스와 Cosine Similarity를 사용해 유사 영화를 검색한다. 임베딩 생성은 Spark/PySpark 오프라인 파이프라인에서 수행하고 모델 이름·Revision·벡터 차원을 함께 기록한다.

MVP 저장·검색 계약은 `multilingual-e5-base` 계열의 768차원 벡터로 확정한다. DB의 `model_version varchar(50)`에는 50자 이내의 안정적인 모델 식별자와 Revision을 저장하고, 전체 산출물 SHA와 생성 설정은 파이프라인 manifest에서 관리한다. 이후 `multilingual-e5-large`, `BAAI/bge-m3`처럼 차원이 다른 모델을 도입하려면 별도 결정과 마이그레이션, 전체 재임베딩 및 HNSW 인덱스 재구축을 수행한다. 유사 영화 검색은 Recall@K·NDCG@K, 운영 측면은 임베딩 처리시간·메모리·인덱스 크기를 계속 평가한다.

## 고려한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| 다국어 임베딩 + pgvector (선택) | 다국어 의미 유사도, PostgreSQL 안에서 벡터 저장·검색 | 모델 비교 평가와 모델·인덱스 버전 관리 필요 |
| TF-IDF | 빠르고 대표 단어 추출에 유리 | 의미가 같아도 단어가 다르면 유사도를 잡기 어려움 |
| 별도 Vector DB | 벡터 검색 기능이 풍부함 | 운영 저장소와 배포 구성 증가 |

## 결과

- **얻는 것**: 의미 기반 유사 영화 검색, 콘텐츠 점수와 취향 군집의 공통 표현
- **감수하는 것**: 향후 모델 또는 벡터 차원 교체 시 별도 마이그레이션, 전체 영화 재임베딩과 HNSW 인덱스 재구축 필요
- **후속 작업**: 한국어 영화 평가셋으로 품질 검증, 입력 텍스트 조합과 배치 갱신 주기 결정
