# ADR-0021: PostgreSQL 인앱 알림을 2차 알림 정본으로 사용한다

| 항목 | 값 |
|---|---|
| 상태 | 채택 |
| 결정일 | 2026-09-17 |
| 결정자 | S15P21E106-580 팀 승인 |
| 관련 | FR-41, API-070~074, ADR-0011, S15P21E106-581~583 |

## 맥락

1차 MVP는 파티 초대와 감상 확인 도메인 API를 각각 폴링했다(ADR-0011). 2차에서는 여러 세션에서 같은 읽음 상태를 보여 주고, 후속 브라우저 푸시가 재시도되더라도 중복 사건을 만들지 않는 서버 정본이 필요하다. 도메인 원본 저장과 알림 생성이 분리되면 한쪽만 성공해 사용자에게 누락되거나 존재하지 않는 업무를 알릴 수 있다.

## 결정

PostgreSQL의 `notifications`를 2차 인앱 알림 정본으로 사용한다. 파티 초대와 감상 확인 알림은 원본 도메인 변경과 같은 트랜잭션에서 중복 없이 저장하고, 목록·미확인 개수·개별 및 전체 읽음·개별 숨김 API를 제공한다. 숨김은 원본 사건 종료와 구분해 기록하고 행은 만료 정책에 따라 정리한다. Web Push는 이 정본을 사용하는 후속 S15P21E106-582에서 구현한다.

## 고려한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| PostgreSQL 인앱 알림 정본 (선택) | 원본과 원자적 저장, 읽음 상태 영속화, 푸시 재시도 기준 제공 | 저장·정리 작업과 조회 API가 필요 |
| 기존 도메인 API 계속 폴링 | 새 저장소가 필요 없음 | 통합 목록·읽음 상태가 없고 사건별 조회가 분산됨 |
| 푸시 제공자만 정본으로 사용 | 전달 구현이 단순해 보임 | 읽음 동기화와 재처리 감사가 어렵고 외부 제공자 장애에 종속됨 |

## 결과

- **얻는 것**: 여러 세션에서 일관된 알림 목록과 읽음·숨김 상태, 도메인 원본과의 원자성, 후속 푸시의 안정적인 입력
- **감수하는 것**: 만료 데이터 정리와 인덱스 운영, 새 알림 종류 추가 시 DB 제약·API 열거형 동시 변경
- **후속 작업**: S15P21E106-582에서 Web Push 구독·발송·재시도를 구현하고 S15P21E106-583에서 프론트 폴링을 새 API로 전환한다
