# Pipeline AGENTS.md

루트 `AGENTS.md`의 공통 절차를 전제로, `pipeline/` 기능 변경에 필요한
단계별 작업·검증 규칙만 정의한다.

## 1. 적용 범위

- Spark, Consumer, 파이프라인 계약·실행 설정의 기능 변경은 `3. 작업
  파이프라인`을 모두 따른다.
- 문서·주석 전용 변경은 네 단계를 생략하고 링크·명령·diff만 검증한다.
- 테스트 전용 변경도 생산 동작·계약을 바꾸지 않으면 네 단계를 생략할 수
  있다. 대신 테스트가 의도한 성공·실패 경로를 실제로 검증하는지 확인한다.
- HDFS·분산 클러스터 검증 전용 업무는 **플랜·리뷰**만 필수로 적용한다.
  사람이 플랜을 확인한 뒤 별도의 새 세션에서 실환경 검증을 실행한다.
- 예외를 적용하면 시작 보고와 MR에 생략 단계·근거를 남긴다. 애매하면 네 단계를
  적용한다.

## 2. 기준·런타임·검증

문서 충돌은 루트 `AGENTS.md`의 우선순위를 따르고, 영역별 기준은 다음과 같다.

- HDFS 경로·Parquet 스키마·ID 매핑·모델 산출물: `pipeline/contracts/`
- 서비스 경계: `docs/api/`, `docs/erd.md`
- 아키텍처: `docs/adr/`의 채택된 ADR
- 요구사항: `docs/requirements.md`
- 실행·재현 방법: `pipeline/README.md`와 변경 영역의 `README.md`

`pipeline/docs/`의 연구 자료는 명시적으로 승격되지 않은 계약을 확정하지 않는다.
`pipeline/contracts/`는 내부 교환 계약의 기준이며 API·DB·ADR을 덮어쓰지 않는다.
영역이 겹치거나 계약과 구현이 다르면 임의로 진행하지 않고 합의한다.

Spark와 Consumer는 독립 실행 단위다. 서로의 코드·의존성을 공유하지 않고
`pipeline/contracts/`로 연결한다. 정확한 런타임은 `pipeline/README.md`를 따른다.

- Spark: `pipeline/spark/`에서 `uv run pytest`, `uv run ruff check .`
- Consumer: `pipeline/consumer/README.md`와 Consumer 자체 프로젝트의 명령

로컬·합성 fixture 검증은 HDFS 권한·네트워크·분산 실행·재시도를 입증하지
않는다. 실환경 검증은 환경·산출물 버전, 명령, 결과, 실패 정리·재시도와
미검증 범위를 따로 남긴다. Secret·실제 URI·내부 주소는 기록하지 않는다.

## 3. 작업 파이프라인

기능 변경은 **플랜 → 테스트 선행 → 구현 → 리뷰** 순서를 따른다. 각 단계는
사람이 이전 대화 없이 새 세션으로 시작한다. AI는 현재 단계의 산출물을 남기고
종료하며 다음 단계로 자동 진행하지 않는다. 각 세션은 Jira, 기준 문서, 저장소
상태와 이전 산출물을 다시 확인한다.

1. **플랜**: 루트 `plans/<Jira-Key>.md`에 설계, 계약 영향·합의, 로컬·클러스터·HDFS
   검증 계층, 미확정 사항을 남긴다. 시작 커밋과 기존 미커밋 변경·새 파일을
   **기준선**으로 기록하고 후속 단계가 다시 확인하게 한다.
2. **테스트 선행**: 요구사항을 검증하는 테스트를 먼저 작성해 실패를 확인한다.
   실패가 환경·fixture·외부 상태 문제가 아닌지 확인한 뒤에만 구현을 시작한다.
3. **구현**: 선행 테스트를 통과시키는 최소 구현을 작성하고 검증한다. 테스트를
   약화하지 않는다. 플랜 변경은 사람의 판단과 플랜 파일 기록을 요구한다.
4. **리뷰**: 루트 `plans/<Jira-Key>-review.md`에 플랜 대비 변경·검증·미검증 범위와
   다음 검토 결과를 남긴다.
   - HDFS·Parquet·ID·모델 산출물·API·DB 계약 정합성
   - 데이터 누수, 분할, 제외·중복·분모·후보 생성을 포함한 지표 정확성
   - 분산 실행, 부분 실패, 재시도, 임시·부분 산출물 정리
   - Secret·개인정보·내부 주소 노출과 테스트 실효성

## 4. 기록 관리

`plans/<Jira-Key>.md`와 `plans/<Jira-Key>-review.md`는 `.gitignore`된 인계 자료로
커밋하지 않는다. MR에 플랜·변경·리뷰와 로컬·실환경 검증을 요약하고,
후속 작업에 필요한 계약·결정·재현 방법은 해당 기준 문서에 반영한다.
