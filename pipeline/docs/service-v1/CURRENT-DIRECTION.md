# 추천 v1 개발 방향 기록 (2026-09-18)

상태: **HISTORICAL SNAPSHOT**. 당시 TARGET CONTRACT(구현·학습·배포 전)를 보존한다.
625의 v26 채택 이후 최신 방향은 [v26 GBT 안내](../gbt-v26/README.md)다.
아래 모델 선택 보류·업무 책임·특징 후보는 당시 기록이며 새 구현의 지시가 아니다.

이 문서는 2026-09-13에 작성한 v1 자료 중 모델 입력·학습 장소·특징 선택·배포 경계에 대한
후속 결정을 모은다. 세부 정책과 과거 실험 근거는 기존 문서에 남기되, 아래 항목이 충돌하면
이 문서와 [0~N 학습·평가 계약](../../contracts/zero-n-learning-evaluation.md)을 우선한다.

`config.v1.json.defaultModel=GBT`, `config.v1.json.personalization.originalHistoryLimit=10`,
`comparison-registry.v1.json.defaultExposureModel=GBT`,
`comparison-registry.v1.json.inputContract.originalHistoryLimit=10`은 2026-09-13 게시 해시를
보존하는 legacy snapshot 값이다. 현재 방향에서는 이 네 필드로 기본 모델이나 입력 제한을
결정하지 않는다.

## 2. 0~N 서비스 경로

- 모델은 `N=0`을 포함한 임의 N 입력을 오류 없이 처리해야 한다. 이는 모든 K의 품질 우위나 노출
  승인을 뜻하지 않는다.
- 검증된 전환점 미만은 콘텐츠·대중성 신호 또는 승인된 blend를 사용하고, 전환점 이상에서만 배포
  승인된 GBT 또는 FM을 사용한다. 전환점이 검증되기 전에는 초기 경로를 유지한다.
- 10편은 legacy 값이며 자동 전환점이 아니다. K 후보와 경계는 같은 paired 비교에서 직접 평가한다.
- 모델 입력은 전체 과거 이력을 직접 나열할 필요가 없다. GBT는 고정 차원 집계·관계 특징으로,
  FM은 namespace가 분리된 희소 이력·영화 속성으로 임의 N을 표현한다.
- 계산량을 제한하는 최근 이력 특징을 두더라도 `totalHistoryCount`, 전체 이력 집계와 잘린 건수를
  함께 기록한다. 최근 10편만 사용한 결과를 0~N 전체 이력 모델이라고 부르지 않는다.
- 성능이 이력마다 단조 증가한다고 가정하지 않는다. 평균 곡선, paired 변화, 악화 사용자 비율,
  지원률과 후보 누락을 함께 보고한다.

## 3. 모델별 특징 경계

공통 데이터 계약은 사용자·예측 시점·target·과거 이력·후보·label과 누수 방지 lineage까지다.
최종 feature vector를 GBT와 FM이 공유해야 한다는 뜻은 아니다.

- GBT: 영화 속성, 전체·최근 선호/비선호 집계, 후보와 이력의 관계, 근거량·결측을 후보로 두고
  movie-only·빈 이력·타 사용자·본인 이력 및 feature block 제거 실험으로 개인화 기여를 확인한다.
- FM: 후보·긍정 이력·부정 이력·장르·감독·배우·키워드 namespace를 분리하고 OOV가 서로 다른
  범주를 거짓으로 일치시키지 않게 한다. 선형항과 상호작용의 기여를 따로 측정한다.
- TMDB와 KOBIS는 원 단위와 결측을 보존한다. 원값을 직접 max로 합치지 않고, 발견 후보의
  백분위 max·출처별 혼합·순위 합성은 S15P21E106-624에서 비교한다.

## 4. 로컬 학습과 승격 경계

1. S15P21E106-621에서 데이터·split·코드·runtime·seed와 역할별 분포 기준을 manifest로 고정한다.
   같은 paired comparison family의 episode·후보를 동결하고 분포 상태를 기록한다. 작은 재현 뒤에는
   사전 표본 수나 사용자 단위 CI 정밀도를 만족할 만큼 확장하며 10%·전체 실행을 일률적으로 강제하지 않는다.
2. S15P21E106-622와 623은 데스크톱·노트북에서 서로 다른 모델·seed를 독립 실행한다.
3. 결과는 로컬 `outputs/`, `models/`, `checkpoints/`에 남기며 GitLab 코드 배포 대상에 넣지 않는다.
4. 채택 후보만 source revision, 입력·설정·모델 SHA-256, feature schema, metric과 parity 증거를 가진
   불변 promotion manifest로 제안한다.
5. 서버/HDFS 반영은 manifest 검증과 no-overwrite 전송, 서버 CPU 추론 parity, rollback 준비가
   끝난 산출물에 한정한다. 로컬 절대 경로나 최신 파일을 직접 참조하지 않는다.

현재 Spark 코드 CD는 보호된 `main` push에서 Git commit의 runtime allowlist를 이미지로 만든다.
개인 실험 파일의 Git 추적·이미지 유입을 막는 추가 검증은 S15P21E106-644에서 처리한다.
