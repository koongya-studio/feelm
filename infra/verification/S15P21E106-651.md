# S15P21E106-651 backend MR Kafka 이미지 검증 기록

검증일: 2026-09-18

## 범위

`PersonalCandidateKafkaOffsetIntegrationTest`가 요구하는 `apache/kafka:4.3.1`을 backend MR
격리 Runner의 고정 오프라인 이미지 입력에 추가한다. 외부 pull fallback, 테스트 timeout 완화,
운영 Kafka와의 연결 및 기존 Runner의 무검증 전환은 범위에 포함하지 않는다.

## 이미지 증빙

- Docker Hub의 `apache/kafka:4.3.1` multi-platform index digest
  `sha256:77e3df9054047a88b520d0cc46e16696d3b22022e1d580aeccd2632df6532837`을 고정했다.
- 전용 rootless Docker에서 실행 중 컨테이너가 없을 때 digest reference를 pull한 뒤
  `apache/kafka:4.3.1` 태그로 연결했다.
- Kafka, Redis, pgvector, Ryuk 모두 `linux/amd64`이고 저장소의 고정 `RepoDigests`와 일치했다.
- 기존 bundle은 유지하고 새
  `/home/feelm-ci-test/ci651-backend-images-kafka-20260918/backend-images.tar`를 생성했다.
- 새 archive는 `feelm-ci-test:feelm-ci-test`, mode `0600`, 438,666,240 bytes이고 SHA256은
  `0e8105d4929e11fe0c0e0542d4fe135b5c6f18916096aef7bf1ee3cda2d646df`이다.
- OCI `index.json`에 네 태그와 고정 digest가 모두 포함된 것을 확인했다.

## 코드 및 후보 stage 검증

- 이미지 목록에 Kafka의 고정 digest를 추가했고 runtime이 기존과 동일하게 manifest image ID,
  digest, OS와 architecture를 검사한다.
- archive 경로와 SHA의 중복 상수를 입력 검사 모듈 한 곳으로 통합하고 transfer와 server manager가
  같은 값을 사용하도록 회귀 검사를 추가했다.
- Windows 로컬에서 `infra/scripts/test_ci_*.py` 485개가 통과했고 환경 제약 20개가 skip됐다.
- 후보 업로드 stage는 `/var/tmp/ci222-server-fg9rxive`, upload SHA256은
  `7a7cf8fdaf25857e227d2ba0cb668e0a2d3cb3f43cb5d46baaa8496069fc40a6`이다.
- 일치하는 보존 source/cache manifest를 사용해 후보 stage의 파일 준비와 새 image archive
  재해시가 성공했다. 호스트 패키지는 설치하지 않았다.

## 남은 검증과 적용 조건

- 다른 backend MR Job이 연속 실행 중이어서 후보 stage의 전체 backend 테스트와 현재 실패한
  Kafka offset 통합 테스트 재현은 아직 실행하지 않았다.
- 전체 테스트가 성공하기 전에는 `/etc/feelm-ci222/gitlab-adapter.json`, 설치 script,
  `prepared_base` 및 Runner 서비스를 전환하지 않는다.
- 검증 성공 뒤 `ci-dependency-cache-install.py`의 원자 전환·자동 복구 경로를 사용한다. 기존
  image bundle과 설치본은 롤백 증빙으로 보존한다.
