# S15P21E106-350 Grafana HTTPS 접근 검증 기록

검증일: 2026-09-16

## 구현 범위

- 기존 서비스 도메인의 `/grafana/` 경로를 Grafana로 프록시한다.
- 전용 Nginx Basic Auth와 Grafana 자체 로그인을 함께 유지한다.
- Grafana의 sub-path URL과 Grafana Live WebSocket 전달을 구성한다.
- Grafana와 Prometheus의 원본 포트는 루프백 바인딩을 유지한다.
- 인증 파일은 저장소 밖의 서버 파일로 주입하고 실제 인증정보는 기록하지 않는다.
- 공개 경로 장애 시 root URL을 루프백으로 임시 전환해 SSH 터널로 복구할 수 있다.

## 로컬 검증 결과

| 검증 | 결과 |
| --- | --- |
| Grafana 접근 정책 계약 테스트 | 9개 통과 |
| Swagger·모니터링·CI 관련 회귀 테스트 | 총 37개 통과 |
| `git diff --check` | 통과 |
| Secret 원문 및 인증 파일 포함 여부 | 포함 없음 |

전체 `infra/scripts/run-infra-config-tests.py`는 Windows 환경에서 실행했을 때 이번 테스트를
포함한 86개가 통과했다. Bash 배포 스크립트를 직접 실행하는 기존 Consumer 배포 테스트는
Windows에서 스크립트가 시작되지 않아 14개가 실패했다. 이번 변경과 무관한 환경 제약이며,
Linux 격리 Runner에서 전체 묶음을 다시 실행해야 한다.

로컬 호스트에 Docker와 Nginx 실행 파일이 없어 `docker compose config`와 `nginx -t`는
실행하지 못했다.

## 서버 적용 후 필수 검증

- 비인증 `/grafana/` 요청이 `401`인지 확인한다.
- Basic Auth 뒤에서 Grafana 로그인 화면, 정적 파일과 리다이렉트가 정상인지 확인한다.
- Viewer 계정이 조회만 가능하고 사용자·데이터소스·대시보드 편집은 거부되는지 확인한다.
- `/grafana/api/live/ws` WebSocket이 `101`로 전환되는지 확인한다.
- 공인망에서 `3000`과 `9090` 직접 연결이 실패하는지 확인한다.
- 서비스 노드 루프백에서 Grafana health와 Prometheus readiness가 계속 성공하는지 확인한다.
- Nginx access/error log에 인증 헤더, 쿠키, 비밀번호 및 환경변수 원문이 없는지 확인한다.

이 서버 검증이 끝나기 전에는 Jira의 운영 완료 조건을 모두 충족한 것으로 간주하지 않는다.
