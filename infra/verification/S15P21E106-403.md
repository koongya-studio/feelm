# S15P21E106-403 검증 기록

## 범위

프론트엔드 MR과 develop의 테스트·이미지·배포 Job에서 `frontend/**/*` 조건을 실제 React
검증·컨테이너·배포 입력의 허용 목록으로 바꾼다. `frontend/README.md`, `frontend/docs`,
`frontend/verification` 및 React 빌드와 분리된 `frontend/landing`만 변경한 경우에는 해당
Job을 생성하지 않는다. 프론트 기능·테스트, 배포 구조와 Runner 격리 정책은 변경하지 않는다.

## 포함 경로와 이유

| 경로 | 포함 이유 |
| --- | --- |
| `frontend/src/**/*`, `frontend/public/**/*`, `frontend/index.html` | React 소스·테스트·정적 자산·HTML 진입점 |
| `frontend/package*.json` | 패키지 명령·의존성·잠금 계약 |
| `frontend/tsconfig*.json`, `frontend/vite.config.*`, `frontend/eslint.config.*` | 타입 검사·빌드·정적 검사 설정 |
| `frontend/.prettier*` | 포맷 검사 입력 |
| `frontend/Dockerfile*`, `frontend/nginx.conf`, `frontend/.dockerignore` | 컨테이너 빌드·운영 이미지 입력 |
| Compose·Nginx·프론트 배포·롤백 경로 | develop 이미지·배포 연쇄 입력 |
| 공통·프론트 CI 및 기존 격리 실행기 경로 | MR Job 명령과 Runner 실행 경계 |

허용 목록 밖의 문서·시안·독립 랜딩만 변경하면 Job을 생성하지 않는다. 문서와 포함 경로가
섞인 MR은 실행한다. GitLab의 MR `rules:changes`는 대상 브랜치와 MR 전체 변경을 비교하므로
코드 변경 뒤 문서 커밋을 추가해도 실행 조건은 유지된다. 삭제는 삭제 전 경로가, 이름 변경은
이전·새 경로가 변경 목록에 포함되므로 소스 파일 삭제나 소스에서 문서로의 이동도 실행한다.
현재 빌드 입력에서 제외되고 별도 주입도 없는 `frontend/.env.example`만 변경한 경우도 실행하지
않는다. 환경변수 계약이 실제 빌드 입력으로 바뀌면 해당 구현 변경과 함께 경로를 재검토한다.

## 로컬 검증

- 전용 테스트에서 문서·시안·랜딩-only 제외, 소스·테스트·정적 자산·패키지·빌드 설정·
  컨테이너 입력 포함, 혼합 변경과 삭제·이름 변경을 확인한다.
- MR과 develop의 테스트·이미지·배포 Job이 동일한 프론트 실행 입력을 사용하고, develop의
  Compose·Nginx·배포 입력 및 `needs` 연쇄가 일치하는지 확인한다.
- 전용·CI 설정 테스트 13건과 전체 `infra/scripts` 단위 테스트 407건이 통과했다
  (환경 의존 25건 skip).
- CI YAML 4개 파싱과 `git diff --check`가 통과했다.

## 남은 실환경 검증

로컬 경로 매칭은 GitLab 내부 `rules:changes` 평가를 대신하지 않는다. MR 생성 및 병합 후
다음을 확인한다.

1. 문서·시안·독립 랜딩-only MR에서 `frontend-mr-test`가 생성되지 않는다.
2. 같은 변경이 develop에 반영돼도 `frontend-test`, `frontend-image`, `deploy-frontend`가 생성되지 않는다.
3. 프론트 실행 코드·설정 변경 MR과 develop 파이프라인에서는 필요한 Job 연쇄가 모두 실행된다.
