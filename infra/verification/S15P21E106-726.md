# S15P21E106-726 Kafka Topic 프로비저닝 검증

- Jira: https://ssafy.atlassian.net/browse/S15P21E106-726
- 기준: `origin/develop`의 `da1a3aec` (2026-09-21 fetch)
- 브랜치: `ci/S15P21E106-726-kafka-topic-provisioning`
- 실행 환경: Windows, Python 3, Git Bash

## 변경 및 보존 범위

기존 `ensure-kafka-topics.sh`의 8개 Topic 선언, 기본 파티션 3, 복제 수 1을 유지한다.
기존 Topic 전체를 먼저 검증하고 누락 Topic만 생성하며 생성 후 전체를 재검증한다.
복제 검증은 요약값과 모든 파티션의 replica 할당 개수를 확인한다.
설정 불일치 및 메타데이터 누락은 자동 수정 없이 실패한다.

`.gitlab/ci/infra.yml`의 `provision-kafka-topics`는 보호된 main push에서 관련 파일 변경 시
자동 실행한다. Kafka 설정 배포와 같은 잠금 및 기존 최신 커밋 검사를 사용한다.
기존 전체 인프라 복구도 보강된 스크립트를 사용한다. API·Topic 이름·Broker 설정·데이터
볼륨·서비스 의존성은 변경하지 않는다.

## 검증 결과

| 검사 | 결과 |
| --- | --- |
| Topic 스크립트 행동 테스트 | 9개 통과 |
| Topic·bootstrap·CI 구성 테스트 합계 | 42개 통과 |
| `bash -n infra/scripts/ensure-kafka-topics.sh` | 통과 |
| `git diff --check` | 통과 |
| 최신 develop과 작업 HEAD 차이 | 0/0, 동일 기준 커밋 |
| 전체 인프라 unittest | 276개 중 249개 통과, 16 failures 및 11 errors |

실패한 27개는 기존 Consumer·PostgreSQL shell 배포 테스트다. 변경 전 `origin/develop`의
별도 임시 archive에서 해당 두 모듈을 실행해 동일한 16 failures 및 11 errors를 재현했다.
Windows의 기본 `bash` 실행 환경에서 대역 이벤트 파일이 생성되지 않는 오류 등이 발생한다.
전체 인프라 검사가 성공한 것은 아니며 Linux CI에서 다시 확인해야 한다. 전체 runner는
unittest 실패 시 종료하므로 뒤의 별도 `test_pipeline_observability` 함수 검사는 실행되지 않았다.

새 테스트는 상태를 보존하는 Docker 대역으로 실제 shell을 실행한다. 최초 생성·부분 존재·
재실행·관리 대상 외 Topic 보존, 파티션 과소/과다·복제 불일치·메타데이터 누락/중복,
목록/상세/생성 오류, 동시 생성의 설정 불일치와 잘못된 입력을 검증한다.
메시지·offset 대역 파일과 기존 Topic 메타데이터가 재실행 후 유지되는지 확인했다.

## 미검증 및 적용 전 확인

- 실제 Kafka Broker와 실제 메시지 보존, GitLab Runner 실행은 미검증이다.
- 운영 Topic을 생성·삭제·변경하거나 서버에 배포하지 않았다.
- 관련 열린 Jira에서 동일 프로비저닝 업무는 발견하지 못했다. GitLab MR API는 404로
  열린 MR을 확인하지 못했으므로 공통 CI 파일의 병행 변경은 MR 전 다시 확인한다.
- commit, push, MR 생성은 수행하지 않았다.
- 실행·재시도·부분 실패 처리 방법은 [운영 안내](../scripts/KAFKA-TOPICS.md)를 따른다.
