# S15P21E106-411 검증 기록

## 범위

보호된 `develop`의 모든 Pipeline에서 자동 실행되던 `runner-check`를 Runner 연결·설치·서비스
구성 변경에만 자동 실행하도록 제한한다. 애플리케이션 또는 문서 변경에서는 Job을 자동으로
실행하지 않으며, 운영자가 필요할 때 실행할 수 있는 비차단 수동 Job은 유지한다.

## 실행 조건

| 보호된 develop push의 변경 | runner-check 기대 결과 |
| --- | --- |
| `.gitlab-ci.yml`, `.gitlab/ci/common.yml` | 자동 실행 |
| `infra/scripts/ci-gitlab-*.py` | 자동 실행 |
| Runner 가드·네트워크 가드 Python | 자동 실행 |
| `infra/scripts/systemd/feelm-ci*.service` | 자동 실행 |
| 백엔드·프론트엔드 애플리케이션 코드 | 수동 대기, Pipeline 비차단 |
| 백엔드·프론트엔드 및 일반 인프라 문서 | 수동 대기, Pipeline 비차단 |
| 서비스별 `.gitlab/ci/backend.yml`, `.gitlab/ci/frontend.yml` | 수동 대기, Pipeline 비차단 |
| 비보호 브랜치 또는 develop 이외 브랜치 | Job 제외 |
| Claude 검토용 API Pipeline | Job 제외 |

운영자는 가장 최근의 보호된 `develop` Push Pipeline에서 수동 `runner-check`를 실행한다.
수동 Job은 `allow_failure: true`이므로 실패해도 기능 Pipeline을 차단하지 않는다. 정기
Scheduler는 추가하지 않는다.

## 로컬 검증 결과

- `python -B -m unittest discover -s infra/scripts -p 'test_*.py' -q`: 364개 통과,
  25개 건너뜀.
- 전용 규칙 테스트에서 관련 경로 자동 실행, 무관 경로 수동 대기, 보호 브랜치·push 제한,
  Claude 검토 API 제외 조건을 확인했다.
- PyYAML로 루트와 분리된 CI YAML 4개 파싱 성공.
- `git diff --check` 통과.

## 남은 실환경 검증

로컬 검증은 GitLab 내부 `rules:changes` 평가나 실제 `e106-shell` 호스트 상태를 대신하지
않는다. MR Pipeline에서 GitLab CI Lint를 확인하고 병합 후 다음을 확인한다.

1. 관련 파일 변경 Pipeline에서 `runner-check`가 자동 실행되는지 확인한다.
2. 무관한 변경 Pipeline에서 Job이 자동 실행되지 않고 수동 상태인지 확인한다.
3. 수동 실행 결과에서 Runner 호스트·계정과 `docker --version`,
   `docker compose version`이 모두 성공하는지 확인한다.
4. 수동 실행 실패가 Pipeline을 차단하지 않는지 확인한다.
