# S15P21E106-296 검증 기록

## 범위와 결정

문서 전용 MR에서 서비스 Job이 모두 제외돼 파이프라인이 생성되지 않는 문제를 해결한다.
`docs-mr-check`는 develop 대상 모든 MR에서 실행한다. 문서 링크가 소스·설정·이미지 등 임의의
추적 파일을 가리킬 수 있으므로, 이 방식은 문서 변경뿐 아니라 링크 대상 삭제·이동도 검사한다.

새 외부 도구나 의존성을 추가하지 않고 Python 표준 라이브러리로 검사한다. 기존 문서 위반을
baseline으로 숨기지 않으며 구현 시점의 추적 Markdown 전체가 통과해야 한다.

## 로컬 검증

- `python -B infra/scripts/check-markdown.py`
  - 구현 전 추적 Markdown 182개 통과
  - 최신 `origin/develop` 반영 및 신규 운영·검증 문서를 포함한 Markdown 188개 통과
- 문서 검사 fixture
  - 정상 상대경로, 한글·공백 경로, 이미지, 외부 URL 통과
  - 깨진 링크, 대상 삭제·이동, 저장소 탈출, 미지원 scheme 실패
  - 코드 예시 안의 링크·충돌 표식은 제외하고 실제 충돌 표식과 닫히지 않은 문법은 실패
- 격리 경계 fixture
  - Markdown 전체와 추적 경로 manifest의 일치 검증
  - 누락 Markdown, 범위 밖 실행 파일, symlink 거부
  - 고정 설치 검사기, 비특권 계정, private network와 자원 제한 확인
- CI 계약 fixture
  - 모든 develop MR 변경에서 Job 생성
  - 고정 Job 이름·stage·script와 Custom executor 어댑터 routing 확인
- 관련 문서·CI·격리 어댑터·서버 stage 단위 테스트 81개 통과
- `python -B -m unittest discover -s infra/scripts -p 'test_*.py' -q`
  - 전체 503개 중 473개 통과, 19개 skip, 11개 실패
  - 실패 11개는 모두 변경하지 않은 `test_deploy_backend.py`의 Windows 셸 실행 사례이며,
    동일한 `origin/develop` 임시 worktree에서도 같은 11개가 재현됨
  - 이후 병합된 최신 `origin/develop`에서도 해당 테스트와 대상 스크립트는 변경되지 않았음을 확인
- `git diff --check` 통과
- 실환경 1차 확인
  - MR !290에서 `docs-mr-check` 생성 및 운영 Runner의 신규 고정 정책 수락 확인
  - UID/GID 1001, root 소유 설치 파일과 private-network transient unit의 합성 snapshot 검사 통과
  - 실제 MR snapshot 준비 과정의 예상하지 못한 `ValueError`는 상세 값을 숨기고 고정 단계명과
    예외 종류만 출력하도록 진단 경계를 추가
  - 진단 결과 `git ls-tree`에 `capture_output`과 `stderr`를 함께 전달한 충돌을 확인해
    `stdout=PIPE`로 수정하고 실제 문서 archive 생성 회귀 테스트를 포함한 관련 테스트 38개 통과

## 남은 실환경 검증

- 실제 MR pipeline에서 `docs-mr-check` 최종 성공
- 깨진 내부 링크, 이미지 누락, 링크 대상 삭제 fixture의 실제 MR 실패
- Job 프로세스에 Docker socket, 배포 Secret, GitLab Job Token과 외부 네트워크가 노출되지 않는지
  서버 측 확인

실제 MR snapshot 실패 원인을 수정하고 정상·실패 fixture를 확인하기 전에는 실환경 검증이
완료된 상태가 아니다.
