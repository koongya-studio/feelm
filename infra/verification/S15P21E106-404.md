# S15P21E106-404 검증 기록

## 범위

보호된 `develop` 변경에서 백엔드 런타임·빌드·컨테이너·배포 입력이 바뀐 경우에만
`backend-test`, `backend-image`, `deploy-backend` 연쇄를 생성한다. 프론트엔드, 데이터
파이프라인 및 문서 전용 변경에서는 해당 Job을 만들지 않는다. 배포·롤백 구현, Runner,
캐시 승격 방식과 프론트엔드·데이터 파이프라인은 변경하지 않는다.

## 포함 경로와 이유

| 경로 | 포함 이유 |
| --- | --- |
| `backend/src/**/*` | 백엔드 소스·테스트·리소스와 Flyway migration |
| Gradle 설정·Wrapper | 테스트와 운영 JAR 빌드 입력, 의존성 캐시 승격 대상 |
| `backend/Dockerfile*`, `backend/.dockerignore` | 백엔드 이미지 빌드 입력 |
| Compose·Redis·데이터스토어 검증 경로 | 백엔드 실행 환경과 배포 전 설정 검증 입력 |
| 백엔드 배포·롤백 및 배포 검증 경로 | 이미지 배포 연쇄와 현재 커밋 검증 입력 |
| 루트·공통·백엔드 CI와 `.gitattributes` | Job 규칙·실행 명령 및 실행 파일 계약 |

백엔드 문서, 프론트엔드와 데이터 파이프라인만 변경하면 세 Job을 생성하지 않는다. 포함
경로가 함께 바뀐 혼합 변경, 소스 삭제와 소스에서 문서로의 이름 변경은 실행한다.
`backend-cache-promote`의 의존성 경로는 세 Job에 모두 포함하며 기존 verify → test → build →
deploy 단계와 `service-and-backend-cache` resource group을 유지한다.

## 로컬 검증

- 전용 테스트에서 무관한 서비스·문서 변경 제외, 백엔드 소스·테스트·리소스·Gradle·Wrapper·
  컨테이너 입력 포함, 혼합 변경과 삭제·이름 변경을 확인한다.
- Compose·Redis·백엔드 배포·롤백 입력에서 데이터스토어 검증과 세 Job 연쇄가 유지되는지
  확인한다.
- 의존성 변경에서 캐시 승격 경로가 세 Job에 포함되고 `needs` 및 보호된 develop push 조건이
  유지되는지 확인한다.
- 전용·CI 설정 테스트 12건과 전체 `infra/scripts` 단위 테스트 414건이 통과했다
  (환경 의존 25건 제외).
- `git diff --check`가 통과했다. 로컬 환경에는 YAML 파서가 없어 CI YAML 구문은 MR의
  GitLab CI Lint에서 확인한다.

## 남은 실환경 검증

로컬 경로 매칭은 GitLab 내부 `rules:changes` 평가를 대신하지 않는다. MR 생성 및 병합 후
다음을 확인한다.

1. 프론트엔드·데이터 파이프라인·문서 전용 develop 변경에서 백엔드 세 Job이 생성되지 않는다.
2. 백엔드 코드·빌드·컨테이너 입력 변경에서 테스트·이미지·배포 연쇄가 성공한다.
3. 의존성 변경에서 캐시 승격 이후 검증된 캐시를 사용해 세 Job이 순서대로 실행된다.
