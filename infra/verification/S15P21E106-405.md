# S15P21E106-405 검증 기록

## 범위

`backend-mr-test`의 `backend/**/*` 조건을 실제 백엔드 검증 입력의 허용 목록으로 바꾼다.
`backend/README.md`, `backend/AGENTS.md`, `backend/CLAUDE.md`, `backend/docs`와
`backend/verification`의 Markdown만 변경한 MR은 전체 백엔드 테스트를 실행하지 않는다.
develop 테스트·이미지·배포 조건과 격리 Runner 실행 정책은 변경하지 않는다.

## 포함 경로와 이유

| 경로 | 포함 이유 |
| --- | --- |
| `backend/src/**/*` | 애플리케이션 소스·테스트·리소스·DB migration |
| `backend/scripts/**/*` | 초기 데이터 적재 실행 코드·테스트·입력 fixture |
| `backend/gradle/**/*` | Wrapper와 CI 테스트 시간 계측을 포함한 Gradle 입력 |
| `backend/build.gradle*`, `backend/settings.gradle*`, `backend/gradle.properties` | 빌드·플러그인·의존성 설정 |
| `backend/gradlew*` | Gradle Wrapper 실행기 |
| `backend/Dockerfile*` | 백엔드 컨테이너 빌드 입력 |
| `backend/.*` | `.dockerignore`, `.env.example`, `.gitattributes` 등 숨김 설정 |
| 공통·백엔드 CI 및 기존 격리 실행기 경로 | Job 명령·캐시·네트워크·systemd 실행 경계 |

허용 목록 밖의 Markdown 문서만 변경하면 Job을 생성하지 않는다. 문서와 포함 경로가 섞인
MR은 실행한다. GitLab의 MR `rules:changes`는 대상 브랜치와 MR 전체 변경을 비교하므로,
코드 변경 뒤 문서 커밋을 추가해도 실행 조건은 유지된다. 삭제는 삭제 전 경로가, 이름 변경은
이전·새 경로가 변경 목록에 포함되므로 소스 파일 삭제나 소스에서 문서로의 이동도 실행한다.

## 로컬 검증

- 전용 테스트에서 문서-only 제외, 소스·테스트·리소스·Gradle·Wrapper·Dockerfile·숨김
  설정 포함, 혼합 변경, 삭제·이름 변경과 공통 CI·격리 Runner 경로를 확인한다.
- `backend-cache-prepare`의 기존 의존성 경로가 새 `backend-mr-test` 허용 목록에 모두
  포함되는지 확인한다. 캐시 준비·승격 규칙 자체는 변경하지 않는다.
- CI YAML 4개 파싱, 전체 `infra/scripts` 단위 테스트 399건 통과(환경 의존 25건 skip),
  `git diff --check` 통과를 확인했다.

## 남은 실환경 검증

로컬 경로 매칭은 GitLab 내부 `rules:changes` 평가를 대신하지 않는다. MR 생성 후 다음을
확인한다.

1. 문서-only MR에서 `backend-mr-test`가 생성되지 않는다.
2. 백엔드 실행 코드 또는 설정 변경 MR에서 `backend-mr-test`가 생성된다.
3. 코드와 문서가 섞인 MR에서도 Job이 생성되고 기존 격리 Runner에서 성공한다.
