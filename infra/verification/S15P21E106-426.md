# S15P21E106-426 배포 기준 브랜치 전환 검증 기록

## 저장소 설정 검증

- develop 대상 MR의 백엔드·프론트엔드 검증 Job은 유지한다.
- 서비스 테스트·이미지 빌드·배포와 데이터스토어 사전 검증은 보호된 main Push에서만 실행한다.
- develop Push, MR, API와 Web Pipeline에서는 서비스 배포 Job이 실행되지 않는다.
- 테스트와 이미지 빌드는 `interruptible: true`, 배포와 캐시 승격·롤백은
  `interruptible: false`를 유지한다.
- 백엔드와 프론트엔드 배포는 같은 `service-and-backend-cache` resource group을 사용한다.
- 배포 직전 원격 main HEAD와 `CI_COMMIT_SHA`가 일치하지 않으면 배포를 거부한다.

## GitLab 설정 확인

2026-09-15 GitLab 프로젝트 설정을 값 공개 없이 확인했다.

- `main`: Protected 표시 확인
- `develop`: Default, Protected 표시 확인
- `e106-shell` Runner: Online, Protected, 태그 일치 확인
- Docker Hub 인증 변수: Protected 표시 확인
- 서비스 배포 변수: `service` 환경 범위와 Protected 표시 확인
- 오래된 배포 Job 방지 설정: 활성화 확인

## 병합 후 확인할 항목

다음 항목은 이 MR의 develop 대상 Pipeline만으로는 실제 실행을 검증할 수 없다.

1. 대표 백엔드·프론트엔드 MR에서 기존 영역별 검증 Job이 실행되고 배포 Job은 없는지 확인한다.
2. develop 병합 Pipeline에서 서비스 이미지와 배포 Job이 생성되지 않는지 확인한다.
3. develop에서 main으로 통합한 뒤 main Push Pipeline에서 변경 영역의 테스트, 이미지 빌드,
   배포가 순서대로 성공하는지 확인한다.
4. main 배포 후 실행 이미지 태그가 main의 배포 commit SHA와 일치하고 백엔드 Actuator 및
   프론트엔드 공개 health endpoint가 정상인지 확인한다.
5. API와 Web Pipeline에서 서비스 배포 Job이 생성되지 않는지 확인한다.
6. 이전 main Pipeline을 재시도했을 때 최신 main HEAD 검사가 오래된 배포를 거부하는지 확인한다.

실제 Pipeline URL, commit SHA와 헬스체크 결과는 main 반영 후 이 기록 또는 Jira에 추가한다.
