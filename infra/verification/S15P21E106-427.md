# S15P21E106-427 검증 기록

- 백엔드 Spring 설정의 필수 환경변수와 `.env.example` 문서 일치
- 배포 환경변수 계약과 Compose backend 주입 구조 일치
- 보호된 `main` Push에서 `service` 범위 변수의 비어 있지 않은 값 확인
- 검사 로그에 환경변수 값 또는 Secret 미출력

## 저장소 검증

- `python -B -m unittest discover -s infra/scripts -p 'test_*.py' -v`: 리뷰 반영 후 424개 통과,
  Windows에서 POSIX bash가 필요한 기존 테스트 25개 제외
- `gradlew.bat test --tests com.feelm.backend.config.BackendEnvironmentContractTest spotlessCheck`:
  성공
- `gradlew.bat build`: 새 계약 테스트까지 실행됐으나 로컬 Docker daemon을 사용할 수 없어
  기존 Testcontainers 기반 통합 테스트가 실패함. 계약 테스트에서 발견된 `MAIL_MODE`의 dev
  기본값 처리는 수정 후 대상 테스트로 재검증함.
- `git diff --check`: 통과

Review A/B 합성에서 채택한 Compose MR 실행 누락, 기본값 marker literal 우회, 선택 변수 문서
누락, invalid 계약 행 원문 노출과 일부 필수 키만 검사하던 테스트를 보완했다. backend MR
격리 archive에는 `infra/compose/service.yml` 한 파일만 추가하며 다른 infra 입력은 거부한다.

MR 생성 전 서비스 서버의 설치된 GitLab adapter/runtime을 이 변경과 일치시키고 Runner 시작
검사를 다시 수행해야 한다. 적용 전에는 기존 어댑터가 Compose 파일을 전달하지 않아 신규
JUnit이 실패하는 것이 정상이며, 저장소 변경만으로 서버 운영 파일이 자동 교체되지는 않는다.

## GitLab 운영 설정 확인

최초 배포 전에 GitLab UI에서 다음 항목을 사람이 확인한다.

- `main`이 보호 브랜치인지
- `e106-shell` Runner가 Protected인지
- 계약에 이름이 기록된 CI/CD Variable이 `service` 환경 범위와 Protected 속성을 갖는지
- 비밀번호, 토큰 및 JWT 키가 Masked and hidden인지

이 저장소 검사는 변수 값의 존재 여부만 확인한다. GitLab 변수의 속성과 실제 값은 저장소나
검증 기록에 복사하지 않는다.
